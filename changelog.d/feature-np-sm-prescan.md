- BLASTX with `-parse_deflines` and `-outfmt` 5, 11 or 13 to 16 now stops at the query reader's error, as NCBI BLAST+ 2.17.0 does, when the query file's first line that is not blank or a comment is not a defline (`BLAST query error: CFastaReader: Input doesn't start with a defline or comment around line N`, exit status 1), or when a defline names a Seq-id NCBI cannot make (`>gi|abc`: `Could not construct seq-id from 'gi|abc'`) in the batch of an earlier record. Before, the read of the query file that these formats make before the search (to refuse a title they cannot write before any byte) did not use `-parse_deflines`, so LOSAT refused the title of a later record (not US-ASCII for XML and JSON, outside the visible ASCII range for the archive) instead. That read now also takes the search's batches (`BATCH_SIZE`): with `BATCH_SIZE=1` a record written before the reader's error is still checked, and with a batch larger than 10,002 letters a record of the batch that the error interrupts is not. Runs without `-parse_deflines`, and the other programs, do not change.
