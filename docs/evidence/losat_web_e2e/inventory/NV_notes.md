## Surprises / findings worth a decision

1. **Matrix name case**: NCBI keeps the matrix name as typed (`SetMatrixName` does not upper-case) and prints it in the outfmt 0 footer; all lookups use `strcasecmp`. `-matrix blosum62 -outfmt 0` differs from LOSAT in one line (row 10). Real, verified.
2. **Threshold and X-drop reals are cast to Int4**: fractions truncate (13.9 -> 13, 0.5 -> 0 = exact words only), but the footer prints the double (`13.9`). Values outside Int4 (>= 2^31, +inf) are undefined behaviour; x86-64 gives INT_MIN (all neighbours / tiny X-drop); Rust `as i32` saturates (a different result). Platform-variant, so proposed `reject` (rows 36, 83); needs a batch decision. TBLASTN also lets `-xdrop_gap 5e8` allocate 20 GB while NCBI answers in seconds.
3. **NCBI accepts spellings LOSAT rejects** in every real/integer option of this range: hex (`0x10`), `+inf`, `+nan`, `1e400`, negative X-drops/e-values (the e-value then fails in Validate with the options-error frame). The BLASTN session already built `ncbi_integer`/`ncbi_double` (`value_parsers.rs:190,232`); TBLASTN/TBLASTX parsers (`nonnegative_f64`, `positive_usize`, `nonnegative_i32`, `nonnegative_usize`, `u32`) do not use them. Recommend the same replacement here. Genetic-code Verify uses `StringToInt` (no hex) - LOSAT is right to reject hex there.
4. **Booleans** accept `on`/`off` too (`NStr::StringToBool`); LOSAT's `ncbi_bool` lacks them (row 73).
5. **IDENTITY + compressed alphabet (word size >= 5, tblastn-fast) crashes NCBI** (SIGSEGV, rc -11, reproducible with `-comp_based_stats 0`, `-threshold 30`, `-ungapped`). Word sizes 2..4 work, and IDENTITY resets cbs to 0 with a per-query warning (`setup_factory.cpp:143-155`).
6. **tblastn-fast** keeps threshold 20 whatever the matrix or word size 3/4 (`s_IsDefaultWordThreshold` sees 20 != 13) and flips the table back to the plain one for word sizes <= 4 (`CBlastOptionsLocal::SetWordSize`); word sizes 6/7 give 21/20.25.
7. **Order of option errors** (row 114) and the **error frame** (row 113): LOSAT's TBLASTN validation uses `anyhow` (`Error: ...`, exit 1) and clap parsers (exit 2) where NCBI has `BLAST query/options error: ...` + `Please refer to the BLAST+ user manual.`, exit 1, with a fixed first-failure order; TBLASTX has the frame for `-evalue` only. BLASTN's `NativeError` route is the model.
8. **The web adapter's `validate` for TBLASTN checks nothing** beyond parsing (`web/adapter/src/run.rs:74-92`), so ABI v2 accepts option sets that `run` rejects (row 115).
9. **-ungapped ordering**: NCBI raises the cbs+ungapped error during option extraction, i.e. before `Validate`, so `-comp_based_stats 2 -ungapped -matrix BAD` reports the cbs error and `-ungapped -matrix BAD` (cbs F) runs and fails inside the search set-up with exit 3 and one `Error: Unknown error code -1` per query (rows 23, 68).
10. **TBLASTN window 2147483647**: NCBI's `qlen+window_size` overflows Int4 and the run returns no hits; TBLASTX reproduces it with i32 arithmetic, TBLASTN's `Diagonals::new` (usize + `next_power_of_two`) would try a 16 GB table once the gate is lifted (row 56).
11. **TBLASTX `-db_gencode`**: any non-default value differs from NCBI by design (AGENTS.md exception); `-query_gencode` is NOT covered by the exception and is byte-equal for all 26 IDs (row 'X: -query_gencode').
12. `-culling_limit 2147483647` gives the same 116 lines as `-culling_limit 1` in NCBI (possible Int4 overflow in the culling code; XC to check).
13. `-lcase_masking` in `is_unported_tblastn_arg` is dead (the clap field exists), harmless.
14. `-soft_masking true` alone changes NCBI's TBLASTX output (538 vs 569 lines); LOSAT's TBLASTX has neither masking flag.
