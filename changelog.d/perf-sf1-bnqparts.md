- `blastn` with a tabular report (and the other formats that show no query letter) keeps the query records it reads before the search in a few buffers per file part (titles and packed letters) instead of one set of heap objects per record, reads those parts on the search's threads where the query file can be cut at record starts, and makes each batch's records again when the batch starts. Outputs do not change. One million 150-letter reads against the 16S database with `-task megablast` at 16 threads: 6.0 → 4.3 s, max RSS 528 → 343 MiB; at one thread the time is the same and max RSS 500 → 299 MiB. `LOSAT_X_BNQPARTS=0` keeps the previous store.
