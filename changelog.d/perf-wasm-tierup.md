- LOSAT Web (Wasm): the first TBLASTX search of a page no longer runs most of its subject scan, HSP linking, SEG trims and pairwise records in V8's baseline code. On wasm32 each of these long calls is cut into calls of a function entered many times (one scan batch, one linking round, one segment, one HSP), so V8 runs its optimized code from the next call on; reports do not change. In headed Chromium 149 on a loaded i9 (8 threads) the first search of two ~650 kb genomes (genetic code 4) took 5.7 s instead of 7.8 s, as long as the later searches (1.00 of them, before 1.79), and of two ~300 kb genomes 0.86 s instead of 1.44 s. On other targets the new functions are inlined, and native TBLASTX runs 6-8 % fewer instructions (callgrind, one thread).
