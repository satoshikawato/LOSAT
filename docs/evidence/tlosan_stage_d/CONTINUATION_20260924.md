## First unimplemented boundary and remaining work

The earliest missing **integrated** LOSAT Stage D step is **before preliminary Stage C search**: NCBI's `BLAST_OneSubjectUpdateParameters` computes local per-context effective lengths and search spaces, hit/word cutoffs, and link parameters. `LOSAT/src/algorithm/tblastn/stage_d_stats.rs` now ports the translated-subject length conversion and per-context effective search space calculation, using the existing NCBI length-adjustment port. Its focused unit test exactly matches the observed `(15, 15225, 120)` and `(33, 182004, 2125)` / `(28, 88074, 2125)` for the saved code-1 fixtures and preserves the third multi-query context's NCBI invalid-context branch (`adjustment=0`, `eff_searchsp=0`). It is not yet wired into a complete TBLASTN search. The Rust `PreliminaryProfile` in `LOSAT/src/algorithm/tblastn/search_gapped.rs:351-368` still receives cutoffs as fixed comparison inputs. There is no integrated Rust Stage D list that can yet be compared against the default NCBI call trace, so no claim of a first *numeric LOSAT-vs-NCBI* D mismatch is supported. Implement the source-defined update and compare actual computed C inputs first; reopen C if that changes candidate/HSP behavior. Then port the uneven-gap link, preliminary reap, Kappa redo, post-redo link/reap, score normalization, ranking and deletion order using the traces above. The existing BLASTP path's `do_link_hsps=false` is not a TBLASTN rule. Every Rust port requires the NCBI file, line and snippet immediately above it.

Before closing D, compare Rust versus NCBI exact raw score, full-precision bit/E-value, rank and deletion order on code 1 fixtures.
