## Reproduction

From the LOSAT repository root, each script requires a **new** output directory:

```bash
bash docs/evidence/tlosan_stage_a/run_cli_oracles.sh /tmp/tlosan-cli-new
bash docs/evidence/tlosan_stage_a/run_api_oracle.sh /tmp/tlosan-api-new
(cd /tmp/tlosan-cli-new && sha256sum -c outputs.sha256)
(cd /tmp/tlosan-api-new && sha256sum -c outputs.sha256)
```

The scripts are comparison-only. They do not enter the LOSAT build or runtime.
`run_api_oracle.sh` uses `git archive` of the exact source commit, checks
[ncbi_source.sha256](ncbi_source.sha256), generates NCBI ASN.1 headers with
`datatool`, compiles [tblastn_code32_oracle.cpp](oracle/tblastn_code32_oracle.cpp)
against installed NCBI libraries, creates a nucleotide DB with `makeblastdb
-parse_seqids`, and invokes NCBI's `CSearchDatabase` → `CLocalBlast` →
`CBlastFormat` API. Its executable is temporary; its source and logs are
retained. This route bypasses only the CLI ID validator and explicitly calls
`FindGeneticCode(32)`. The generated binary, source, fixtures, and libraries
have SHA-256 records in `api_20260923_verified/`.

The CLI matrix uses, for every code 1/4, each subject FASTA, each `-subject`
or `-db` mode, and outfmt 0/6/7:

```text
-task tblastn -query fixtures/query.faa -subject SUBJECT.fna | -db PREBUILT_DB
-evalue 10 -matrix BLOSUM62 -word_size 3 -threshold 13 -window_size 40
-gapopen 11 -gapextend 1 -comp_based_stats 2 -seg '12 2.2 2.5'
-sum_stats true -max_intron_length 0 -db_gencode CODE -num_threads 1
-outfmt FORMAT
```

The detailed outfmt-6 variant additionally selects `score`, `sframe`, `qseq`,
and `sseq`. The `-db` path is built before searches; `makeblastdb` execution is
not a search timing. `-subject` and `-db` have different database/formatting
contracts and are never raw-byte equality gates against each other. There are
no performance measurements in Stage A.

## Handoff and remaining work

- Stage A's bounded authority/product decision and code-32 oracle are established.
  The approved exception is recorded in `AGENTS.md` and the product decision.
- Stage B must validate all 27 IDs × 64 codons and invalid-ID rejection against
  the pinned `gc.prt`/API, then implement the Rust CLI/genetic-code path. Each
  non-default code needs a code-sensitive fixture; do not treat argument
  acceptance as translation validation.
- The API harness is a DB-search reference. It does not certify LOSAT local
  subject code 32 or all six frames. Stage C–E must compare LOSAT's eventual
  local output to the proper source/API stages and preserve the local subject
  decision. The local-subject code boundary established by the CLI code-4
  fixture and NCBI source must not be used as the code-32 search oracle.
- No LOSAT Rust code or v0.1.0 execution path changed in Stage A. Existing
  program regressions and native/Wasm gates remain for later implementation
  and certification stages; none are claimed here. The unchanged v0.1.0
  baseline remains recorded in `docs/release/{blastn,blastp,tblastx}_v0.1.0_certification.md`
  and `docs/release/pure_rust_runtime_v0.1.0_certification.md`; it was not
  re-executed during this documentation-only stage.
