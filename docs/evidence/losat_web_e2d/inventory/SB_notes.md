## Coordinate conventions (verified)
- `-subject_loc a-b` is 1-based closed in the file; ParseSequenceRange returns 0-based closed [a-1, b-1] (blast_input_aux.cpp:146-178). The interval actually used is [from, min(to, seqlen-1)] 0-based closed (blast_fasta_input.cpp:445-452), strand both for nucleotide subjects. `to` >= seqlen is clipped silently. Length of the interval = to-from+1 (oracle: 1001-2500 -> 1,500 letters; 7001-9999 on an 8001-letter record -> 1,001 letters).
- Mask coordinates: full record, 0-based closed (CFastaReader::SaveMask). Shifted/clipped to the interval only for the search (s_SeqLoc2MaskedSubjRanges: first = from>offset ? from-offset : 0, second = min(to-offset, len-1) (inclusive `to`, stored as if exclusive: this is the known quirk that the last masked letter of each mask stays searchable, already reproduced by LOSAT without a range), kept only if to >= offset and first < len).
- Engine coordinates are interval-relative: nucleotide letters of the interval (both strands built from them), protein letters of the interval; translated frames are defined from the interval start (plus) and from the interval end (minus). Seq-align subject coordinates are then shifted by the interval start (RemapAlignToLoc; strand both = no flip). Output coordinates (sstart/send, the "Sbjct" numbers) are therefore full-record 1-based coordinates; for minus strand/frames sstart > send as without a range (oracle: n_rc_r.out sstart 2500 send 1002; t_minus_*.out).
- `slen` (outfmt 6 field) and the outfmt 0 "Length=" line are the FULL record length (oracle: slen 8001 with -subject_loc 1001-2500). They come from the bioseq, not from the interval.
- `sframe` (tabular) and the "Frame = " line (outfmt 0) for tblastn/tblastx are computed by the formatter from the remapped full-record coordinates and the full bioseq length (CAlignFormatUtil::GetFrame, align_format_util.cpp:1233-1245: plus (start0 % 3)+1; minus -((L_full - start0 - 1) % 3 + 1) with start0 = s_start-1 using the larger coordinate for minus). So the printed frame is the frame of the full record, not the interval-relative frame (oracle t_r_*: starts 1001/1002/1003 print identical frames and alignments; the hit at 4529-5998 prints frame +2 with every range). Only the choice of residues at the range edges depends on the interval-relative phase (partial codons at the interval start/end are dropped: t_edge_*.out: range 4530-5999 loses the first residue of the 4529 hit: sstart 4532, qstart 2).
- Database totals: outfmt 0 prints the sum of interval lengths and the record count (all records, also empty intervals): n_m2_r0.out "3 sequences; 3,500 total letters" (1500+1500+500), "Number of letters in database: 3,500", "Number of sequences in database:  3"; n_sub_multi_1000_o0.out: 3 sequences, 2,000 letters with one empty interval. The same numbers drive "Effective search space used" (blastn ESS 55760256 full-record vs 10365740 for 1500 letters, query 7001) and the e-values (tblastn 2.29e-38 -> 1.17e-38 for the same hit with 5000 letters). tblastn/tblastx: total letters printed in nucleotides, statistics use total/3.

## Surprises
- Frame labels and slen are full-record values even though the search runs on the interval (items above).
- The subject mask display quirk (full-record masks tested against interval-coordinate HSP ranges).
- 1-based start == seqlen+1 is accepted by NCBI (empty interval) while seqlen+2 is an error.
- The query reading loop swallows std::exception (blast_input.cpp:149-152 `catch (const exception&) { continue; }`) but the subject loop (GetAllSeqs, blast_input.cpp:199-217) does not: for a query range error (QN range) the query is skipped silently or reported differently; for subjects the error aborts (exit 1). Cross-range hint for QN.
- dbscan mode (CLocalDbAdapter ctor with dbscan_mode=true unless the environment variable BL2SEQ_LEGACY is set) is what makes the totals the sum of the interval lengths; with BL2SEQ_LEGACY the total is 0 and every subject is its own database (LOSAT's check_unsupported_environment is the place that already deals with environment variables; not examined here).

## Decisions for the session
1. Cut the subject record to the interval before the existing code sees it (letters and case preserved) and carry per record (offset, full_length, original masks) for: coordinate shift, slen/Length=, frame labels (tblastn/tblastx), display masks. Everything that receives the cut letters (search, stats, totals, translation, chunking, masks) is then already NCBI-conformant (rows marked faithful).
2. How to treat the uncaught StringToInt exceptions (exit 255, text with the conda build path): reproduce exit 255 and the text with the oracle's path, or reject with an explicit LOSAT error (NCBI defect policy). Needs a decision; shared with the query range (QN).
3. Empty intervals: port the NCBI branch for blastn/tblastn/tblastx (warning, count in db totals, error `The average subject length is too short` exit 3 for blastn/tblastx single subject, zero-length stats for blastp/tblastn) or keep rejecting; the current empty-record rejection for these three programs is a separate pre-existing divergence that the range makes reachable.
4. Display masks quirk (outfmt 0 only, blastn; blastp rejects -lcase_masking in LOSAT today): reproduce with the full-record masks kept per subject.
