- BLASTN: the approximate ungapped extension reads its 4-base blocks from slices cut once by NCBI's loop counts, with one index per loop and no bound check or guard per block, so V8 keeps both loops' values in registers in the WebAssembly build (it had spilled five loop values to the stack). The extension takes about 12 % fewer CPU cycles in Node (one thread, 8,000 fly cDNAs against 3 Mb of the fly genome; the whole search changes less than its run-to-run spread), and the native build runs the same search in about 1 % fewer cycles. Results do not change.
