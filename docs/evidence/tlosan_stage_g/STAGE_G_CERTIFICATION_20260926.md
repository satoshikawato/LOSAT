## First observed differences and NCBI owners

1. An all-invalid query (`W`-only fixture) initially exited from LOSAT with empty stdout while NCBI returned a no-hit report and warning. [Initial row](nohit_initial_failure.json) records input hashes and the actual empty-output hash. NCBI `c++/src/algo/blast/api/local_blast.cpp:177–224` and `prelim_stage.cpp:322–327` skip a batch whose score blocks have no valid context but return ancillary `-1` Karlin blocks. `blast_format.cpp:445–478`, `tabular.cpp:1266–1338`, `blast_setup_cxx.cpp:535–543`, and `blast_results.cpp:277–293` define the no-hit footer, suppressed outfmt7 hit-count line, query title, and warning. LOSAT now preserves the skipped-batch state and emits those bytes. The 72/72 real/no-hit and 12/12 mixed-batch gates below include stdout **and stderr**.
2. Full AvCLPV self code-1 pairwise output exposed HSP order for BDT63286/BDT63383, a tied gapped script for BDT63294, and BDT63307's gap placement despite equal score and coordinates. NCBI `blast_seqalign.cpp:1572–1577` sorts HSPs by E-value at report conversion; `blast_hits.c:2268–2323,2455–2537` resolves common endpoints in two passes, retaining the first exact comparator tie in the pinned oracle. `blast_stat.c:2777–2827` and `blast_parameters.c:208–223,335–347` require each query context's Karlin block for word X-drop and gap trigger. The [preserved BDT63307 before-fix pairwise files](first_differences/) first differ at byte **2237**: NCBI prints a `+` at that gap-script position, LOSAT printed a space and placed a later gap. The comparison-only [NCBI source probe](first_differences/ncbi_diag_trace.c) records `DIRECT_EXT q63/s76811 score=27 ... reached=0` in [its trace](first_differences/ncbi_seed_trace.log); matrix-average X-drop 16 had admitted this alternate LOSAT seed, while NCBI query-specific X-drop 15 did not. The permanent test verifies word X-drop 15, cutoff 36, and gapped seed `(q173,s76909)`. All final full-data bytes now match their declared oracles.
3. AvCLPV→PsCLPV full-query output then had an extra HSP at BDT63314 because LOSAT, and the earlier monolithic API comparison, treated all 120 queries as one local search. NCBI `tblastn_app.cpp:250–301`, `blast_input_aux.cpp:105–127`, and `blast_input.cpp:135–165` process TBLASTN query batches of at least 20,000 residues, retaining the threshold-crossing query in its batch. For diagnosis, NCBI CLI with `BATCH_SIZE=1000000` reproduced the old monolithic output; the default CLI and a comparison-only [batch API wrapper](run_batch_api_oracle.py) agree after query boundary reproduction. LOSAT now searches each batch independently and formats in input order. [Mixed validity boundary fixtures](batch_boundary/summary.json) distinguish skipped and searched batches; the full AvCLPV→PsCLPV code-1 CLI [cross-check](full_real_code1_cross/summary.json) is 12/12 exact.

The modified owners are `LOSAT/src/algorithm/tblastn/{args.rs,stage_d_pipeline.rs,search_gapped.rs,stage_d_results.rs,stage_e_report.rs}` and `LOSAT/src/report/pairwise.rs`. Each new Rust behavior has an adjacent NCBI file/line/snippet comment. The new unit tests cover the 20,000-residue boundary, invalid-query warning, all-invalid skipped search, tied HSP, and query-specific seed.
