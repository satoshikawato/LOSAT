# NA notes: TBLASTN application and argument layer

Files: `NA.tsv` (one row per NCBI function/branch/option), evidence in `scratch_NA/` (`runs/<label>.{n,l}.{out,err,rc}`: `n` = NCBI tblastn 2.17.0, `l` = `LOSAT-before tblastn`; helpers `cmp.sh`, `q.sh`, `qq.sh`, `qo.sh`, `add.py`; inputs `q1.faa`, `q.faa` (1 and 3 proteins of AvCLPV.faa), `s.fna` (first 30 kb of AvCLPV.fasta), `s15.fna` (15 subjects with the same hits), `q1_lc.faa`, `s_lc.fna`, `q1x.faa`).

## 1. Call path followed (NCBI)

1. `ncbiapp.cpp:920-1010` (`AppMain`): argv is pre-scanned (up to a bare `--`) for `-logfile`, `-conffile`, `-version`, `-version-full`, `-dryrun`; `-version` prints and exits 0 before any argument is parsed. `HideStdArgs(...)` (`tblastn_app.cpp:90`) only hides them from `-help`.
2. `ncbiargs.cpp:2833-3110` `CArgDescriptions::CreateArgs`/`x_CreateArg`: syntax (`-key value`, `-key=value`, flags, `--`), unknown/duplicate/missing/extra, then per-argument type conversion (`CArg_Integer`/`Int8`: decimal or `0x` hex via `s_StringToInt8`; `CArg_Double`: `NStr::StringToDouble` first-character rule then `strtod`; `CArg_Boolean`: `NStr::StringToBool`), constraints (`CArgAllowValuesGreaterThanOrEqual`, `CArgAllowStringSet`, `CArgAllowGeneticCodeInteger`, file name length) and dependencies (`eExcludes`, `eRequires`; `eRequires` needs an EXPLICIT value, a default does not count). All of this is "parser" level: USAGE text + `Error:` line, exit 1 (LOSAT: exit 2, PD exception 1).
3. `tblastn_app.cpp:114-170` `CTblastnApp::Run`: `SetDiagPostLevel(eDiag_Warning)`, `SetDiagPostPrefix("tblastn")` (warnings print as `Warning: [tblastn] ...`), `RecoverSearchStrategy` (`-import_search_strategy`), then `CBlastAppArgs::SetOptions` (`blast_args.cpp:3585-3640`).
4. `SetOptions` order (arg classes are pushed in `tblastn_args.cpp:48-129`, after `CSearchStrategyArgs` from the base constructor): `-outfmt` parsed first (`ArchiveFormatRequested`), options handle from `-task`, then `ExtractAlgorithmOptions` of: CProgramDescriptionArgs, CTaskCmdLineArgs, **CBlastDatabaseArgs** (missing `-subject`; subject file opened and read), **CStdCmdLineArgs** (`-query` opened, `-out` created/truncated), CGenericSearchArgs (`-evalue`, gaps with the matrix default, X-drops, `-word_size`, `-searchsp`, `-qcov_hsp_perc`, `-max_hsps`, `-sum_stats`), CGeneticCodeArgs, CGappedArgs, CLargestIntronSizeArgs, CFilteringArgs (`-soft_masking`, `-seg`), CMatrixNameArg, CWordThresholdArg, CHspFilteringArgs, CWindowSizeArg, CQueryOptionsArgs, CFormattingArgs (outfmt again, "Examining 5 or more matches is recommended"), CMTArgs (thread warnings), CRemoteArgs, CCompositionBasedStatsArgs, CPsiBlastArgs, CDebugArgs. Finally `CBlastOptionsHandle::Validate` -> `BLAST_ValidateOptions` (`blast_options.c:1749-1812`: extension, scoring (matrix, gap table), lookup (threshold, word size), initial word (x_dropoff), hit saving (hit list size, evalue, intron, culling, HSP filtering), extension+scoring (composition vs ungapped), identity word size). The first failing check becomes a `CBlastException` -> `CInputException` -> `BLAST query/options error: <msg>` + `Please refer to the BLAST+ user manual.`, exit 1 (`blast_app_util.hpp:167-262` `CATCH_ALL`).
5. `x_RunMTBySplitDB` (`tblastn_app.cpp:176-360`; with `-subject` `CMTArgs` forces one thread and split-by-DB): `InitializeSubject` (`BL2SEQ_LEGACY`), pssm/query setup, `IsIStreamEmpty(query)` -> `Warning: [tblastn] Query is Empty!` exit 0 (before any output), `CBlastFormat` + `PrintProlog` (outfmt 0 prolog goes out BEFORE the first query batch is read), per batch: `GetNextSeqBatch` (batch size 20000 residues, env `BATCH_SIZE`), `CLocalBlast::Run` (env `CHUNK_SIZE`, `OVERLAP_CHUNK_SIZE`, `OLD_FSC`, `ADAPTIVE_CBS`), `BlastFormatter_PreFetchSequenceData` (env `PRE_FETCH_SEQS_LIMIT`), `PrintOneResultSet` (per-query warnings are posted just before the query's block), `PrintEpilog`.

## 2. LOSAT counterpart and what it does (base commit 78c06fe61)

- `cli.rs:63-141` (`try_parse_from`): translates single-dash names to clap, rejects `is_unported_tblastn_arg` names with "unsupported TBLASTN option '-x': Rust behavior is unimplemented" (exit 2), anything else with "unknown option or argument" (exit 2).
- `algorithm/tblastn/args.rs`: `TblastnArgs` (clap struct, value parsers `tblastn_*`, `nonnegative_*`, `positive_usize`, `ncbi_bool`, `parse_seg_filtering`), `validate` (matrix, gap pair, identity word size, task, `-in_pssm`, `-db`, `-remote`, missing `-subject`/`-query`, `-subject_loc`, ungapped+CBS), `search_settings` (composition mode, `-max_intron_length`, `-ungapped`, threads, "profile_supported" = only BLOSUM62/word 3/gaps 11-1/threshold 13/window 40, and BLOSUM45/CBS 0/word 2/gaps 14-2/threshold 16/window 60), `run` (reads query then subject with `bio`, buffers the whole report, writes `-out` or stdout at the end), `run_local` (used by the web adapter; query batches of 20000 via `query_batches`).
- `main.rs:138-141` calls `TblastnArgs::run(args)?` directly: no `NativeError`, no `exit_on_native_error`, no `check_ncbi_application_settings`. Every post-parse failure is a plain anyhow error ("Error: ..." in Rust Debug form, with "Caused by:" chains), exit 1.
- The model to port to is BLASTN's `run` (`algorithm/blastn/blast_engine/run.rs:5134-5260`) and TBLASTX's `run_impl.rs` (`ReportStream`, `QueryWarnings`, `check_options`, `get_query_batch_size`).

## 3. Main findings (see the TSV for each)

1. **Error shape and exit codes (high impact, one fix)**: all post-parse TBLASTN errors lack the `BLAST query/options error: ` prefix and the `Please refer to the BLAST+ user manual.` line, and exit codes 3 (engine: empty subject), 255 (unknown exception, outfmt out of range), 6 (outfmt 0 write failure) are never produced. Route everything through `NativeError`.
2. **Order of checks (high)**: LOSAT reports value errors at clap parse time (exit 2) and validates options before any file is opened; NCBI parses `-outfmt` first, then subject, query, `-out` (created/truncated), then the option checks, then "Query is Empty!". Errors that NCBI raises AFTER parsing but LOSAT raises at parse time are not covered by PD exception 1: `-word_size 8..`, `-threshold 0`, `-evalue 0/-1`, `-seg` token errors, `-outfmt` errors (exit 1 / 255, `BLAST query/options error:`), `-db_gencode` is a true parser error in both (exception).
3. **Parser spellings (medium/low)**: LOSAT's integer/real/boolean parsers for TBLASTN are Rust `parse` based. NCBI accepts hex integers (`0x5`), `+5`, hex/`inf`/`nan` reals (`0x10`, `+inf`, `1e400`, `+nan`), negative `-gapopen`/`-gapextend`/`-xdrop_*`, booleans `on/off`, `--`, `-h`. Fix: reuse `ncbi_integer`, `ncbi_double`, `ncbi_string_to_bool` (all exist; BLASTN uses the first two).
4. **Entire inputs unported**: stdin for `-query`/`-subject` (and the default `-query -`), `Query is Empty!` (and empty-subject exit 3), `-out -`, name length < 256, `BATCH_SIZE`, `PRE_FETCH_SEQS_LIMIT`, `CHUNK_SIZE`/`OVERLAP_CHUNK_SIZE` conversion errors, non-UTF-8 names, `check_ncbi_application_settings("tblastn")`, the "Examining 5 or more matches is recommended" warning, warning order in a merged stderr/stdout stream, outfmt 0 write failure (exit 6), the prolog before reading queries.
5. **Option values that run in NCBI but not in LOSAT** (argument layer is S, engine work belongs to LK/NS): `-task tblastn-fast`, `-word_size` != 3, `-threshold`, `-window_size`, `-matrix` != BLOSUM62, gap pairs, `-comp_based_stats` 1/3/D/d/T/t/unknown, `-ungapped`, `-max_intron_length > 0`. D/d/T/t and "unknown first character" (= mode 0 in NCBI, no error) need only the argument mapping because mode 2 and mode 0 exist.
6. **Large `-max_target_seqs`**: NCBI's prelim hit list size wraps in Int4 (`2*h` / `2*h+50`): 2^30..2147483597 keeps 10 subjects (comp stats off), crash from 2147483598 (off) and from 1073741799 to 2147483623 (comp stats on, the default), 2147483624..2147483647 keep 2..all subjects. LOSAT keeps all. BLASTN has the same finding and a model (`get_prelim_hitlist_size`, `check_losat_limits`).

## 4. Surprises

- `-logfile`, `-conffile`, `-version-full`, `-xmlhelp`, `-dryrun` (hidden from `-help`) are accepted by NCBI; `-version` exits 0 before parsing and so wins over invalid arguments.
- `-out -` in LOSAT creates a file called `-` (NCBI: standard output).
- `-remote` ran against NCBI's server even with a local `-subject` (network is reachable here); avoid in further oracle runs.
- `-evalue +nan` searches and prints nothing (rc 0); `-evalue +inf`/`1e400` print every HSP; `-seg 12 2.2 0x10` (hicut 16 via strtod) prints nothing.
- `-gapopen 32767 -gapextend 32767` is a valid pair (the ungapped row of each matrix table).
- `-matrix blosum62` prints `Matrix: blosum62` in the outfmt 0 epilog (as typed); LOSAT prints `BLOSUM62`.
- `-use_sw_tback -ungapped -comp_based_stats 0` does not terminate in NCBI 2.17.0 (UNSURE: not investigated; > 120 s on a 1-query test).
- `-num_descriptions 0 -num_alignments 0` -> `BLAST query/options error: No hits are being saved`.
- `ADAPTIVE_CBS` set to anything (even empty) makes NCBI take another stream close; LOSAT stops with an "unimplemented" error when comp stats are on; no output difference was seen on the 15-subject test.
- Warnings in a merged stream: NCBI prints a query's warning after the previous query's rows; LOSAT prints it before all rows (stdout is written at the end).

## 5. NCBI tables/data the port needs

- Matrix list for the "not a supported matrix" message: `BLAST_PrintMatrixMessage` (`blast_stat.c:3760-3790`): `BLOSUM80, BLOSUM62, BLOSUM50, BLOSUM45, PAM250, BLOSUM90, PAM30, PAM70, IDENTITY`, each followed by " \n" (tblastn: standard_only false).
- Gap tables for "Gap existence and extension values of X and Y not supported for M\nsupported values are:\n" + rows: `BLAST_PrintAllowedValues` (`blast_stat.c:3797-3860`), first row 32767, 32767 (BLOSUM62: 32767/32767, 11/2, 10/2, 9/2, 8/2, 7/2, 6/2, 13/1, 12/1, 11/1, 10/1, 9/1); LOSAT `scoring.rs` tables lack the first row and the order must be the NCBI table order (they are already in that order for BLOSUM62).

## 6. Decisions the session must take

1. e-value `+inf`/`+nan`/`1e400`: port the cutoff arithmetic or reject as BLASTN did (row "BLAST_Cutoffs").
2. `-version`, `-h`: print LOSAT's own text? (`-version` names NCBI's build); map `-h` to `-help`.
3. Hidden framework flags (`-logfile`, `-conffile`, `-dryrun`, `-version-full`, `-xmlhelp`): keep the generic unknown-option error.
4. `BL2SEQ_LEGACY`, `OLD_FSC`, `CHUNK_SIZE`/`PRE_FETCH_SEQS_LIMIT`/`BATCH_SIZE` non-integers: reject explicitly (the NCBI message names the oracle build's source path), as TBLASTX did.
5. Large `-max_target_seqs`: port the Int4 wrap, reject the NCBI crash ranges.
6. `-searchsp`/`-dbsize`: port (needs the old finite-size-correction path for `-searchsp`) or reject.
7. Options beyond the product's outfmt 0/6/7 scope (`-html`, `-outfmt 5/8-16/18/20`, custom fields): keep rejecting; formatting options `-num_descriptions`, `-num_alignments`, `-line_length`, `-sorthits`, `-sorthsps`, `-parse_deflines`, `-show_gis` are RN/RP report work.
8. `-query_loc`/`-subject_loc`: S11 as instructed. `-db`, `-remote`, `-in_pssm`, `-import/-export_search_strategy`: reject.
9. Adapter `validate` (`web/adapter/src/run.rs:78-96`) runs no option check for TBLASTN: add `check_options` for TblastnArgs once the NCBI-ordered checks exist (the web GUI's validation text must equal the CLI's).

## 7. Cross-range hand-offs

NV: BLAST_ValidateOptions branches and task defaults (this range lists the message texts only); NS: matrices, gap pairs, comp stats modes, ungapped, sum stats, X-drops, intron; LK: word sizes, threshold, window, tblastn-fast lookup; IN/IP: reading of nucleotide/protein FASTA (LOSAT reads TBLASTN inputs with `bio`); RN: epilog (matrix name as typed), description table limits, warnings text positions.
