## LOSAT path

`algorithm/tblastn/args.rs:455-476` `run`: options check, then `bio::io::fasta::Reader::from_file` for the query and then the subject (no subject-first order, no `-`, no directory handling), records go straight to `run_local`; letters are converted in `search_seed.rs:138` (`resolve_local_subject_ncbi2na`, IUPAC incl. `-`, no `U`, anything else is the generic error "TBLASTN subject base 'x' is not implemented"). TBLASTX and BLASTN read through `blastn/input.rs` and *reject* what bio would misread (rows 7-9, 13-17, 21-24, 26, 29, 35 are rejections there); TBLASTN has none of those rejections, so it either errors with a generic text or, worse, succeeds silently with different output (rows 7, 13, 21-24, 27, 29, 31, 35).

## What is faithful (verified)

- IUPAC letters and line shapes (rows 12, 39); lowercase mask intervals under `-lcase_masking` (row 19: 40 random layouts + 12 multi-record files, outfmt 0 and 6 identical; the S07+ §O quirk and the double push for both strands are already in `translated_scan_ranges`); CRandom ambiguity resolution (row 33: 40 random layouts identical in outfmt 6); ordinary deflines (row 28); ordinary outfmt 0 titles (row 36).

## Most important differences (impact)

- Silent wrong output: `-` in a sequence line (row 13, different HSPs), lone CR line ends (row 7, empty output), `>?N` gap lines (row 35, extra subject), tab/control characters in the defline (row 24, outfmt 0 title and sseqid), empty/blank/leading-space deflines (rows 21, 22, sseqid empty instead of `Subject_N` or the first token), subjects shorter than 3 nt (row 31, the other subjects lose weak HSPs: `min_subject_length` lacks NCBI's floor of 10 and counts the empty record).
- Generic hard errors where NCBI continues (medium impact): spaces/tabs inside sequence lines (14), `U` (18), any non-IUPAC letter (16), blank/comment lines before the first defline (8), no-defline FASTA (9), whitespace-only/comment-only subject (30), `-subject -` (3).
- Message/exit-code differences: nonexistent subject (2), directory (4), missing `-subject` (1), order of errors (6), BOM/implausible first data line (11).

## Surprises

1. NCBI's byte-wise defline handling: the title is cut at the first byte < 0x20, but the first byte after the leading blanks is always kept; sseqid is the first space-separated token of that title (not the first token of the file's defline), so for deflines with leading blanks, control bytes or Unicode white space the NCBI sseqid differs from bio's id. The local id `Subject_N` appears only when the title is empty.
2. `Subject_N` counts every record read (also empty ones that are later skipped with the "no data" warning).
3. bl2seq keeps empty subjects in the set (counted in "N sequences", length 0) and they enter `min_subject_length`; NCBI floors it at 10; LOSAT computes `min/3` without the floor and silently loses weak HSPs of the other subjects when a subject has 0-2 nt (row 31). This is an engine difference, not a reader difference.
4. outfmt 0 title of a non-UTF-8 defline is transcoded (Latin-1/Windows-1252 to UTF-8) by `HtmlDecode`'s encoding guess, while outfmt 6/7 print the raw bytes; a byte 0x81/0x8D/0x8F/0x90/0x9D among invalid UTF-8 makes NCBI print `Unknown` and skip the alignments of that subject (exit 0). This is deterministic, so by PD-LOSAT-NCBI-DEFECTS rule 2 it is reproduced, not an exception.
5. The ambiguous-codon display B/Z/J also changes `Positives` and the middle line (row 34), although outfmt 6 is identical.
6. `CBlastInputReader` makes a file whose first line looks like an accession a remote lookup (row 10). Offline NCBI gives `Sequence ID not found` (exit 1); with network the outcome depends on Genbank. Reject.
7. TBLASTX has the same gap for lone CR line ends (`hx.py e_cr`: output differs; its title warning fires on the file read as one defline). BLASTN presumably too. TBLASTX m_len2 equal (different engine).
8. The approved exception 2 (punctuation titles) is still unported for TBLASTN (row 38): LOSAT rejects; port is small (drop the bail, check with the S07+ `title_sweep.py` approach on the 3124 TBLASTN deflines of up to 5 of `,;~ a`).

## Decisions for the session

1. Shared reader port or rejections. Two routes: (a) cheap: give TBLASTN the same rejections as TBLASTX/BLASTN (`blastn/input.rs` with program "TBLASTN": `check_utf8_file_name`, `open_input`, `read_fasta_bytes`, `check_deflines_of`, `check_sequence_lines_of`, `check_residues_of`, `check_records_have_residues_of`, `with_u_as_t`, `write_title_warnings`) and the `check_subjects_not_empty` / order of TBLASTX `run`. That turns rows 7, 13, 21-24, 26, 29, 35 and the generic errors of 14-18 into explicit rejections (S each) but not into NCBI behaviour. (b) per the memory rule "transpile NCBI paths wholesale": one new reader module (about 600-800 Rust lines: CStreamLineReader, ReadOneSeq, ParseDefline, CheckDataLine, ParseDataLine with mask offsets over kept residues, ParseGapLine/AssembleSeq gap fill, title warning, PostWarning texts, ConvertBadIndexesToString) that returns raw defline bytes, title bytes (cut), `Subject_N` ordinal, kept uppercase residues, mask intervals and the warnings in order; BLASTN and TBLASTX could drop their rejections later. The rows marked `port:M` with "shared reader" assume (b); `port:S` rows are independent of it.
2. HtmlDecode (row 37): port (table 281 entries + encoding guess + Unknown path, about 400 lines) or keep rejecting; BLASTN rejects the same today.
3. Row 43 (2^31 nt subject) not run; BLASTN rejects a total of 2^31; decide the same for TBLASTN or test NCBI on a large file.
4. `-parse_deflines` (range `*A`) changes this reader (fParseRawID: ids are parsed, ranges `:1-100` create new ids, `>?` etc.); the reader port should carry the flag set.
5. Not tested (environment variables, out of scope): `BLASTINPUT_GEN_DELTA_SEQ` (removes fNoSplit), `BLASTDB`/`.ncbirc` (data loaders in row 10).

## Other observations outside range IN (seen on the way)

- `-word_size 2` is accepted by NCBI tblastn but LOSAT stops with "unsupported TBLASTN scoring and lookup option combination" (exit 1); `-window_size 0` too (rc 1). Both belong to the option ranges.
- Empty query with a good subject: NCBI prints "Warning: [tblastn] Query is Empty!" and exits 0, LOSAT: "TBLASTN query file is empty" exit 1 (query range).
- Missing query file: NCBI `Command line argument error: Argument "query". File is not accessible` (exit 1) vs LOSAT's "failed to open FASTA" (query range; same `inaccessible` helper fixes it).
