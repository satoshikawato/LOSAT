- LOSAT Web (`web/adapter`, the `losat` npm package at ABI version 14, and the browser application) now reads `-logfile` against the run's real files (the run directory and a search's `-query`, `-subject`, `-conffile` and `-window_masker_db` inputs, inside or outside the working directory), as the command line does in a folder holding those files: a `-logfile` in a missing folder or naming a folder keeps messages on stderr with no file, a `-logfile` naming an existing file of the run or a file the run opens or checks for reading (also when that file is missing, such as a `-db` list file, database lookup files of `-db`, BLASTN's `-filtering_db` or `windowmasker -infmt blastdb`, `taxdb.bti` or paired `taxdb.btd` when `-outfmt` consults the taxonomy database, or a `windowmasker` input including `-fa_list true` listed entries) and a `windowmasker` `-out` naming an existing file or a missing input read after `-out` (`-in` of `-mk_counts` including `-fa_list true` entries and `-infmt blastdb` lookup files, `-ustat` of masking) are refused, `windowmasker -logfile /dev/stdout` writes diagnostic messages into stdout in the command line's byte order, and output and log files delivered to the host carry the command line's normalized file name (`run.log` for ` run.log` and `./run.log`, `logs` for `logs/`, `x.counts` for `-out ./x.counts`).
