- `losat psiblast` writes `-outfmt 5` (BLAST XML), `8` and `9` (Seq-annot in ASN.1 text and binary) and `11` (the BLAST archive) with the bytes of NCBI BLAST+ 2.17.0 `-num_threads 1` (apart from the version line, which names LOSAT), at every thread count, for a FASTA query at any `-num_iterations`, for `-in_pssm` and for `-in_msa`, with `-db` and `-subject`; with `-in_pssm` or `-in_msa` it also writes `-outfmt 10` and `20`. Before, `psiblast` wrote `0`, `6`, `7`, `10` and `20` (with `-in_pssm` or `-in_msa`: `0`, `6` and `7`). The XML document holds one `Iteration` per round, numbered across rounds and queries; the Seq-annots and archives come one per round, and the archive of a later round holds the PSSM that the round searched with its Karlin-Altschul values, as NCBI's does. As in NCBI, the XML report cuts each round's hits to `-max_target_seqs` before the next round's PSSM is made, so with a small `-max_target_seqs` its rounds can converge earlier than those of the other formats, and the archive keeps every hit of the round. `losat tblastn -in_pssm` now writes `-outfmt 5`, `8`, `9` and `20` too; `-outfmt 11` stays refused, because NCBI's `tblastn` stops there with a C++ exception whose report changes from run to run. Formats `1` to `4`, `12` to `16` and `18` stay refused for `psiblast` (and `12` to `16` and `18` for `tblastn -in_pssm`), with the message "output format N is not supported by LOSAT's PSIBLAST yet". Tests: frozen NCBI rows for each new format.
