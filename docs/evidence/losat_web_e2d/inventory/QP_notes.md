# QP notes: -query_loc for protein queries (blastp, tblastn), bl2seq only

All NCBI line numbers are relative to `c++/` of commit 598d8ae6. Oracle = NCBI BLAST+ 2.17.0 in `scratch_QP/` (`run.sh` defines `o NAME PROG args` which writes NAME.cmd/.out/.err/.rc/.time, and `l` for LOSAT-before).

## Call path (blastp_app.cpp / tblastn_app.cpp, bl2seq = `-subject`, `x_RunMTBySplitDB`)
1. `CQueryOptionsArgs::ExtractAlgorithmOptions` (blast_args.cpp:1996-1999): `-query_loc` -> `ParseSequenceRange(str, "Invalid specification of query location")` (blast_input_aux.cpp:145-179) -> `TSeqRange` 0-based closed [from-1, to-1]. One range for ALL query records.
   Parser errors (thrown from `SetOptions`/arg processing, before any input is read): format != `a-b` (split on `-`, 2 non-empty tokens) -> `Invalid specification of query location (Format: start-stop)`; elements <= 0 -> `... (range elements cannot be less than or equal to 0)`; from == to -> `... (range cannot be empty)`; from > to -> `... (start cannot be larger than stop)`; `NStr::StringToInt` failure -> CStringException. (Parser details belong to range RF; see its table. Observed texts are repeated below in the oracle section.)
2. `CBlastInputSourceConfig iconfig(dlconfig, strand, lcase, parse_deflines, query_opts->GetRange())`; `CBlastFastaInputSource`; `CBlastInput input(&fasta, GetQueryBatchSize())` (blastp 10000, tblastn 20000, blast_input_aux.cpp:70-139).
3. Loop `input.GetNextSeqBatch(scope)` (blast_input.cpp:121-160) -> `CBlastFastaInputSource::GetNextSequence` -> `x_FastaToSeqLoc` (blast_fasta_input.cpp:380-460): reads the WHOLE record (CFastaReader, all reader warnings/errors for the whole record), then range sanity checks and builds the `CSeq_interval` (strand unknown for proteins; id = best id; from/to 0-based closed).
   * `from = range.from (0 if empty range) ; to = range.to (0 if empty)`; `seqlen` = full record length.
   * `to > 0 && to < from` -> throw eInvalidRange "Invalid sequence range" (cannot happen after the parser).
   * `from > seqlen` -> throw eInvalidRange "Invalid from coordinate (greater than sequence length)".
   * interval = [from, (to>0 && to<seqlen) ? to : seqlen-1] (to past the end is fixed silently).
   * NOTE `from == seqlen` is NOT rejected: with -query_loc 675-800 on a 674-letter record the interval is [674,673], length 0 -> later "Sequence contains no data".
4. CRUCIAL: `GetNextSeqBatch` wraps `GetNextSequence` in `catch (const exception&) { continue; }` (SB-2307). The eInvalidRange exceptions are therefore SWALLOWED: a record shorter than the range start is silently skipped (no message), numbering of later records (Query_N local ids) is unchanged (the reader already consumed it). Skipped records add nothing to `size_read`.
   If every record of the final batch is skipped, `CObjMgr_QueryFactory(CBlastQueryVector&)` throws `Empty CBlastQueryVector` (objmgr_query_data.cpp:375-380): `BLAST engine error: Empty CBlastQueryVector`, exit 3, after the reports of earlier batches (and after the outfmt 0 prolog).
   `size_read += sequence::GetLength(loc->GetInt().GetId(), scope)` = FULL record length (not the interval) -> batch composition ignores the range.
5. `CObjMgr_QueryFactory` -> `CLocalBlast` -> `CBlastPrelimSearch` etc. `CObjMgr_LocalQueryData::GetQueryInfo` -> `SetupQueryInfo_OMF` (blast_setup_cxx.cpp:153-281): `length = queries.GetLength(j)` = `sequence::GetLength(seqloc)` = INTERVAL length (blast_objmgr_tools.cpp:324-345); protein: one context, `s_QueryInfo_SetContext(qinfo, ctx_index, length)`; offsets = prev_offset + prev_len + 1. `max_length/min_length` from interval lengths.
6. `GetSequenceBlk` -> `SetupQueries_OMF` (blast_setup_cxx.cpp:485-657): per query `s_GetRestrictedBlastSeqLocs` (the lowercase mask in RECORD coordinates restricted to the interval and shifted to interval-local by `BlastSeqLoc_RestrictToInterval(mask, from, to)`, core/blast_setup.c:1029-1062), message id (`Query_N title`, 25 chars + ".. " when > 35), `GetBlastSequence` -> `GetSequence(seqloc,...)` (blast_objmgr_tools.cpp:568) -> `CBlastSeqVectorOM` over the interval -> `GetSequenceProtein` (blast_setup_cxx.cpp:871-943): `O` -> X with the warning, positions are 0-BASED INDEXES INSIDE THE INTERVAL, only letters of the interval are examined. Then `s_AddMask`.
7. `BLAST_MainSetUp` (core/blast_setup.c:563-): `BlastSetUp_GetFilteringLocations` (core/blast_filter.c:1262) runs SEG (`SeqBufferSeg`) on each context buffer (= the interval residues), appends the restricted lowercase mask, `BlastSeqLocCombine`; `BlastSetUp_MaskQuery` Xs the buffer; `BlastSetup_ScoreBlkInit` -> `Blast_ScoreBlkKbpUngappedCalc` (blast_stat.c:2737) computes kbp from the composition of the context buffer (interval, SEG-masked) -> every query statistic (length adjustment, effective search space, cutoffs, x-dropoffs) uses the interval length and interval composition.
8. Split: `CBlastPrelimSearch::Run` -> `CQuerySplitter` (split_query_cxx.cpp): `m_TotalQueryLength = sum of GetSeqLength` = interval lengths; `SplitQuery_CalculateNumChunks` (split_query_aux_priv.cpp:104-145); chunk ranges are in concatenated-interval coordinates; `x_ComputeQueryIndicesForChunks` offsets each chunk Seq-interval by the interval start (`q_sl_offset`). BUG-LIKE: masks for the chunk are restricted with an interval in range-LOCAL coordinates while `m_UserSpecifiedMasks` are in RECORD coordinates (see below).

## Coordinate conventions at each step
* CLI string `a-b` (1-based, inclusive) -> `TSeqRange` [a-1, b-1] 0-based closed (`ParseSequenceRange`, blast_input_aux.cpp:145-179).
* `x_FastaToSeqLoc`: Seq-interval [from, to] 0-based closed in RECORD coordinates, residue units (protein). `to` is clipped to seqlen-1. Length = to-from+1 (can be 0 when from == seqlen).
* Search setup (SetupQueryInfo_OMF/SetupQueries_OMF): only the interval residues exist; context 0 = interval residue 0. SEG, lowercase masks, composition, Karlin parameters, length adjustment, effective search space, cutoffs, query splitting, kappa/CBS all work in INTERVAL-LOCAL coordinates and lengths. Lowercase masks (record coordinates from the reader) are restricted and shifted by `BlastSeqLoc_RestrictToInterval(mask, from, to)`: left=max(0,left-from), right=min(right,to)-from (core/blast_setup.c:1029-1062).
* Split: chunk ranges [cs,ce) are over the concatenation of the batch's INTERVALS (interval-local); a chunk's Seq-interval is `[max(0,qstart)+f, ...+f-1]` (f = interval start, `q_sl_offset`, split_query_cxx.cpp:188-208). HSPs of a chunk are shifted back by the context offsets (also interval-local).
* Results: HSP query offsets are interval-local; `RemapToQueryLoc` (blast_seqalign.cpp:1520-1530) shifts the Seq-align query row by f. Reported qstart/qend (1-based) = local + f + 1. Subject coordinates are untouched.
* Message positions (O->X warning) are 0-based INDEXES INSIDE THE INTERVAL (GetSequenceProtein iterates the CSeqVector of the interval).
* Lengths in play (use exactly these): batch accounting = FULL record length of kept records; statistics/split/context = INTERVAL length (clipped); tabular `qlen` = unclipped range length (to-from+1 of the option) when -query_loc is given; outfmt 0 `Length=` = FULL record length. (qlen and Length= are formatter, range RF.)

## Oracle observations (all in scratch_QP; inputs: q1.faa = BDT63357.1 674 aa, qmulti.faa = records of 986/674/394 aa, s3.faa protein subjects, sn.fa = LvMJNV genome 280 kb)
1. `blastp -query q1.faa -subject s3.faa -query_loc 100-400 -outfmt "6 std qlen slen"`: first line `...100 400 109 392 6.67e-130 375 301 707` (o_p_mid.6.txt). Without a range the same hit is 4-638 with E=0.0. qstart/qend are record coordinates, E-value is that of a 301-residue query, qlen = 301.
2. End past record end (p_end_past, t_end_past): `-query_loc 600-1000` on 674 letters: no message, exit 0, statistics of a 75-residue query, but qlen column = 401 (formatter prints to-from+1 of the option). `-query_loc 100-675` on 674 letters: qlen 576; `1-674`: identical to no range; `1-2147483647`: qlen 2147483647, hits identical to no range.
3. Start beyond the record: `-query_loc 676-800` on 674 letters -> exit 3, stdout empty (outfmt 0: prolog printed), stderr `BLAST engine error: Empty CBlastQueryVector` (no mention of the range). `675-800` (from == seqlen) -> exit 3 `BLAST engine error: Warning: Sequence contains no data ` (query kept with length 0). `674-800` -> exit 0, 1-residue query, no hits. Same for tblastn (t_from_gt, t_from_eq).
4. Multiple records, one range (p_multi_*, t_multi_*): `-query_loc 700-900` on 986/674/394 aa: only the 986 aa record is searched; the others vanish without any message, exit 0; with `1000-1100` all vanish -> exit 3 Empty CBlastQueryVector. `-query_loc 100-400`: the 394 aa record is searched on 100-394 (qlen printed 301). outfmt 7 header says `# BLAST processed 1 queries` for 3 records read.
5. Record numbering: with record 1 dropped, the O warning of the next record says `Query_2` (p_skip_first.err); with three 6000-aa records the third says `Query_3` (p_ABC.err): global ordinal.
6. Batches (p_ABshort/t_ABshort2): records of 6000/6000/50 aa (blastp) or 12000/12000/50 aa (tblastn), `-query_loc 100-300`: A and B are searched and printed, then `BLAST engine error: Empty CBlastQueryVector`, exit 3, because batching adds FULL record lengths (A+B >= 10000 closes the batch) and the last record is dropped. Order A,S,B: exit 0. Same input without a range: one search, exit 0 (p_ABshort_nolocjunk).
7. O/U/*/J (p_O_*, t_O_*, p_U_*, p_Star_*, p_J_*, p_B_*): O outside the range -> no warning, hits identical to a clean query; O at record 200 and 250 with range 100-400 -> `One or more O characters replaced by X for alignment score calculations at positions 100, 150`; without a range the same O's give `positions 199, 249`. U, J, B, Z, `*` inside the range change the E-value slightly and give no warning; outside the range they change nothing. A trailing `*` counts in the record length (675) and is searched when inside the range.
8. Reader warnings and errors are for the whole record, before the cut: a hyphen outside the range still gives `CFastaReader: Hyphens are invalid and will be ignored around line 2`; a digit gives `FASTA-Reader: Ignoring invalid residues at position(s): On line 2: 50` and removes the residue, so the range then counts the cleaned sequence (hit moved by one). A dropped record with a 50+ amino-acid title tail still gives the title warning (p_title_skip.err). LOSAT rejects those bytes today (blastn/input.rs).
9. SEG (p_LC_*, slice_cmp qLC*): low-complexity run at 80-131 and 390-441 with range 100-400: output == the cut slice searched unranged (qstart/qend shifted by from-1, same E-values) for blastp -seg yes and tblastn default. Lowercase run straddling the range start/end (tblastn -lcase_masking, also with -soft_masking true): output == cut slice.
10. Composition-based statistics (-comp_based_stats 0,1,2,3, blastp and tblastn), -use_sw_tback, -task blastp-fast/blastp-short/tblastn-fast, -db_gencode 11, -max_target_seqs: ranged == cut slice, all IDENTICAL (evidence_slice_cmp.txt).
11. Split (evidence_split_cmp.txt): record qSkew25k.faa (25000 aa: 12000 aa of skewed composition + AvCLPV proteins), subject LvMJNV.faa, `-evalue 1000` (this makes the split visible: default chunking and CHUNK_SIZE=1000000 give 998 vs 939 lines). Ranges 1-12000, 12001-25000, 9950-10150, 1-19799: ranged == unsplit; 1-19800, 3001-22800 (both 19800 aa), 5000-25000 (20001 aa): ranged == split cut slice, and != unsplit. Thus: the split depends on the interval length (19799 -> 1 chunk, 19800 -> 2 chunks), never on the record length; chunk boundaries are interval-start + [0,12551)/[12451,...) style ranges (chunk size = (L+(n-1)*100)/n (+1)). Records 9000+25000 aa with 5001-25000: sum 24000 -> split. Dropped records add nothing.
12. Lowercase mask + split + f>0 (tblastn, qMaskA_low.faa, evidence_mask_boundary.txt): ranged output differs from the cut slice only when the query is split and the mask lies in the lost span; with `CHUNK_SIZE=1000000` the ranged output equals the cut slice. Behaviour above is an NCBI defect (mask restriction in the wrong coordinate space); per the NCBI defect policy it is deterministic and stays reproduced; the session may want to ask in a batch.
13. -num_threads 4 with a range: byte-identical output (p_threads). stdin query (`-query -`) with a range: same (p_stdin).
14. Parser errors (p_parse_*): see row 2; all before any output; `100-` etc exit 3, non-numeric exit 255 with the CStringException text.

## Surprises / things the session must decide
* The SB-2307 `catch (const exception&) { continue; }` turns every "range start beyond this record" into a silent skip (no message) and can end in `Empty CBlastQueryVector` (exit 3) in the LAST batch after the earlier batches printed. LOSAT's current `batch_size == 0` path (blast_engine.rs:5023, tblastn/args.rs:850) is the template for the message and the outfmt 0 prolog.
* `from == seqlen` (range start = record length + 1) is accepted by NCBI and yields a zero-length query ("Sequence contains no data"). LOSAT has no zero-length query path anywhere (rejects empty records). Decide: port the NCBI path (also fixes the unranged empty-record rejection) or keep an explicit rejection only for this edge (reason would be 'LOSAT has no zero-length query'; it is not an NCBI crash).
* Three different lengths per query must coexist in LOSAT: FULL record length (batches, title warnings, outfmt 0 `Length=`), INTERVAL length (statistics, split, contexts), unclipped RANGE length (tabular `qlen`). Today LOSAT has one `query_lengths` vector per program.
* Original record ordinal must be carried for `Query_<n>` messages when records are dropped.
* Mask defect with split + range + lowercase (tblastn): reproduce; the algorithm is in the table row; blastp has no -lcase_masking.
* Existing code that is right once it receives the cut sequence: SEG, lowercase runs, composition/Karlin, eff. lengths, CBS (kappa), chunking and offsets; the oracle runs (evidence_slice_cmp.txt, evidence_split_cmp.txt) are a ready regression recipe: for each case, ranged LOSAT output must equal LOSAT run on the cut record with qstart/qend shifted by from-1 (qlen column excluded).
* The tabular `qlen` quirk and `# BLAST processed N queries` (kept records only) belong to the formatter range (RF) but must use the lengths above.
* Reader behaviour for invalid residues (digits removed, hyphen warning) makes the range count the cleaned sequence; irrelevant while LOSAT rejects those bytes.
* UNSURE (not tested): behaviour with a protein subject set that is the query file itself, -query_loc together with -in_pssm (rejected by LOSAT, NCBI uses the PSSM query), and -parse_deflines (rejected by LOSAT): no ranges involved.
