# LOSAT v0.1.0 Scope

Last updated: 2026-09-03.

This document is the canonical concise v0.1.0 support table. The three durable
program certification records govern every supported claim. The release remains
unpublished; exact-SHA artifact certification is emitted by the separate manual
release-readiness workflow and is not embedded back into this source document.

NCBI BLAST C/C++ source code remains the sole behavior authority. NCBI BLAST+
executables are validation oracles only and must not be used by LOSAT runtime,
build, feature, fallback, or unsupported-feature paths.

## Approved TBLASTX Deviation

TBLASTX local `-subject` searches intentionally honor `--db-gencode` for subject
translation/search/reporting for every non-default genetic code. This is the
only approved v0.1.0 deviation from NCBI BLAST+ local `-subject` behavior.

This exception is narrow. It does not permit differences in timing, ordering,
scoring, filtering, statistics, pruning, coordinate handling, output fields, or
formatting.

This is the only approved v0.1.0 behavioral deviation.

The BLASTN source-underdetermined equal-HSP classification in
[`PD-BLASTN-HSP-CANONICALIZATION`](product_decisions/PD-BLASTN-HSP-CANONICALIZATION.md)
Version 1.2 is not an additional deviation. It preserves the multiple survivor
representations permitted by NCBI BLAST+ 2.17.0 source while retaining exact
parity for source-defined behavior.

## User-Facing Contract

- LOSAT is a Rust implementation, not a wrapper around NCBI BLAST+.
- NCBI BLAST+ may appear in tests, diagnostics, comparison scripts, and release
  validation artifacts only.
- Unsupported options must fail explicitly or remain outside the documented
  release scope.
- Generated comparison outputs are not release source unless explicitly
  documented as canonical fixtures.

## Remaining Release-Wide Gate

Program and platform certification do not publish v0.1.0. Run the manual
release-readiness workflow at one exact committed candidate SHA. Its output
must contain:

- the candidate SHA and PR 5/PR 6 certification lineage;
- Rust/Cargo 1.92.0 identities, target triples, features, profile, and relevant
  build environment;
- four native archives, one serial-Wasm archive, and one Cargo source package;
- SHA-256 checksums, target architecture, `--version`, and the canonical
  representative BLASTP smoke result for every executable artifact;
- clean extraction for binary archives and a clean offline install for the
  source package;
- truthful signing/notarization and publication state;
- explicit `RC_HANDOFF_READY` only after all six artifacts pass.

The machine-readable authority for this gate is
[`v0.1.0_rc_contract.json`](release/v0.1.0_rc_contract.json). Tagging, GitHub
Release creation, crates.io publication, and Bioconda submission remain
separate maintainer-authorized actions.
