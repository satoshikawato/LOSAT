# Session A — 権威・基準値・製品判断

## INSTRUCTION PROMPT

`feature/tlosan-tblastn-v0.2.0` で TLOSAN v0.2.0 の段階 A を実行する。
開始時に現在のブランチ、作業ツリー、直前セッションの有無を確認し、
総合計画書 `docs/tlosan_tblastn_v0.2.0_plan.md` と `AGENTS.md`、
`verify-ncbi-parity-and-speed` を読む。このセッションでは基準を固定し、
段階 B 以降の探索・出力実装には進まない。

1. NCBI ソース checkout の commit と主要ファイル、NCBI BLAST+ の版・SHA-256、
   LOSAT commit、target、コマンドラインの全オプションを記録する。
   総合計画書のソース行番号は着手時に再確認する。
2. `-task tblastn` の CLI → オプション → subject 翻訳 → 探索 → HSP 統合 →
   統計 → 表示という NCBI 呼び出し経路を、関数・ファイル・行範囲と実行順で表にする。
   既定値はソースと現行 `-help`・基準出力を照合する。
3. 入力 SHA-256 を固定した小型ケースを作り、コード 1 と非標準コードについて
   NCBI `-subject` と事前作成した `-db` の出力を新しい一時ディレクトリに保存する。
   ローカル検索と DB 検索の生バイトを直接同一視せず、差の原因を記録する。
4. 明示された TBLASTN ローカル subject の `-db_gencode` 要件と
   コード 32 の CLI 受理を TBLASTN 限定の製品判断として記録し、
   `AGENTS.md` に範囲を明記する。既存の TBLASTX 例外を暗黙に拡張しない。
   対象外の相違を許す文言は加えない。
5. NCBI CLI が拒否するコード 32 について、`gc.prt` と
   `FindGeneticCode(32)` を使う比較専用 NCBI C++ API オラクルの成立方法と
   実行コマンドを確立する。翻訳だけでなく HSP・統計・表示の検証経路を用意し、
   LOSAT のビルド・実行・配布経路へ含めない。

成果物は、再実行可能なコマンド、入力と実行ファイルの SHA-256、ソース対応表、
最初の差分と例外区分、コード 32 のオラクル記録である。
段階 B へは、27 ID の検証方法と限定契約が明確になってから進む。
不成立のオラクルや未決定の製品判断は未解決として明示する。
