# Range QP: the query range for protein queries (blastp, tblastn)

Files: `QP.tsv`, `QP_notes.md`. Read `COMMON.md` first.

Entry points (NCBI): as in nucleotide queries, the range becomes a `CSeq_interval` in `CBlastFastaInputSource::x_FastaToSeqLoc` (`c++/src/algo/blast/blastinput/blast_fasta_input.cpp:380-460`, strand unknown for proteins). Follow it through `CObjMgr_QueryFactory` (`c++/src/algo/blast/api/objmgr_query_data.cpp`), `SetupQueryInfo_OMF` and `SetupQueries_OMF` (`c++/src/algo/blast/api/blast_setup_cxx.cpp`: protein sequence data for the interval, sentinels, context length), invalid-residue handling and warnings (which letters are checked: the whole record at read time, or the interval at setup? e.g. `O`/`U`/`*`/`-` replaced by X with a warning), lowercase masks (`-lcase_masking` on tblastn; blastp has no `-lcase_masking` in LOSAT), SEG (`-seg yes` default for tblastn? and blastp `-seg yes`): `BlastSetUp_GetFilteringLocations` on the interval letters, composition-based statistics (`-comp_based_stats` 0-3: the query composition comes from the interval), the query split for long queries (`c++/src/algo/blast/api/split_query*.cpp`, `split_query_aux_priv.cpp:73-138`: blastp chunk 10000, tblastn 20000, overlap 100; is the split decided from the interval length; `s_SetSplitQuerySeqInterval` and how chunk offsets map back to the record when the query is an interval), query batches (`GetQueryBatchSize` for blastp/tblastn), statistics (query length in effective lengths, length adjustment, effective search space, the `kbp` from the interval composition), and outfmt 0's "Length=" for the query (full record or interval? the formatter is range RF; you only note what the query length in the search setup is).

LOSAT side: BLASTP query reading and encoding (`algorithm/blastp/blast_engine.rs` `run`/`run_local`, `algorithm/blastp/query_split.rs`, `algorithm/common/protein_query_split.rs`, SEG, composition stats in `algorithm/blastp/kappa.rs`), TBLASTN query reading (`algorithm/tblastn/args.rs` `run`, `search_init.rs`, `stage_d_*`, `kappa.rs`), lowercase in TBLASTN. For each NCBI step say where LOSAT must apply the range and whether existing code then matches NCBI.

Oracle runs to make (blastp and tblastn, outfmt 0 and `6 std qlen`): a range in the middle with hits crossing the range edges; a range end past the record end; multiple query records with one range; an `O`/`U`/`*` letter outside the range and inside the range (which warnings appear, and for which coordinates); a lowercase run straddling the range start with `-lcase_masking` (tblastn); a low-complexity run straddling the range start with SEG on; `-comp_based_stats 2` with a range (composition from the range); a ranged query that is split: blastp record of 25,000 letters with ranges 1-12000, 5000-25000, 9950-10150 (does the split depend on the range length? where are the chunk boundaries in record coordinates?), tblastn similarly with a 45,000-letter record (chunk 20000).
