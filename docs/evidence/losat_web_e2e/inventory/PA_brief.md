# Range PA: BLASTP application and argument layer

Files to write: `PA.tsv`, `PA_notes.md`. Scratch: `scratch_PA/`.

Entry points (NCBI): `src/app/blast/blastp_app.cpp` (`CBlastpApp::Run`, `main`), `src/algo/blast/blastinput/blastp_args.cpp` (`CBlastpAppArgs`: which arg classes, order, `x_CreateOptionsHandle`, tasks), `src/algo/blast/blastinput/blast_args.cpp` (each arg class's `SetArgumentDescriptions` (types, defaults, constraints, dependencies) and `ExtractAlgorithmOptions` for the classes blastp uses: CProgramDescriptionArgs, CTaskCmdLineArgs, CGenericSearchArgs, CFilteringArgs (`-seg`, `-lcase_masking`, `-soft_masking`), CWindowSizeArg, CWordThresholdArg, CMatrixNameArg, CCompositionBasedStatsArgs, CGappedArgs, CHspFilteringArgs, CFormattingArgs (`-outfmt` parsing `ParseFormattingString`, `-max_target_seqs` and the hitlist size, the "Examining 5 or more matches" warning), CMTArgs (`-num_threads`, `-mt_mode`), CStdCmdLineArgs (`-query`, `-out`), CBlastDatabaseArgs (`-subject`, missing subject error), CRemoteArgs, CDebugArgs, CSearchStrategyArgs, CQueryOptionsArgs; `CBlastAppArgs::SetOptions` order and `Validate`), `src/algo/blast/blastinput/blast_input_aux.cpp`, `src/app/blast/blast_app_util.{hpp,cpp}` (the exception-to-exit-code macro, `IsIStreamEmpty`, `Query is Empty!`), `src/corelib/ncbiargs.cpp` (how CArg_Integer, CArg_Int8, CArg_Double, CArg_Boolean, CArg_String parse values; constraint classes `CArgAllowValuesGreaterThanOrEqual`, `CArgAllowValuesBetween`, `CArgAllowStrings`; dependency/exclusion errors; USAGE output and exit 1 for argument errors), `src/corelib/ncbistr.cpp` (`StringToInt`, `StringToDouble`), `src/corelib/ncbiapp.cpp` / environment-reading of the application (see `LOSAT/src/blastinput/ncbi_environment.rs` for what BLASTN reproduces).

LOSAT counterpart: `cli.rs`, `blastinput/value_parsers.rs`, `algorithm/blastp/args.rs`, `algorithm/blastp/blast_engine.rs` (`run`, `run_local`, `validate_cli_outfmt`), `main.rs`. Compare with BLASTN's `run` (model).

Cover, per option in the blastp scope and per NCBI blastp option outside it (one row each): type and value parsing (hex, signs, spaces, `strtod` spellings, inf/nan, overflow), constraint and its error text and exit code, default, where/when NCBI reads it (which handler, in which order relative to opening the subject, query and `-out`), and what LOSAT does. Then the application flow: order of `-outfmt` parsing, missing `-subject`, reading the subject (empty subject file error), opening the query (inaccessible file text, `-` stdin, default `-query -`), opening `-out` (once, name length), warnings, the options check (`Validate`), `Query is Empty!`, batching of queries (`GetQueryBatchSize` for blastp), the per-batch search and formatting, write failures (`BLAST failed to write output`, exit 6 for outfmt 0), environment variables NCBI's blastp reads (`check_ncbi_application_settings` is BLASTN-only in LOSAT today), `-num_threads` limits, non-UTF-8 file names. Run both binaries on representative bad values to compare stdout, stderr and exit codes.
