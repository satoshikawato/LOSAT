# LK notes: protein lookup table, word finder, word size / threshold / window (BLASTP, TBLASTN, TBLASTX)

Range file: `LK.tsv` (79 rows). Scratch: `scratch_LK/` (inputs, `cmp.sh` runs NCBI 2.17.0 and `LOSAT-before` on the same arguments and writes `<tag>.ncbi.*` / `<tag>.losat.*`; `rows_part*.py` + `addrows.py` produced the TSV). Evidence names in the TSV are file stems in that directory.

## 1. Call path followed (NCBI, bl2seq: `-query Q -subject S`)

1. Arguments (`blast_args.cpp`): `CGenericSearchArgs::SetArgumentDescriptions` (-word_size, CArg_Integer, constraint >= 2 for blastp, tblastn AND tblastx: tblastx_args.cpp:68 passes `!kQueryIsProtein` = true), `CWordThresholdArg` (-threshold, CArg_Double, constraint >= 0), `CWindowSizeArg` (-window_size, CArg_Integer, >= 0). Extraction order: `CGenericSearchArgs::ExtractAlgorithmOptions` (word size: `m_QueryIsProtein && ws > 4` sets compressed type and threshold 19.3 / 21.0 / 20.25, then `SetWordSize`), then `CWordThresholdArg` (explicit value, else `s_IsDefaultWordThreshold` -> `BLAST_GetSuggestedThreshold`: BLOSUM62 11, +2 for translated subjects = 13, +1 for translated queries), then `CWindowSizeArg` (explicit value, else `BLAST_GetSuggestedWindowSize`: 40 for BLOSUM62).
2. Task handles (`blast_options_handle.cpp`): blastp-fast = ws 5 + compressed + threshold 20 + chaining; blastp-short = ws 2 + PAM30 (+ window 15, threshold 16 through the suggestions); tblastn-fast = ws 5 + compressed + threshold 20. `CBlastOptionsLocal::SetWordSize` flips the lookup type by `ws > 4` (so a task's type never survives a user word size on the other side of 4; `s_IsDefaultWordThreshold` keeps the task's 20 because (int)20 != the program default).
3. `BLAST_ValidateOptions` (blast_options.c:1757-1799): extension, scoring (gap costs/matrix), **lookup** (`threshold <= 0` -> "Non-zero threshold required"; ws > 7 for blastp/tblastn -> "Word-size must be less than 8 ..."; any other protein program with ws > 4 -> "Word-size must be less than 6 for protein comparison" (this is tblastx)), initial word (x_dropoff only), hit saving, identity-matrix word-size rule.
4. `LookupTableWrapInit_MT` (lookup_wrap.c): `eAaLookupTable` -> `BlastAaLookupTableNew` (`threshold = (Int4)opt->threshold`), `BlastAaLookupIndexQuery` (`BlastLookupIndexQueryExactMatches` + `s_AddWordHits`/`s_AddWordHitsCore` neighbours), `BlastAaLookupFinalize` (small or thick backbone); `eCompressedAaLookupTable` -> `BlastCompressedAaLookupTableNew` (`threshold = (Int4)(100 * threshold)`, `SCompressedAlphabetNew` score matrix, `s_CompressedAddNeighboringWords`, `s_CompressedLookupFinalize`).
5. `BLAST_PreliminarySearchEngine` (blast_engine.c:1337+): translated subjects shorter than `word_length*3+2` nt are skipped before any statistics update; `BlastInitialWordParametersNew` (cutoffs do not depend on ws/threshold/window); `s_BlastSetUpAuxStructures` -> `BlastExtendWordNew` (diag array length = smallest power of 2 >= qlen + window, **Int4 arithmetic**; `multiple_hits = window > 0`); per subject / frame / chunk `BlastAaWordFinder` -> `s_BlastAaWordFinder_TwoHit` or `_OneHit` with the scan callbacks of `blast_aascan.c`, `s_BlastAaExtend*`, `Blast_ExtendWordExit`, `Blast_InitHitListSortByScore`.
6. Output: the outfmt 0 epilog prints `Neighboring words threshold: ` << **double** (omitted when 0.0) and `Window for multiple hits: ` << int (omitted when 0) (blast_format.cpp:2282-2289). outfmt 6/7 print neither.

## 2. Data and code the port needs

- Nothing new for Aa lookups of word size 2..4 in any program: `build_ncbi_lookup_for_profile(.., matrix, word_length)` (tblastx/lookup/backbone.rs:805) is generic and already runs TBLASTN word 2 (BLOSUM45). BLASTP calls the wrapper `build_ncbi_lookup` that fixes `LOOKUP_WORD_LENGTH = 3`; TBLASTX has the constant in four more places (run_impl `wordsize`, parser, min-subject check, `k_size` in `extend_hit_two_hit`).
- Compressed lookup (word 5, 6, 7): `tblastx/lookup/compressed.rs` is a complete port for BLOSUM62 (alphabets 15/15/10, index tables, scan, overflow cells). Only ws 5 has been compared with the oracle. TBLASTN needs the dispatch Aa/compressed in `scan_protein_words_by_chunk`.
- Matrix-dependent compressed matrix (`SCompressedAlphabetNew`): needs the eight frequency-ratio tables of `matrix_freq_ratios.c` (BLOSUM45/50/62/80/90, PAM30/70/250; 28x28 doubles each, lines 38-1640 of that file, plus the BLOSUM62_20/20A/20B scalings) and the first ungapped lambda of each matrix from `Blast_GetMatrixValues` (blast_stat.c). This belongs to the matrix session; ws >= 5 with a non-BLOSUM62 matrix needs it.
- One-hit word finders for TBLASTN and TBLASTX (window 0): model = BLASTP's one-hit branch (blast_engine.rs:4630-4745) and `blastp/extension.rs` `extend_one_hit` (generic in word size).
- Helper for the C cast `(Int4)double` (x86-64 gives INT_MIN outside the range): needed by the Aa threshold and the compressed `100*threshold`.

## 4. Surprises

1. `-threshold` is a real, but the lookup uses `(Int4)` truncation (Aa) or `(Int4)(100*thr)` (compressed: 11.5 and 11 differ for word size >= 5), while the footer prints the full double (19.3 for word size 5). LOSAT BLASTP prints the truncated integer ("19"): divergent for every `-word_size 5` outfmt 0 run (row 65).
2. TBLASTX accepts word sizes 2, 3, 4 (not only 3); 5 and above fail with the "less than 6 for protein comparison" text even for 6, 7, 8.
3. `-task blastp-fast -word_size 3` is valid in NCBI: the lookup type follows the word size (SetWordSize), the threshold stays 20. LOSAT's CLI only offers `-task blastp`; `resolve()` already models the tasks but gives 19.3 instead of 20 for the default fast task.
4. NCBI crash and hang cases found (all deterministic): `-matrix IDENTITY -word_size 5` segfaults (blastp and tblastn, exit 139); a compressed lookup with a very low threshold (blastp -word_size 5 -threshold 0.99) exhausts the 1024 overflow banks and corrupts the heap (abort 134 after partial output; LOSAT panics with an assert message instead); `-window_size` with query length + window in (2^30, 2^31-1] makes `s_BlastDiagTableNew` loop forever (shift passes INT_MIN and 0): NCBI and LOSAT BLASTP/TBLASTX both hang (killed by timeout; `hang_*` files); LOSAT TBLASTN would instead allocate with `usize` arithmetic (row 60).
5. `(Int4)` of a double beyond Int4 (threshold 1e10, `+inf`, which NCBI parses because `+` is an allowed first character, whereas `inf` is a conversion error) gives INT_MIN on x86-64: every word becomes a neighbour (36686 lines on the 40x40 set). LOSAT saturates.
6. The letter O is replaced by X by NCBI at sequence read time (blast_setup_cxx.cpp:885-925) with a stderr warning; LOSAT keeps O as its own letter, which changes BLASTP and TBLASTN output at word size 3 (row 73, found by the ambiguity-letter sweeps; belongs to the protein input range). Confirmed by running LOSAT on O->X substituted input: byte-identical to NCBI on the original input.
7. NCBI check order for lookup options: gap costs/matrix -> threshold -> word size -> evalue; an empty `-subject` file ("Empty CBlastQueryVector", exit 3) is reported before option errors, an empty `-query` after. LOSAT checks word size/threshold in clap value parsers (N, X) or at the very start (P), so combinations of errors give other messages (rows 17, 18).
8. Several values that NCBI accepts are refused by LOSAT's own parsers (hex `0x..`, `+inf`; TBLASTX threshold must be an integer): the shared helpers `ncbi_integer`/`ncbi_double`/`blastn_integer_at_least` in `blastinput/value_parsers.rs` already read them as NCBI and can be reused.
9. The three programs share the lookup/scan code (`tblastx/lookup/*`, `tblastx/blast_aascan.rs`) but each has its own word-finder copy: BLASTP (two-hit and one-hit, any word size and window, BLOSUM62 only), TBLASTN (two-hit only, any word size, gated to two profiles), TBLASTX (two-hit only, word size 3 hard-coded).

## 5. Decisions for the porting session

- Hang for huge windows (row 58/59/60): keep NCBI's infinite loop (reproduced today) or reject `-window_size` with `qlen + window > 2^30` through an explicit error. A web GUI should not accept a request that can never finish; the NCBI-defect policy (deterministic NCBI bug) points to reject with a message.
- Compressed-lookup bank exhaustion (row 42): NCBI's behaviour is heap corruption, not reproducible; propose an explicit rejection computed from the cell count (1024 x 209710 cells) instead of the current panic.
- `(Int4)` UB cast (rows 34, 41): reproduce the x86-64 result (INT_MIN) as proposed; note the UB.
- IDENTITY with compressed lookup (row 21): keep rejected (NCBI segfault).
- Whether to open `-task blastp-fast / blastp-short / tblastn-fast` (rows 24, 25) in this session or with the task/matrix sessions: the lookup parts are S/M, blastp-short needs PAM30 (matrix range).
- Suggested port order: (1) shared parsers + f64 threshold + footer + option-check stage with NCBI messages (rows 1-20, 34-36, 65-67); (2) BLASTP word sizes 2/4 and 6/7 by lifting the gate (rows 32, 40); (3) TBLASTX word size parametrisation and window 0 (rows 46, 52); (4) TBLASTN gate relaxation, one-hit and compressed (rows 33, 44, 51); (5) tasks (rows 24, 25); (6) O->X (row 73).
