- `tblastx` with two or more query batches puts each batch's HSPs in report order when the batch has been searched, while the next batch is searched, instead of ordering every batch's HSPs on one thread after the last batch (`LOSAT_X_TBXRPTBATCH`, one of the switches of the strict set, so reports do not change; `LOSAT_X_TBXRPTBATCH=0` turns it off). A `-db` search reads the titles of a batch's reported sequences from that list instead of ordering a copy. On the workstation three ~650 kb genomes against three (genetic code 4, three batches) took x0.995 of the time at 16 threads; the same queries against the three genomes cut into 18,838 pieces of 100 bp x0.992 with a peak memory of 209 MiB (300 MiB before), against one genome x0.990 with 242 MiB (267 MiB); searches of one query batch are unchanged.
