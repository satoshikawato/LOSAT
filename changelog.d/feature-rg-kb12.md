- A database sequence whose `pdb` id in the alignment NCBI BLAST+ 2.17.0's data loader looks up with another chain (a chain number outside -128 to 127 without a chain letter, or a chain letter other than the chain in an id whose lower-case letter or release date NCBI normalizes) gets NCBI's report of a sequence it cannot load: `Unknown` and `no longer exists in database...alignment skipped` in outfmt 0, without the sequence in outfmt 1 to 4, the `Hit` of NCBI's `catch` in BLAST XML, XML2 and JSON, the rows of a failed lookup in the tables and no row in outfmt 18. Where another definition line of the sequence holds the id that NCBI looks up, the description lines, the organism report and the heading of an untitled line show that line's title, as in NCBI. LOSAT refuses `sacc`, `saccver` and the default tabular fields of such a sequence (NCBI stops with a null pointer exception), `-show_gis` where its description line is printed (NCBI prints an uninitialised GI), and the formats that read it where no definition line holds that id (NCBI stops with `oid headers do not contain target gi/seq_id.`). With `-parse_deflines`, a database sequence with the id of a query of its batch is refused only in the formats in which NCBI looks it up by that id (outfmt 8, 9, 11 and 12 give NCBI's output), and a `-subject` record whose description id is longer than 65 bytes only where its description line is printed.
