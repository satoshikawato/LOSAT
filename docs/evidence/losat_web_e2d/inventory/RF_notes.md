# RF notes: results and output formatting with `-query_loc` / `-subject_loc` (NCBI BLAST+ 2.17.0, pinned 598d8ae6)

Files: `RF.tsv` (47 rows), this file, scratch inputs/outputs in `scratch_RF/` (`in/` inputs, `out/` oracle and LOSAT-before outputs with `.cmd/.out/.err/.rc`, `r.sh` runner, `cut.py`, `cmp6.py`/`cmpq.sh` comparison helpers, `gen*.py` input generators).

Method used for every claim: run the NCBI executable (`/home/kawato/micromamba/bin/{blastn,blastp,tblastn,tblastx}`, bl2seq form `-query Q -subject S`) once with the range and once on physically cut copies of the same records (`cut.py`, `*_cut.out` / `*c_*.out`). A column or line that differs between the two runs (after subtracting the shift) is range-dependent output logic. All inputs are synthetic (seeded, `gen.py`, `gen2.py`, `gen3.py`, `gen4.py`), a few hundred to ~1,300 letters.

## 1. Call path that was followed

Entry (all four apps are identical here): `blastn_app.cpp` 225-300, `blastp_app.cpp` 225-290, `tblastn_app.cpp`, `tblastx_app.cpp`:

1. `CBlastAppArgs` parse: `-query_loc` -> `m_Range = ParseSequenceRange(...)` (`blast_args.cpp` 1996-1999), `-subject_loc` -> `subj_range` (`blast_args.cpp` 2540-2545) passed to `ReadSequencesToBlast` (`blast_input_aux.cpp` 177ff). `ParseSequenceRange` (`blast_input_aux.cpp` 145-176): "start-stop", 1-based inclusive typed, stored 0-based inclusive (`from--, to--`).
2. `CBlastFormat formatter(...)` then `formatter.SetQueryRange(query_opts->GetRange())` (`*_app.cpp` lines 250/245/262/165): `m_QueryRange` is the TYPED range (0-based, inclusive, NOT clipped to the record, the same for every query record, empty when no `-query_loc`).
3. `-subject` creates `CLocalDbAdapter(subjects, opts, dbscan_mode=true)` (`blast_app_util.cpp` 205-210, `BL2SEQ_LEGACY` unset). Consequences: `CBlastFormat` has `m_IsBl2Seq=true` AND `m_IsDbScan=true` (`blast_format.cpp` 112-145): the output has the database prolog/epilog and the description table of a database search, no `Subject=` header; the result type is `eDatabaseSearch` (`local_blast.cpp` 288-292), so the Seq-aligns are built by `BlastHitList2SeqAlign_OMF` (`blast_seqalign.cpp` 1549-1651), NOT by the pairwise-comparison function (rows 15-16).
4. Query batches: `CBlastInput::GetNextSeqBatch` (`blast_input.cpp` 126-170) -> `CBlastFastaInputSource::GetNextSequence` -> `x_FastaToSeqLoc` (`blast_fasta_input.cpp` 433-460): Seq-loc `Int [from, (to>0 && to<seqlen) ? to : seqlen-1]` with the record's id. Errors: `to>0 && to<from` -> "Invalid sequence range"; `from>seqlen` -> "Invalid from coordinate (greater than sequence length)"; `to` past the end is clipped silently. For queries `GetNextSeqBatch` swallows `catch (const exception&) { continue; }` (see 4.6). For subjects `GetAllSeqs` lets the exception out.
5. `CLocalBlast::Run` -> prelim search -> `CBlastTracebackSearch::Run` -> `LocalBlastResults2SeqAlign(...)` (`blast_seqalign.cpp` 1987-2040) -> `s_BlastResults2SeqAlignDatabaseSearch_OMF` (1946-1985) -> per query `BlastHitList2SeqAlign_OMF`: `query_length = query.GetSeqLength(i)` (= interval length), `subj_length` from `GetSequenceLengthAndId` -> `CSeqVecSeqInfoSrc::GetLength` = `sequence::GetLength(Seq-loc)` (= interval length). `BLASTHspListToSeqAlign` / `BLASTUngappedHspListToSeqAlign` build the Seq-aligns on the INTERVAL (coordinates relative to the cut sequence; minus strand and minus frames computed from the interval length: `s_GetAlignmentStart` 114-145, `x_UngappedHSPToStdSeg` 1323-1381). Then `RemapToQueryLoc` (1520-1534: `OffsetRow(0, from)`) and `s_RemapToSubjectLoc` (1541-1547: `RemapAlignToLoc` = `CSeq_loc_Mapper` [0,len-1] -> subject Seq-loc) move the rows into RECORD coordinates (1634-1636).
6. Formatting works on the record: `CBlastFormat::PrintOneResultSet` (`blast_format.cpp` 1411-1590) and `x_PrintTabularReport` (759-835) fetch bioseqs from the scope (full records); `CDisplaySeqalign` / `CBlastTabularInfo::SetFields` read record coordinates and record lengths, except where `m_QueryRange` is used (`tabular.cpp` 787-788, 884-885; `InsertSubjectScores`).

## 2. Coordinate conventions at each step

| step | units / base | what it is relative to |
|---|---|---|
| typed `-query_loc a-b` | 1-based, inclusive; stored 0-based inclusive `[a-1, b-1]` | record; `m_QueryRange.GetLength() = b-a+1`, may exceed the record |
| Seq-loc of the search | 0-based inclusive `[a-1, min(b-1, len-1)]` | record; the "interval" |
| engine HSP offsets (`hsp->query.offset/end`) | 0-based, end exclusive; amino acids in translated frames | start of the interval (cut sequence) |
| Seq-align after `BLAST*HspListToSeqAlign` | 0-based inclusive; nucleotides for translated rows (3*offset+frame-1 ...); minus strand/frames from the interval length | interval |
| after `RemapToQueryLoc` / `s_RemapToSubjectLoc` | the same, plus from-1 on the respective row (both strands, any frame) | record |
| tabular qstart/qend/sstart/send | 1-based; minus strand = high end first; nt for translated rows, aa for protein rows | record |
| frames (tabular, outfmt 0 `Frame =`) | `GetFrame(start0, strand, bioseq)`: plus `(start0 % 3)+1`, minus `-(((RECORD_LEN - start0 - 1) % 3) + 1)`, `start0` = 0-based record coordinate of the HSP low end (plus) or high end (minus) | record, FULL bioseq length |

## 5. LOSAT side: what each program accepts today (LOSAT-before)

- All four reject `-query_loc` / `-subject_loc` ("error: the NCBI BLAST+ option -query_loc is not supported by LOSAT's <PROGRAM>", cli.rs `is_unported_*`).
- Custom `-outfmt` field lists: BLASTN, TBLASTN, TBLASTX reject any custom specification or delimiter ("a custom output format specification (fields or a delimiter) is not supported by LOSAT's TBLASTN" etc.): only outfmt 0, 6, 7 with the 12 default fields. BLASTP accepts `std` and: qseqid qacc qaccver qlen sseqid sacc saccver slen qstart qend sstart send qseq sseq evalue bitscore score length pident nident mismatch positive gapopen gaps ppos qframe sframe frames btop stitle; it rejects qgi sallseqid sgi sallgi sallacc staxid ssciname scomname sblastname sskingdom staxids sscinames scomnames sblastnames sskingdoms salltitles sstrand qcovs qcovhsp qcovus. So the range-dependent tabular fields that MUST be handled: BLASTP qlen (typed), slen (full, keep), qstart/qend/sstart/send (shift); all programs: the four coordinates of the default row. qframe/sframe/frames in BLASTP are always 1 (no change). NCBI range-dependent fields that no LOSAT program supports yet (rows say `rejected`): qcovs, qcovus, qcovhsp, sstrand, and the frames of translated programs.
- Outfmt 0 range-dependent items LOSAT must handle in every program: query/subject coordinates and number-column width, Database totals, translated `Frame =` labels (tblastn, tblastx), masks (query shift; subject filter for blastn; tblastx quirk), skipped queries. `Length=`, `# Query:`, search space and Lambda/K/H need no change if the full records stay available to the reporter.
- Where LOSAT produces each number today: BLASTN coordinates `algorithm/blastn/blast_engine/run.rs:950 adjust_blastn_offsets` (1-based; minus query via query_length) into `Hit` (`common.rs:96-99`), written by `algorithm/blastn/hsp.rs:1262-1270`; BLASTP `blastp_tabular_field_text` (`algorithm/blastp/blast_engine.rs:2383-2440`); TBLASTN `algorithm/tblastn/stage_e_report.rs:233-272, 458-476`; TBLASTX `algorithm/tblastx/extension/mod.rs:73 convert_coords` and `algorithm/tblastx/report.rs:423-483, 544-600`. Database totals: `algorithm/blastn/coordination.rs:849-868`, `algorithm/blastp/blast_engine.rs:5451`, `algorithm/tblastn/stage_e_report.rs:609-622`, `algorithm/tblastx/blast_engine/run_impl.rs:1358`.

## 6. Surprises / things the session must decide

1. **Design assumption of the status column:** the natural port cuts query/subject Records to the interval, searches them, and shifts at report time. Then the engine-facing lengths (rows 9-11) are already right, but the reporter needs three different lengths per record: the interval length (minus coordinates; Database totals), the full record length (`Length=`, `slen`, frame labels) and the typed range length (`qlen`, `qcovs`). Keep them as separate fields; do not reuse `subject.seq().len()` for all uses (today it feeds both the minus-frame arithmetic and `Length=` in `stage_e_report.rs` 244-252 and 560).
2. **Frame labels are record-relative.** tblastn/tblastx `Frame =` (and tabular qframe/sframe) are recomputed from record coordinates with the FULL record length, so they differ from the engine frames of the cut interval unless the shift is a multiple of 3 (and, for minus frames, the interval end is congruent to the record end mod 3). The translation itself is unaffected (codons come from the interval).
3. **tblastx single-HSP qcovhsp quirk** (row 12): without any range, a subject with exactly one HSP gets `qcovhsp = 100*nt_len/record_len`, others `aa_len/nt_len`; with a range the single-HSP case uses the TYPED length. Only relevant if LOSAT ever supports qcovhsp.
4. **Skipped queries** (row 42): an invalid range for a record makes the record vanish silently (not counted in `# BLAST processed N queries`); only when ALL queries vanish is there an error (exit 3). Subject range errors exit 1 before any output. These belong to QN/SB but the printed counts are RF-visible.
5. **UNSURE, tblastx query masks (row 37):** with `-query_loc` from>0 and `-seg yes` / `-lcase_masking` NCBI prints lowercase letters in the translated `Query` lines that a cut run (and a no-range run) does not (128 lowercase letters in `xm_segyeslcasemasking.out`; a stray single letter for particular `from` values in `mxs_*`). The Map step (`blast_aux.cpp` 826-841, 904-958) adds the interval start (nt) to per-frame masks. The exact byte behaviour has to be reproduced by porting the NCBI chain, not derived from a cut run; repro inputs `in/mxq.fa`, `in/mxs.fa`, `in/lxq.fa`, `in/lts.fa`. LOSAT already reproduces the no-range conversion (`query_dna_masks`, `lowercase_query_row`).
6. **Subject lowercase quirk** (row 38): with `-subject_loc` from>0 the subject mask filter compares interval-relative HSP ranges with record-relative masks, so lowercase letters at HSP edges can disappear (blastn; blastp the same but LOSAT rejects `-lcase_masking` for blastp).
7. `FillScanModeBlastDbInfo` receives `int` totals (`static_cast<int>(BlastSeqSrcGetTotLen(...))`, `blast_format.cpp` ~136): wrap-around only above 2^31 letters; not run.
8. Out-of-frame (`-frame_shift_penalty`) skips the subject remap in NCBI (row 15): not applicable while LOSAT lacks the option.
9. Not in RF (other ranges): range parsing, interval cutting, engine search spaces and effective lengths, `-strand`.
