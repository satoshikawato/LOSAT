# Range IN: TBLASTN nucleotide subject input

Files to write: `IN.tsv`, `IN_notes.md`. Scratch: `scratch_IN/`.

TBLASTN reads the subject (nucleotide FASTA) with `bio` only (`algorithm/tblastn/args.rs`), while TBLASTX reads nucleotide FASTA with the NCBI-like parts of `algorithm/blastn/input.rs` (`open_input`, `read_records`, `parse_fasta`, `check_deflines_of`, `check_residues_of`, `check_utf8_file_name`, title warnings, with the program name). Session S08's audit (c) F14 found TBLASTN silently misreads subject deflines: tab or control characters in the defline give a different outfmt 0 title (NCBI cuts at the first byte below 0x20), and an empty defline or one starting with a space gives a different outfmt 6 `sseqid` (NCBI uses `Subject_2` etc.). Inventory every CFastaReader behaviour for a nucleotide subject of tblastn (`src/objtools/readers/fasta.cpp`, `src/algo/blast/blastinput/blast_fasta_input.cpp`, `blast_input_aux.cpp`, `blast_args.cpp` subject reading in `CBlastDatabaseArgs::ExtractAlgorithmOptions`, `blast_setup_cxx.cpp` `SetupSubjects_OMF` including the lowercase intervals of `-lcase_masking` and ambiguous letters (`CRandom`?), `U`) and compare with LOSAT's TBLASTN and with what TBLASTX/BLASTN already do (S07+ AUTHORITY §E, §M, §N, §O; S08 AUTHORITY). Also: the outfmt 0 title of subjects (`CDeflineGenerator::GenerateDefline`, ported as `report/defline.rs` `ncbi_nucleotide_title`), including the titles made only of punctuation (approved exception 2, extended to TBLASTN: LOSAT should print the title cut at the end of the string as BLASTN does; today TBLASTN/TBLASTX reject it via `check_shown_subject_titles`/`ncbi_nucleotide_title_reads_past_end`), HTML character references in titles (`HtmlDecode`). One row per feature, with oracle runs.
