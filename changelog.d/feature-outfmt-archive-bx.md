- `-outfmt 11` (the BLAST archive, `Blast4-archive`) in `blastx`, with `-subject` and `-db`, as in `blastn` and `blastp`: one archive per query batch (the request with its nucleotide query and protein subject Bioseqs and its algorithm options, the Seq-aligns of outfmt 8, the masks of the six translated frames and the `LCaseMask` parameters of `-lcase_masking`, the Karlin-Altschul blocks and search statistics of the batch's first query, then the messages of the batch), the same bytes as NCBI BLAST+ 2.17.0's `-num_threads 1` run for every option LOSAT's `blastx` accepts, an error archive after the archives of the batches before when the run stops with NCBI's own error (a reader error in a later batch, a missing `-db`, `-subject` or `-query` file, composition-based statistics with `-ungapped`), `ARCHIVE_FORMAT` read as NCBI reads it (`xml` is refused for now). A query or subject title or a `-db` name with a byte outside `0x20..=0x7E` is refused before the first byte, as in `blastn`; with `-outfmt 11` the query file is read once more before the search for that check and must be a regular file. `blastx` now reads the environment variable `BATCH_SIZE` as NCBI does for every format (the letters of a query batch, 10002 when it is not set), so a batch size other than the default gives NCBI's batches in outfmt 0, 5-8, 11 and the others. `-culling_limit` is kept as given (`Option`), the value `blastx` searches with is unchanged. Other formats' bytes are unchanged.
