- `losat makeblastdb` writes its output files as makeblastdb 2.17.0 does: a file that cannot be created (a directory of its name that holds a directory that cannot be read) or written (a full device) no longer stops the build with `Error: <path>: ...` (exit status 255). The build goes on and ends as makeblastdb's: with `No alias or index file found ...` or `Could not find volume or alias file ...` (exit status 2) when an index file or the alias file is missing, normally when another file is, whose name the metadata file then leaves out. A volume file under its numbered name is renamed whatever it is, a link as the link. The totals of the metadata file count the volumes the new database resolves to (an alias file cut short names fewer). A metadata file (`.pjs`, `.njs`) that cannot be written gets makeblastdb's messages, `CObjectOStream: error at byte N` (exit status 0), or `BLAST failed to write output: COStreamBuffer::Flush: failed` (exit status 6) when its stream cannot be flushed. A duplicate id in the last sequence leaves the files makeblastdb leaves (the lookup files, a `.ptf` of 16 KiB, the volume's ISAM and OID to GI files under its numbered name); it left an 8 KiB `.ptf` only.
