- Compressed input: a `.gz` file (`makeblastdb -in`, and `-query` and `-subject`, which LOSAT reads by the same rule) is read as NCBI's makeblastdb reads it (`CZipDecompressor`): a member's trailer (CRC-32 and length) and header CRC are not checked, so a wrong CRC or length, or a trailer cut short, builds the database of the intact file, as makeblastdb 2.17.0 does, where LOSAT stopped with `is named .gz but is not gzip data (corrupt gzip stream does not have a matching checksum)`. Up to four zero bytes or a line feed after the last member are read as makeblastdb reads them (fewer than 4 KiB of bytes that inflate to nothing); a file that starts with a zlib stream instead of a gzip header is read up to that stream's end. A member's header must end within the next 4 KiB (a longer name or extra field now stops the build, as in makeblastdb), and a reserved header flag, other bytes after the last member and a deflate stream cut short still stop it with LOSAT's message.
