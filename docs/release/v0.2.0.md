# LOSAT v0.2.0 release record

Status: **in preparation; the candidate commit is not chosen yet.** v0.2.0 is cut from the head of
`dev`: everything merged before the candidate commit `C` is in the release (Owner, 2026-11-17). `C`
is the first head of `dev` after the items below on which the full
`platform-checks` run (`set=full`) and the `nightly` run are green. The runs on `C` are listed in the
[release test plan](v0.2.0_certification_plan.md); their results are written into this record when
they are done. Nothing is tagged, released, uploaded or submitted to Bioconda from this record:
publishing follows the Owner's GO.

The items v0.2.0 waited for, all merged: `rpstblastn` with composition-based statistics
(`-comp_based_stats` 1, 2 and 3, and the default 1), the end of the current WebAssembly speed work,
the WASI fixes found by running the release rows through the serial WASI command, and makeblastdb's
times and database date on native Windows in local time, as NCBI BLAST+ prints them (they were UTC).

## What's new since v0.1.0

- **More programs.** `psiblast` (iterations, `-in_pssm`, `-in_msa` with a Clustal, FASTA, PHYLIP, NEXUS, Sequin or MultAlin alignment, `-out_pssm`, `-out_ascii_pssm`), `rpsblast` and
  `rpstblastn` (composition-based statistics `-comp_based_stats` 0 to 3, default 1; every `-outfmt` NCBI's
  programs write, with NCBI BLAST+'s bytes, so `losat rpsblast -outfmt 11 | losat rpsbproc` runs without NCBI's programs), `rpsbproc` (the report
  of NCBI's `rpsbproc` 0.5.1), `blastdbcmd`, `dustmasker`, `segmasker`, `windowmasker` (counts files
  of a genome, `-mk_counts` and `-convert`, and masking with them, `-ustat`), `convert2blastmask`, with `makeblastdb -mask_data`, `makembindex` (the megablast index of a database or of FASTA input), `makeprofiledb` (the profile databases that `rpsblast` and `rpstblastn` search, such as CDD, built from PSSM files), and `blastdb_aliastool` (alias files that combine databases or keep a list of their sequences, and binary GI and sequence id lists); `tblastn` takes PSSM queries (`-in_pssm`) and genetic code 32.
- **Every output format of the five main search programs.** `blastn`, `blastp`, `blastx`, `tblastn` and
  `tblastx` write `-outfmt` 0 to 18 and 20 (17, SAM, in `blastn` only, as in NCBI BLAST+).
- **Compressed input.** FASTA files ending in `.gz`, `.bz2` or `.zst` are read directly, by the search
  programs and by `makeblastdb`; a query can also come from the standard input (`-query -`).
- **Faster, with less memory, than v0.1.0** (16 threads, commit `93ca2f652`):
  - `blastn`, 31,168 cDNAs against chromosome 2L of *D. melanogaster*: 212.38 s and 3,858 MiB with v0.1.0,
    4.67 s and 76.7 MiB now (45.5 times faster, 2.0% (1/50.3) of v0.1.0's memory).
  - `megablast`, 16S rRNA genes: 57.66 s and 2,031 MiB, now 4.20 s and 62.0 MiB (13.7 times faster, 3.1%
    (1/32.8) of v0.1.0's memory).
  - `tblastx`, three *Candidatus* genomes against each other: 188.02 s and 1,605 MiB, now 4.72 s and 567.5
    MiB (39.8 times faster, 35% (1/2.8) of v0.1.0's memory). NCBI BLAST+ 2.17.0 took 2,970.75 s with 16
    threads (`-db` on a database of the same genomes).
- **Large databases with little memory** (16 threads, file cache warm): `core_nt` (319.4 GB, 132.3 million
  sequences) took 391.74 s with a peak resident memory of 407 MiB (LOSAT `095ff0c16`, an earlier development
  build); NCBI BLAST+ took 542.14 s and 263,594 MiB, a figure that includes the database files it maps into
  memory.
  `ref_prok_rep_genomes` (26.8 GB): 29.37 s and 358 MiB; NCBI BLAST+ 47.28 s and 25,580 MiB.
- **Published pipelines run unchanged** under the NCBI names (`losat --install-shims`), and their BLAST
  steps write the same output (where NCBI BLAST+'s own output changes with the thread count, as in BUSCO and
  QIIME 2, the same as its 1-thread output): [benchmarks/v0.2.0](../../benchmarks/v0.2.0/README.md) lists the tools and
  times.
- **WebAssembly writes the same numbers as native.** LOSAT computes `exp`, `log`, `log10` and `pow` with the
  same bits on every platform, so on WASI and in the browser the full-precision E values (`-outfmt 11` and
  `8`) and psiblast's PSSM files are those of native LOSAT and NCBI BLAST+. macOS keeps one difference: the
  last digit of a full-precision E value can differ by 1
  ([PD-LOSAT-PLATFORM-LIBM](../product_decisions/PD-LOSAT-PLATFORM-LIBM.md)).
- **Messages in LOSAT's words.** LOSAT's messages point to the LOSAT user manual instead of NCBI's BLAST+
  manual, and errors that NCBI reports as C++ exceptions show only their message, without NCBI's build
  paths, class names and function names (`(m_Pos = N)` reads `(position N)`); the error prefixes name LOSAT (`LOSAT query/options error:`, `LOSAT engine error:`,
  `LOSAT database error:`, `LOSAT database creation error:`, `LOSAT options error:`, `LOSAT query error:`),
  while the text after the prefix, NCBI's diagnostic codes and exit statuses stay as NCBI BLAST+ writes them.
- **Where to get it.** The release files below, [Bioconda](https://anaconda.org/bioconda/losat)
  (`conda install -c bioconda -c conda-forge losat`) and [crates.io](https://crates.io/crates/losat)
  (`cargo install --locked losat`). The Rust library is the same crate (`cargo add losat`), and the Python
  package is [`pylosat` on PyPI](https://pypi.org/project/pylosat/) (`pip install pylosat`). The npm package
  `losat` for web pages is built from this repository.
- **Upgrading from v0.1.0:** one program, `losat`, with the NCBI program names as subcommands or as links
  (`--install-shims`), and options LOSAT does not support are refused instead of ignored. See
  [Upgrading from LOSAT v0.1](../manual/src/from-losat-v0-1.md) and the
  [user manual](../manual/src/introduction.md).

## What v0.2.0 provides

One executable, `losat`, with NCBI BLAST+ 2.17.0's command lines (`losat blastn ...`, or `blastn ...`
through the links of `losat --install-shims`):

| Kind | Programs |
| --- | --- |
| Search | `blastn` (`megablast`, `blastn`, `dc-megablast`, `blastn-short`), `blastp` (`blastp`, `blastp-fast`, `blastp-short`), `blastx` (`blastx`, `blastx-fast`), `tblastn` (`tblastn`, `tblastn-fast`, PSSM queries with `-in_pssm`), `tblastx`, `psiblast`, `rpsblast`, `rpstblastn` |
| Databases and masks | `makeblastdb`, `blastdbcmd`, `dustmasker`, `segmasker`, `windowmasker` (`-mk_counts`, `-convert`, `-ustat`), `convert2blastmask`, `makembindex`, `makeprofiledb` (`-dbtype rps`), `blastdb_aliastool` |
| Domain annotation | `rpsbproc` |

The search programs read BLAST databases (`-db`) and, except `rpsblast` and `rpstblastn` (as in
NCBI), FASTA subjects (`-subject`); each can read its query from the standard input (`-query -`).
The options, output formats and the cases LOSAT refuses are listed per program in the
[user manual](../manual/src/introduction.md): [Differences from NCBI BLAST+](../manual/src/differences.md)
and [What LOSAT refuses](../manual/src/refusals.md).

## Differences from NCBI BLAST+ 2.17.0 that ship with v0.2.0

Each difference has a product decision:

- [PD-TBLASTX-LOCAL-SUBJECT-GENCODE](../product_decisions/PD-TBLASTX-LOCAL-SUBJECT-GENCODE.md) and
  [PD-TLOSAN-LOCAL-GENCODE-32](../product_decisions/PD-TLOSAN-LOCAL-GENCODE-32.md): a local
  `-subject` search of `tblastx` and `tblastn` translates the subject with the code `-db_gencode`
  selects, where NCBI's local search uses code 1; `tblastn` also accepts genetic code 32.
- [PD-LOSAT-PLATFORM-LIBM](../product_decisions/PD-LOSAT-PLATFORM-LIBM.md): on macOS, the last
  (15th) digit of a full-precision E value (`-outfmt 11`, `-outfmt 8`) can differ by 1. WASI is no
  longer named (1.2, Owner 2026-11-20): with LOSAT's `exp`, `log`, `log10` and `pow` giving the bits
  of glibc 2.35's FMA versions on every target (the code of Arm Optimized Routines, MIT, and Sun's
  fdlibm for `log10`; #1344), set G compares every psiblast `-db` row on both WASI commands byte for
  byte, with no rule.
- [PD-NCBI-PLATFORM-VARIANCE](../product_decisions/PD-NCBI-PLATFORM-VARIANCE.md): in the six
  cases run with NCBI on Windows, macOS and Linux aarch64, NCBI's builds for those platforms may
  differ from its Linux x64 build within the bounds recorded there; LOSAT's output is checked against
  the Linux x64 bytes on every platform.
- [PD-LOSAT-NCBI-DEFECTS](../product_decisions/PD-LOSAT-NCBI-DEFECTS.md): where NCBI's result
  depends on undefined behaviour (a signed overflow, a read outside its buffers), LOSAT computes the
  value without it or refuses the input; each case is listed there.
- [PD-LOSAT-CLI-NONSEARCH-DIFFERENCES](../product_decisions/PD-LOSAT-CLI-NONSEARCH-DIFFERENCES.md),
  [PD-LOSAT-DATABASE-SEARCH](../product_decisions/PD-LOSAT-DATABASE-SEARCH.md),
  [PD-LOSAT-BLASTDBCMD-DEVIATIONS](../product_decisions/PD-LOSAT-BLASTDBCMD-DEVIATIONS.md) and
  [PD-LOSAT-ARCHIVE-DEFLINE](../product_decisions/PD-LOSAT-ARCHIVE-DEFLINE.md).

The `LOSAT_X_*` variables, `LOSAT_TIMING`, `LOSAT_X_STATS`, `LOSAT_X_REACH` and
`--features diagnostics` are development settings outside the release's claims.

## Not in v0.2.0

- On the list for a later release (Owner, 2026-11-17): `deltablast`,
  `psiblast -phi_pattern`, the `psiblast` output formats `1` to `4`, `12` to `16` and `18` (and
  the `tblastn -in_pssm` ones `12` to `16` and `18`), `blast_formatter`, and `-html` in `psiblast`.
- `makeprofiledb -binary` (PSSM files in ASN.1 binary) and `-dbtype delta` or `cobalt`, which
  `losat makeprofiledb` refuses.
- Programs not provided: `blastdb_aliastool`, `blast_formatter_vdb`, `blast_vdb_cmd`, `blastn_vdb`,
  `tblastn_vdb`, `blastdbcheck`, `legacy_blast.pl`, `update_blastdb.pl`,
  `get_species_taxids.sh`, `cleanup-blastdb-volumes.py`.
- Options that need NCBI's servers or its GI and IPG databases: `-remote` and `-entrez_query` (all
  programs), `-gilist` and `-negative_gilist`, `-ipglist` and `-negative_ipglist`;
  `-import_search_strategy` is refused.
