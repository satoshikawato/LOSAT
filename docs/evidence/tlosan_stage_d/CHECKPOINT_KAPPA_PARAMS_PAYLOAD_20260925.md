## Function, state, and result ownership

- Pinned `blast_kappa.c:2352-2384,2418-2479,3099-3110`, `blast_parameters.c:457-463`, and `blast_stat.c:2833-2852` define Kappa's scale, gap penalties, option-dependent x-drop, first-valid-context near-identical cutoff, initial hit cutoff, and ideal score-block matrix initialization. `stage_d_kappa_params.rs` now calculates these from Rust setup values. The focused hard-SEG, code-32, multi-query, 13-subject, and 112-subject tests pass those calculated values to Rust redo and compare gap cost, x-drop, cutoff, Lambda, and where recorded ideal matrix Lambda against retained NCBI calls. The 112-subject test no longer reads those redo parameter values from the trace as inputs.
- The independent auditor found that the first implementation used minimum Lambda for the near-identical cutoff, while NCBI uses the first valid context (`blast_kappa.c:2439-2448`). It also fixed 15/25-bit x-drop within the helper. Both were corrected: valid-context state and the final x-drop option plus previously computed extension cutoff are explicit inputs. Source-boundary tests exercise differing context Lambda values and non-default preliminary/final x-drop bits. BLOSUM62 is the only ported composition matrix; the builder rejects other matrices explicitly before ideal-Lambda calculation.
- Pinned `blast_kappa.c:305-358,3687-3713` transfers the edit-script pointer from each distinct alignment into its HSP, then normalizes the score and calculates identity before heap insertion. Rust linking now retains an input index for the corresponding HSP value. In the natural 112-subject comparison, retained HSPs carry Rust-computed bit score, identity, edit script, and matrix-adjustment rule through composition heap pop, all ten `Blast_HitListUpdate` calls, list replacement, HSP sorting, and result reversal. The 13-subject natural chain carries the same fields for its single-HSP lists. For the 112-subject fixture, every retained hitlist update compares bit-score bits and identities to `K_TRACE_HEAP_HSP`; final OIDs 10 and 11 compare edit-script operations byte-for-byte to `K_TRACE_EDIT 1` and `0`. The two-HSP OID 5 remains covered through postredo, heap insertion, hitlist update, and payload retention until it is removed by the two-target limit.
