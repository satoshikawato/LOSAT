3. **検索画面**（W3）を寄せる：節の順と見出し（「Enter Query Sequence」「Enter Subject Sequence」「Program Selection」、検索のボタンとその近く、開閉する「Algorithm parameters」と下位の節）、欄の名前と並び、BLASTN の task の選び方。検索のボタンの言葉は NCBI に寄せつつ、ローカルで実行することとキューに積むことが分かるようにする。下調べで分かっていること：
   - NCBI は「Align two or more sequences」に印を付けると「Enter Subject Sequence」を出し「Choose Search Set」を隠す。LOSAT は常に subject を与える検索なので、この形を常に取る（印は置かない）。query と subject のそれぞれに「Query subrange」「Subject subrange」（From / To）と「Or, upload file」があり、LOSAT の領域（`-query_loc` / `-subject_loc`）とファイルの選択がこれに当たる。レコード一覧と除外、Combined / Separate は LOSAT だけのもので、各ブロックの中か直下に置く。
   - 「Program Selection」：BLASTN は「Optimize for」の radio（Highly similar sequences (megablast)、More dissimilar sequences (discontiguous megablast)、Somewhat similar sequences (blastn)）。LOSAT の task（blastn-short を含む）をこの形で選べるようにする。NCBI の 2 配列の画面の既定は blastn だが、LOSAT の既定は CLI と同じ megablast のまま（出力を CLI と比べるため）。違いは対応表に書く。
   - 検索のボタンの後に、選んだ program と task を言う一文（NCBI の「Search using Megablast (Optimize for highly similar sequences)」に当たる）。
   - 「Algorithm parameters」は開閉する節にし、「General Parameters」（Max target sequences、Expect threshold、Word size、Max matches in a query range）、「Scoring Parameters」（Match/Mismatch Scores、Matrix、Gap Costs、Compositional adjustments）、「Filters and Masking」（Low complexity regions filter、Mask for lookup table only、Mask lower case letters）、「Discontiguous Word Options」（Template length、Template type）の下位の節に、LOSAT の欄を NCBI の名前で並べる。NCBI の select の選択肢（Word size、Match/Mismatch、Gap Costs など）を写すかは、`describe` とエンジンの検査を正とし（TS で検証の規則を作らない、W3 の判断 3・9）、対応表で決める。既定と違う値の印（NCBI は黄色と ♦）と「Restore default search parameters」に当たるものを置く。
   - 「Job Title」：LOSAT に無い。Run の名前として採るかを対応表で決める（採るなら RunSnapshot に持ち、argv には入れない）。
   - program のタブ：NCBI は小文字の「blastn | blastp | blastx | tblastn | tblastx」。DW-21（BLASTN 系の表示名）は変えない。
4. **結果画面**（W4）を寄せる：上部の要約（NCBI の結果の見出しの塊に当たる Run の情報）、「Results for」に当たる query の選択（10 万 query の仮想化を保つ）、タブ（Descriptions・Graphic Summary・Alignments・Dot Plot、それに LOSAT の Run details・Outputs）、Descriptions の表（NCBI の列の並び。E2j の前は今の Score (bits)・E value をその位置に置き、列名は今の意味のまま）、Graphic Summary（新しい表示：query の軸に HSP を bit score の階級の色で並べる。階級の境界は NCBI の凡例のとおり。表示の分類であって BLAST の値の計算ではない）、Alignments（subject ごとに outfmt 0 の節を原文のまま、`Range n` の並びと前後の移動）、Filter Results に当たる表示用のフィルター（ViewState の規則は変えない）。下調べで分かっていること：
   - 要約：NCBI の 2 配列の結果は Job Title、RID、Program、Query ID、Query Descr、Query Length、Subject ID、Subject Descr、Subject Length、それに「Search Summary」（Search Parameters の表）、「Edit Search」、「Download All」。LOSAT では Run の番号、program、入力名、`Options:`、検証バッジ、Run details、Outputs と書き出しがこれに当たる。「Edit Search」（Run の設定を検索画面に戻す）を採るかは対応表で決める。
   - 「Results for」：複数 query の select。LOSAT の Query の選択（ID での絞り込み、With hits only）をこの位置と名前に寄せる。
   - Descriptions：見出し「Sequences producing significant alignments」、列は NCBI の並び（Description、Max Score、Total Score、Query Cover、E value、Per. Ident、Acc. Len、Accession。Scientific Name・Common Name・Taxid は LOSAT に無い）。並べ替えは Accession 以外の列、既定は E value の順（LOSAT はエンジンの順が既定。変えるかは対応表で決める）。E2j の前は、今の Score (bits)・E value（その subject の最初の HSP）と HSPs をその位置に置き、列名は今の意味のまま（Max Score と名乗らない）。S13+（E2j）が先に `feature/losat-web-gui` に merge されていれば、その指示書の 6.（アプリへの申し送り）をこの段階で行う：エンジンの渡す Max Score・Total Score・Query Cover・Per. Ident・表形式の E value を NCBI の並びで出し、鎖の欄で BLASTN の 1 文字の HSP の向きを示す（S14 はそれを前提にする）。
   - Graphic Summary：「Alignment Scores」の凡例（< 40 黒、40 - 50 青、50 - 80 緑、80 - 200 マゼンタ、>= 200 赤。NCBI の CSS の値は下調べの文書）、query の棒と目盛り、HSP ごとの細い棒、hover で subject と Score・Evalue、click でその HSP の Alignments へ。この凡例の階級と色は BLAST の利用者が読み慣れた機能上の約束なので写してよい（ブランドではない）。値は HSP レコードの bit score と座標。
   - Alignments：subject ごとの塊（題、Sequence ID、Length、Number of Matches、`Range n: a to b`、Next Match / Previous Match、Score・Expect・Identities・Gaps・Strand の行、Query / Sbjct の等幅の段）。LOSAT は outfmt 0 の節を原文のまま示す（その中に Score・Expect・Identities・Gaps・Strand / Frame の行がある）。`Range n` の座標は HSP レコードの値。「Alignment view」の他の形（Query-anchored など）はエンジンが出さないので採らない。
   - Dot Plot：タブの名前と位置は NCBI に寄せ、図の描き方は保守者の [`blast2dotplot.py`](https://github.com/satoshikawato/bio_small_scripts/blob/main/blast2dotplot.py)（保守者の指示、2026-10-09。版は commit `3b55d116`、2023-12-25、ファイルの sha256 `4f0731f7…`）を参考にする。保守者の言葉は「もしできたら参考に」と「もっと洗練されて軽快に動いてクリックしてポップアップするようなのができるならそれはそれでいい」（同日）。スクリプトは見た目の出発点（軸、目盛り、格子、色、不透明度、同じ縮尺）で、NCBI の Dot Plot と違うところはスクリプトを先にする。そのうえで、より洗練され軽快に動くものにしてよい。目標：HSP をクリック（またはキーボードで選ぶ）すると、その HSP のポップアップ（outfmt 6 の行の値をそのまま：bit score、E value、identity、query と subject の範囲、frame、向き、outfmt 0 に有るか。「Show alignment」で Alignments のその節へ）が出る。hover で線を強調する。ズームとパンは S13 の計測（5,993 HSP で拡大・縮小・移動 55〜89 ms、出すのに 86〜179 ms、Chromium と Firefox。W4 のゲート記録の「実測」）より速く、6,000 HSP でも滑らかに動く（`results-measure.spec.ts` で測る）。ポップアップは Escape で閉じ、キーボードとスクリーンリーダーで届く。スクリプトの描き方：
     - X 軸が query、Y 軸が subject。原点は左上で、subject の座標は下へ増える。両軸は同じ縮尺（1 文字あたりの長さが同じ）で、図の縦横は配列の長さの比（長い方を 1000 px）。軸の目盛りとラベルは上と左、query の題は上、subject の題は左に 90° 回して置く。
     - 目盛りは長さで決める大小の刻み（`tick_size`：1 kbp 以下は 100 / 10、5 kbp 以下は 500 / 100、10 kbp 以下は 1000 / 500、20 kbp 以下は 2000 / 1000、50 kbp 以下は 5000 / 1000、100 kbp 以下は 10000 / 1000、1 Mbp 以下は 50000 / 10000、5 Mbp 以下は 1 M / 200 k、それより上は 1 M / 500 k）。ラベルは大きい刻みだけで、長さが 5000 未満なら bp、1 Mbp 未満なら kbp、それ以上なら Mbp（`base_to_kbp`）。大小の刻みに薄い灰色（`#D3D3D3`）の格子、図の周りに黒い枠。
     - HSP は幅 2 の線（query の start から end、subject の start から end）。両方の frame の符号が同じなら青（`#1f77b4`）、違えばオレンジ（`#ff7f0e`）。identity で不透明度を分ける（60 以下 0.4、70 以下 0.6、80 以下 0.8、それより上 1）。
     LOSAT への写し方：
     - identity は outfmt 6 の `pident` の文字列を数として読み、階級に分けるだけにする（TS で identities / 長さを計算しない。`results_columns.md` のとおり、レコードに原値は無い）。階級の境界の扱い（スクリプトは `int()` で切り捨てる）は対応表で決める。
     - BLASTN の 1 文字の HSP（鎖がレコードに無い、W4 の判断 2）は今の灰色と凡例を保つ。BLASTP・TBLASTN の aa の軸（スクリプトは BLASTN と TBLASTX だけ）は、単位を aa にした同じ刻みにする。
     - LOSAT のドットプロットの操作（ズーム、パン、HSP の選択、n / p、Zoom to HSP、凡例、Ctrl / ⌘ のホイール、`touch-action`。W4 の判断 18）は保つ。ズームした範囲の目盛りは見えている長さで刻みを選び直す。長さの比が大きく短い辺が細くなりすぎるときの最小の幅は対応表で決める。
     - 図を SVG で書き出す（スクリプトの出力）は、この段階で足すか S15（出力）に回すかを対応表で決める。
     - 軽快さのための描き方（Canvas の層を分ける、ズーム中は間引く、OffscreenCanvas など）は実装で選び、計測で確かめる。図の形（軸と色の約束）をスクリプトから大きく変えるときは、対応表に理由を書く。
   - Taxonomy・Related Information・GenBank / Graphics のリンクは採らない（ローカルの FASTA に無い）。
5. **見た目**：表の密度、字の大きさ、節の見出し、リンク、開閉の印を NCBI に寄せる。色は LOSAT の配色のまま（ブランドを写さない。Graphic Summary の凡例とドットプロットの色は上の 4. のとおり）。S13 の基準は保つ：1280 px で表が切れない、390 px で横に流れない、触れる対象は 24 px 以上、コントラスト、キーボード操作（W4 の判断 16〜23）。

## S13（W4）から引き継ぐこと

[W4 のゲート記録](../evidence/losat_web_w4/README.md)の要点：

- **結果画面の構成**：`src/application/results.ts` の `ResultsBrowser` が選択（run、query、subject、HSP。中心は HSP の ID）、表示用のフィルター、並べ替え、詳細と見出しの読み取りを持つ。画面は `src/ui/` の `ResultsPanel`・`QueryPicker`・`SubjectTable`・`HspTable`・`HspDetail`・`DotPlot`・`ResultFilters`・`ResultNotices`・`RunDetails`・`VerificationBadge`・`OutputsView`・`VirtualRows`。寄せるのは画面の層で、`ResultsBrowser` の規則（判断 9〜13：並べ替えは先頭を見せる、隠れた選択を残さない、別の Run はフィルター無し、Subject 一覧は示す値で並べる、読めなかった Run は一度だけ読む）は保つ。

- **画面の基準**（W4 の判断 16〜21）：1280 px で表が枠に収まる（列は `ch` で値に合わせる、見出しは 2 行まで、数の見出しは右寄せ）、390 px で横に流れない（WebKit の select の label を切る）、電話では大事な列を先に並べて横に流れるときだけ知らせる、ドットプロットのホイールは Ctrl / ⌘ のとき、`touch-action: pan-y`、日付は ISO 8601、触れる対象は 24 px 以上。E2E がこれを測る（`results.spec.ts`）。切れて示す値が 2 種類ある（7 桁の HSP のアラインメントの長さ、Orientation の「Not in the record」）。
- **試験と計測**：`tests/e2e/support/search.ts` の補助、`results.spec.ts`（4 program、FakeEngine とエンジン入り、3 ブラウザ）、`screens.spec.ts`（状態 01〜18）、`results-measure.spec.ts`（10 万 query と繰り返しの配列のドットプロット。時計の意味は W4 の判断 14）、`hsp-correspondence.test.ts`。ゲートの script は `LOSAT_WEB_GATE_STEPS` に `all`・`after-review`・`measure` がある。
- **FakeEngine**：検索の形の出力（200 query まで、3 subject まで、3 つ目は outfmt 0 に無い、逆向きの HSP、BLASTN の 1 文字の HSP）。値は `FAKE`。NCBI の参照画面と比べる画面の記録はエンジン入りのビルドで撮る。
- **W4 の画面レビューの 2 回目から回したもの**（W4 の判断 23。この段階で表・キュー・ドットプロットを作り直すときに直す）：Firefox の電話で行のクリックの後に表が横に流れる（Playwright か Firefox のフォーカスの scroll か決まっていない。実際の Firefox for Android の tap で確かめ、流れるなら `focus({ preventScroll: true })` などで止める）、電話の HSP 一覧が subject の範囲の途中で切れて Frames が見えない、キューのカードの折り返しが 3 通りで結果タブではキューの位置が動く、ドットプロットの電話の説明が mouse の操作だけ（拡大した図は指では横にしか動かせない）、x 軸の端のラベルが枠に触れる、TBLASTN・BLASTX（aa と nt の軸）のドットプロットの記録が無い。
- **残件**：エンジンのメモリ不足（20 nt の単位の 4000 写しの自己検索）、WebKit の 512 MB の保存の上限、`runInputs` の解放、iOS Safari での確認（V-MOB、S17）。
