# NCBI unit-test case ledger

This folder counts how many NCBI BLAST+ unit-test cases LOSAT has ported as its own Rust tests.
NCBI checks one behavior per Boost.Test case (for example `testHSPListSort` in
`c++/src/algo/blast/unit_tests/api/blasthits_unit_test.cpp`). LOSAT ports such a case as a test
next to the implementation, so the ledger turns "reference NCBI unit tests when available"
(AGENTS.md, Testing Expectations) into numbers that CI keeps honest.

| File | Kept by | Content |
| --- | --- | --- |
| `NCBI_CASES.tsv` | generated by `extract` | every case of the NCBI unit tests in scope, at the pinned NCBI commit |
| `LEDGER.tsv` | hand | the LOSAT status of each case |
| `README.md` | hand | this description |

The tool is `LOSAT/tests/ncbi_unit_case_ledger.py` (tests: `LOSAT/tests/test_ncbi_unit_case_ledger.py`).

```bash
python3 LOSAT/tests/ncbi_unit_case_ledger.py check --root .    # what CI runs
python3 LOSAT/tests/ncbi_unit_case_ledger.py report --root .   # table per NCBI module, for gate records
python3 LOSAT/tests/ncbi_unit_case_ledger.py scan --root .     # citation lines and the test under each
```

## Scope

`NCBI_CASES.tsv` lists the cases of these NCBI sources (paths under `c++/src/`):

- `algo/blast/unit_tests/api/<m>_unit_test.cpp` for aalookup, aascan, blast, blastdiag,
  blastengine, blastextend, blastfilter, blasthits, blastoptions, blastsetup, gapinfo,
  gencode_singleton, hspfilter_besthit, hspfilter_culling, hspstream, linkhsp, ntlookup, ntscan,
  nuclwordfinder, optionshandle, querydata, queryinfo, redoalignment, scoreblk, split_query, stat,
  subj_ranges, traceback, tracebacksearch, bl2seq. Each file is one module, named as in the list.
- `algo/blast/unit_tests/blast_format/*.cpp` (module `blast_format`),
  `algo/blast/unit_tests/blast_mt/*.cpp` (`blast_mt`),
  `algo/blast/blastinput/unit_test/blastinput_unit_test.cpp` (`blastinput`),
  `objtools/align_format/unit_test/*.cpp` (`align_format`).

PSI-BLAST, PSSM, RPS, PHI, delta, magicblast, rmblast, remote BLAST, SeqDB and BLAST database tests
are out of scope.

## Columns

`NCBI_CASES.tsv`: `module  file  case  line_start  line_end  kind  note`

- `file`: path from the NCBI repository root, as written in a citation.
- `line_start`, `line_end`: the `BOOST_*_TEST_CASE(` line and the line of the closing brace.
- `kind`: `AUTO` (`BOOST_AUTO_TEST_CASE`), `FIXTURE` (`BOOST_FIXTURE_TEST_CASE`), `DISABLED`
  (inside `#if 0` or `#if SEQLOC_MIX_QUERY_OK`, which NCBI never compiles), or `MACRO`.
  `BOOST_AUTO_TEST_CASE_TIMEOUT` lines only set a timeout and are not cases.
- `MACRO`: a `#define` whose body declares a case, counted once as written. ntscan's
  `DECLARE_TEST` (lines 846-905) is one row named after the macro, from the `#define` to its last
  invocation; its 44 invocations (`DECLARE_TEST(Tiny, TINY_GI, 0, 0, 4)` declares
  `TinyScanOffsetSize4`, ...) are not rows of their own.
- `note`: for a `MACRO` row, how many cases the macro declares at run time and where; empty
  otherwise.
- The `# ncbi_commit` line names the NCBI commit the file was generated from.

`LEDGER.tsv`: `module  case  status  losat_test  note  since`

- `module`, `case`: a row of `NCBI_CASES.tsv`. At most one row per case. A case without a row is
  "unlisted" in `report`.
- `status`: one of the statuses below.
- `losat_test`: the LOSAT tests that check the case, separated by `;`. A Rust test is written
  `LOSAT/src/<path>.rs::<fn>` (or `LOSAT/tests/<path>.rs::<fn>`) and must be a `#[test]` function in
  that file that is not `#[ignore]`d. A fixture is a file path from the repository root (not a
  `.rs` file), optionally followed by `#<id>`, a string that must occur in the file. Only a Rust
  test or a citation links a `ported` or `partial` row; a fixture alone is `e2e` coverage.
- `note`: why the status holds - the reason for `n-a` and `superseded`, the fixture or evidence for
  `e2e`, the LOSAT function to test for `to-port`, what is missing for `partial`.
- `since`: the date (YYYY-MM-DD) the status was last set.

## Statuses

| Status | Meaning | Fill in |
| --- | --- | --- |
| `ported` | a LOSAT test makes the same assertions as the NCBI case | a citation line or a `path::fn` test |
| `partial` | a LOSAT test exercises the case but asserts less | a citation line, a `path::fn` test, or the evidence in `note` |
| `e2e` | only fixtures, frozen hashes or oracle comparisons cover it | the fixture in `losat_test` or `note` |
| `to-port` | LOSAT has ported the function, but no test checks this case | the LOSAT function in `note` |
| `n-a` | LOSAT has no such feature (object manager, GenBank, `-db`, PSI/RPS/PHI, ...) or NCBI compiles the case out | the reason in `note` |
| `superseded` | another LOSAT test or fixture checks more than the NCBI case | the reason in `note` |

## Adding a row (porting a case)

1. Port the case as a Rust test in the module that owns the ported function: its
   `#[cfg(test)] mod tests`, or a sibling `<name>_tests.rs` declared with
   `#[cfg(test)] mod <name>_tests;` when the tests pass about 1,000 lines or carry fixture tables.
   Do this inside the parity sweep of that module (AGENTS.md rule 10), not as a separate campaign.
2. Put the citation directly above the test function (comment and attribute lines may sit between):

   ```rust
   // NCBI unit test (598d8ae6): c++/src/algo/blast/unit_tests/api/blasthits_unit_test.cpp:1094-1099 testHSPListSort
   #[test]
   fn hsp_list_sort_matches_ncbi() { ... }
   ```

   One line per case: the commit, the file, the cited lines (inside the case; `a-b`, or several
   ranges joined by `,`), and the case name. The usual `NCBI reference` snippet may follow it.
   Lines that start with `NCBI reference` are not citations of a ported case. For a `MACRO` case,
   cite the macro body and the invocation you port, and name the runtime case in the test name
   (`ntscan_unit_test.cpp:847-853,855 DECLARE_TEST` above `fn tiny_scan_offset_size_4`); the row
   becomes `ported` only when the tests cover every invocation.
3. Set the case's row to `ported` or `partial`, name the test in `losat_test`, and set `since`.
4. Run `check`, and paste `report` into the gate record of the stage.

A failing ported case is a LOSAT difference: do not commit the failing test. Record the input, the
NCBI expectation and LOSAT's result in the gate record and in the row's `note`.

## Regenerating `NCBI_CASES.tsv`

Only when the pinned NCBI commit changes or the scope above changes:

```bash
python3 LOSAT/tests/ncbi_unit_case_ledger.py extract --ncbi-src "$NCBI_SRC" \
  --out docs/evidence/ncbi_unit_cases/NCBI_CASES.tsv
NCBI_SRC="$NCBI_SRC" python3 -m unittest discover -s LOSAT/tests -p 'test_ncbi_unit_case_ledger.py'
```

`$NCBI_SRC` is a git checkout of NCBI BLAST+ (its `HEAD` is written to the file). With `NCBI_SRC`
set, the unittest also compares the committed file with a fresh extract. After a new commit, fix
the citations and ledger rows that `check` reports.

## What `check` enforces (the ratchet)

`check` needs no NCBI source; CI runs it in the `rust` job. It fails, with one line per module,
case and reason, when:

1. a citation names a case that is not in `NCBI_CASES.tsv`, cites lines outside the case, names
   another NCBI commit, is malformed, or is not directly above a `#[test]` function that is not
   `#[ignore]`d;
2. a `losat_test` entry does not exist (file, `#[test]` function that is not `#[ignore]`d, fixture
   file, or fixture id), names a `.rs` file without `::fn`, or a `ported`/`partial` row names only
   fixtures, or a `ported` row has neither a citation nor a test;
3. a cited case has no ledger row, or its row is not `ported` or `partial`;
4. a row has an unknown status, names a case not in `NCBI_CASES.tsv`, repeats a case, has a
   `since` that is not a date, or is `superseded` without a note;
5. the ledger counts more linked `ported` and `partial` cases in a module than the code backs.

So a removed, renamed or moved test fails CI until its ledger row names the new test or no longer
names it. A `partial` row may then fall back to an evidence note, which `check` does not tie to
code: review such a change in the diff, and prefer lowering the status. `check` does not see a
`#[test]` written inside another function or in a file outside the module tree, and it does not
require `to-port` rows to go down; ports happen in the sweeps (AGENTS.md rule 10).

## Origin of the first rows

The first `LEDGER.tsv` (2026-10-10) was converted from a mapping of all 679 NCBI cases to LOSAT
tests made on `main` b28e42e1, each module's mapping checked by a second reader (equivalent ->
`ported`, partial -> `partial`, e2e_only -> `e2e`, gap -> `to-port`, not_ported and out_of_scope
-> `n-a`; the 18 refuted claims take the reader's corrected status and evidence; `DISABLED` cases
set to `n-a`). Where the cited test could not be found on the current `main`, the row is
`partial` with the evidence (paths at b28e42e1) in `note`.
