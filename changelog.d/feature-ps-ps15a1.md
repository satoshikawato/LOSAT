- `losat rpsblast` and `losat rpstblastn` write `-outfmt 11` (the BLAST archive, ASN.1 text, that `losat rpsbproc` and NCBI's rpsbproc read) and `-outfmt 5` (BLAST XML) with the bytes of NCBI BLAST+ 2.17.0 `-num_threads 1` (apart from the version line, which names LOSAT), at every thread count and `-mt_mode`, for every option these programs run (a message stored in the archive carries LOSAT's wording where LOSAT words it as its own, as `blastp`'s archive does). Before, both refused these formats. `losat rpsblast -query proteins.faa -db Cdd -outfmt 11 | losat rpsbproc -d data -t doms -m rep` now runs as one pipeline with NCBI's archive bytes in between (one archive per query batch), for protein and nucleotide queries. The archive and the XML come from the writers of `blastp` and `blastx`: the request's service and options, the XML's program and version, the footer's K of the batch's first query and, for `rpstblastn` with composition-based statistics, NCBI's counts of identities and positives in the Seq-aligns are data of the RPS runs, with no second writer. `rpstblastn -outfmt 5` also reads its query from standard input, as NCBI's does. One case is refused: `-outfmt 5` with a profile whose id is `lcl|Query_N`, the generated id of a query of its batch, among the hits (NCBI's `rpsblast` XML then takes the query for that entry, and NCBI's `rpstblastn` stops after half a document); `-outfmt 11` writes NCBI's bytes for it. Tests: frozen rows at outfmt 11 and 5 for both programs and a pipeline test of the archive and of rpsbproc's output against NCBI's. `rpstblastn -max_target_seqs` over several volumes that hold the same profile now cuts the merged hits by subjects, as NCBI's formatter does, in every report that cuts them (before, a copy of the first hit's profile in the next volume was cut away).
