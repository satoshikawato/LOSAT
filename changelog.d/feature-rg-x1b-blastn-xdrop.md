- `blastn`: `-xdrop_ungap`, `-xdrop_gap` and `-xdrop_gap_final` convert to raw scores in the protein programs' one place (`core::x_drop`), so a raw X-drop past 32-bit integers is NCBI BLAST+ 2.17.0's x86-64 value, and megablast's greedy extension and the ungapped extension use it as NCBI's build does: `-xdrop_gap 1e10` and `-xdrop_gap_final 1e10` of megablast now give NCBI's report. A large final X-drop of dynamic programming (`-task blastn`, `blastn-short`, `dc-megablast`) no longer reserves memory in proportion to the X-drop: `-xdrop_gap_final 1e7` to `1.9e9` give NCBI's report (they stopped on an allocation failure), and `1e6` runs in about 300 MB instead of 6.7 GB on a 12 kb by 20 kb pair. Refused before the search, where NCBI corrupts its heap, reads memory it did not write or stops with `BLAST engine error: Unknown error code -1`: a greedy X-drop that leaves NCBI's greedy alignment no cell to start from (with the default scores about -7.4 bits and less, and about 1.98e9 to 3.97e9 bits), and a final dynamic-programming X-drop past NCBI's 32-bit kernel sizes (line RG, X1b).
