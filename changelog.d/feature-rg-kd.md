- The command line's standard output no longer writes the bytes of a failed write later. When a write failed for a moment (`EAGAIN` on a non-blocking standard output, or a device that got space back), up to 1023 bytes stayed in Rust's line buffer and were written at the next write or at the exit; NCBI BLAST+ 2.17.0 loses them. This affects `dustmasker`, `segmasker`, `windowmasker`, `convert2blastmask`, `blastdbcmd` (`-metadata` too), `makembindex`, `makeprofiledb`, `rpsbproc`, the help and version texts, and `makeblastdb`'s log. A write to a standard output opened only for reading now fails as NCBI's does. Before, it counted as done. `makeblastdb`'s log on standard output is written as NCBI's: each line goes out where NCBI's buffer writes it, and after a failed write the log writes nothing more (line RG, KC-11b-2).
