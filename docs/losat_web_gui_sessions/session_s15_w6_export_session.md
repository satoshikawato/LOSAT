# Session S15 — W6：出力と再現性

## INSTRUCTION PROMPT

LOSAT Web の段階 W6 を実行する。先に [セッション README](README.md) の共通規則を読み、それに従う。完了条件の正本は、総合計画書 §7 の S15 の行である。設計は計画 §5.8、設計書 §12 にある。

始める前に、セッションファイルに候補とメモを含めるかを保守者に確認する（計画 §10）。

1. 互換出力：outfmt 0/6/7 の書き出しは S01 で作ってある。保存したテキストを 1 バイトも変えずに出し、範囲は実行の結果全体だけにする。
2. アプリ独自の出力：CSV・JSON（HSP レコードから作り、ViewState のフィルターや選択を反映できる）、結果レポート（外部スクリプトも計測も含まない静的 HTML、入力はすべてエスケープ）。どれも LOSAT Web の形式であると明記し、NCBI と一致するというラベルを付けない。書き出しは、メモリへ全体を組み立てずに、ブロックを順に書く。
3. 設定ファイル：検索条件（program、入力名を除いた argv、スレッドの設定）だけを書き出し、読み込むとフォームに入る。
4. セッションファイル：manifest（schema の版、app / engine の版、RunSnapshot、レコード表、入力の SHA-256）と、テキスト・レコードのブロックを長さ付きで並べた単純なコンテナにし、`CompressionStream` で gzip する。読み込んでも検索は始めない。スキーマの不一致、欠け、長すぎる値、不正な参照を検出して拒否する。入力の名前や内容を HTML・スクリプト・URL として解釈しない。flank や全長の抽出には元の FASTA を選び直してもらい、SHA-256 が一致したときだけつなぎ直す。内部の OPFS のパスやセッションのトークンは書き出さない。
5. 再現の手順：CLI コマンドと、NCBI との比較用のコマンドを RunSnapshot の argv から作る。既定以外の subject の遺伝暗号を使う TBLASTX / TBLASTN では、承認済みの例外であることを注記する。レコードを除外した実行やファイルをつないだ実行では、「この実行に使った入力 FASTA」を書き出せるようにする。
6. 試験：セッションを再読込しても再計算しないこと、元配列が無いとできない操作が明示されること、勝手につなぎ直さないこと、壊れたセッションファイルを拒否すること。

完了条件は計画 §7 の S15 の行による。記録は `docs/evidence/losat_web_w6/README.md`。
