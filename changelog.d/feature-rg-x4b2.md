- `blastx -use_sw_tback` now runs, with every `-comp_based_stats` (0 to 3), `-db` and `-subject`, with sum statistics (the default) and with `-sum_stats false`, where LOSAT refused the option before: each match is aligned again in the windows of the query's frames with NCBI BLAST+ 2.17.0's Smith-Waterman traceback, at every `-num_threads` as NCBI's `-num_threads 1` does it. A query batch whose last Smith-Waterman alignment fails ends as NCBI's does when the batch's first query has kept no alignment: the results of the query batches before, then `LOSAT engine error: Traceback failed`. With a `-negative_seqidlist`, a subject that the list leaves without a definition line is skipped when the alignments are made again, and it resets the query batch's failure, as in NCBI. Refused, after the results of the query batches before (the manual's page "What LOSAT refuses"): a query and subject whose alignment NCBI never finishes; a query batch on which NCBI crashes, one whose last alignment fails after the batch's first query has kept one; and `-use_sw_tback` with `-ungapped`, on which NCBI crashes at every query batch (line RG, X4b-2). In e-value mode (`-sum_stats false`, or a `-max_intron_length` of 1 to 4), where NCBI checks a new alignment against a list of kept alignments past the end of its lists, one per query of the batch (a frame whose number, 6 × the query's place in the batch plus 0 to 5 for frames +1, +2, +3, -1, -2, -3, is the batch's number of queries or more; with one query in a batch, any hit outside frame +1) and crashes, fails or goes on with what it reads there, LOSAT checks against an empty list and writes NCBI's result for the same queries followed by queries without hits (the manual's page "Differences from NCBI BLAST+").
