- `losat psiblast -in_pssm FILE -comp_based_stats 0` searches with a PSSM query as NCBI BLAST+ 2.17.0 does, byte for byte, with `-subject` or `-db` and outfmt 0, 6 and 7: the PSSM in NCBI's ASN.1 text form (`PssmWithParameters`, as psiblast's `-out_pssm` writes it) is read with the options, its scores (padded to 28 rows) replace the matrix in the lookup table (the neighbouring words of each query position, without the exact-word rule), the one-hit and two-hit ungapped extensions, the gapped start, the score-only and traceback alignments (scalar kernels of their own, `algorithm::pssm_search`), the ungapped X-drop reads the PSSM's ungapped Karlin-Altschul block and the cutoffs, gapped X-drops, e-values and bit scores its gapped block, the identities and positives stay BLOSUM62's, the report shows the PSSM's query (its local id and title, its letters as stored) and the footer prints the PSSM's own Karlin-Altschul values; restricted alignment is not used (NCBI uses it for blastp only). NCBI's errors come as in NCBI: a file that cannot be opened, a file that is not a PSSM (FASTA, empty, compressed: "Unsupported format for PSSM"), a file that does not read as one ("Unrecognized format for PSSM in FILE (must be PssmWithParameters)"), and the checks of `CPsiBlastValidate::Pssm` (a scaled PSSM, a PSSM that is not a protein one, one without scores and frequency ratios) after the outfmt 0 prolog; `-in_pssm` with `-query` or `-query_loc` is the parser's error. Refused before the search: `-comp_based_stats` 1, 2 and 3 (also the default 2) with `-in_pssm` until the position-based composition-based statistics are ported, a PSSM of frequency ratios only, a binary or XML PSSM, the PSSM files (`-out_pssm`, `-out_ascii_pssm`, `-save_each_pssm`, `-save_pssm_after_last_round`), outfmt other than 0, 6 and 7, `-seg` and `-soft_masking true`, a PSSM query that NCBI splits into chunks, a query Seq-id other than one local string, a string with a byte outside the visible ASCII range, a query Seq-entry that is not one Bioseq or a PSSM without a query, and a PSSM whose sizes do not match its scores, frequency ratios or query (NCBI reads past its matrix). The library API (and pylosat) refuses `-in_pssm`: its queries are records (line PS, item PS4a; DECISIONS 11).
