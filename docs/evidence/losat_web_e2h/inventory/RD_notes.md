# Range RD notes: CFastaReader records (ReadOneSeq .. AssembleSeq, warnings)

Table: `RD.tsv` (49 rows). Scratch: `scratch_RD/` (inputs `<name>.q.fa`/`<name>.s.fa`; NCBI runs `<name>.out/.err/.rc`, made by the `t*.py` scripts with the exact commands and custom fields `6 ...`; `<name>.n.*` = NCBI with plain `-outfmt 6` (or `0`), `<name>.l.*` = LOSAT base binary with the same command, produced by `runboth.py`; `cmp2.txt` lists SAME/DIFF per case). Every NCBI run used `scratch_RD` as working directory, which contains `.ncbirc` (`[BLAST]` / `DATA_LOADERS=none`), so no run could reach the network. Consequence: those runs used `CCustomizedFastaReader`; the data-loader class `CBlastInputReader::ReadOneSeq` (Seq-id try on a first line starting with a letter/digit) belongs to range BI and was not observed.

## Call path
1. `CBlastFastaInputSource::x_InitInputReader` (blast_fasta_input.cpp:316-368) builds the reader: flags `fNoParseID|fDLOptional`, `fAssumeNuc|fAssumeProt`, `fNoSplit` (unless env `BLASTINPUT_GEN_DELTA_SEQ` non-empty), `fHyphensIgnoreAndWarn`, `fDisableNoResidues`, `fQuickIDCheck`; ignored problems: ModifierFoundButNoneExpected, TooLong, TooManyAmbiguousResidues; `CSeqIdGenerator(counter init, prefix)`.
2. Per record `CBlastFastaInputSource::x_FastaToSeqLoc` (called through `CBlastInput::GetAllSeqs` for subjects/`GetNextSeqBatch` for query batches): with `-lcase_masking` it calls `SaveMask()` first, then `m_InputReader->ReadOneSeq()` with the DEFAULT null listener (this is why warnings are LOG_POST lines and errors are thrown), then (range BI) mol check, strand, range check.
3. `ReadOneSeq`: reset state, loop over lines: col-0 `>` handling (`>?_` rewrite, `>?` data, defline -> `ParseDefLine`), else `TruncateSpaces_Unsafe`, skip blank/comment, `fDLOptional` -> `ParseDefLine(">")`, then `ParseDataLine` (gap lines -> `ParseGapLine`; others `CheckDataLine` while no residue yet, then the per-byte switch). After the loop `AssembleSeq`: `CloseGap/CloseMask`, `AssignMolType` (override: mol from flag), `ParseTitle` (title warnings; modifiers ignored), N/X substitution for `>?` gaps, empty-record branch.
4. Timing: subjects are read completely during argument processing (before queries; their warnings/errors come first, `o_both_warn`, `o_subj_fail_q_warn`); queries are read per batch just before the search of that batch. For `-outfmt 0` the report header is already on stdout before the first query is read.

## State that persists
- Line reader: 1-based physical line number (blank/comment lines count; `UngetLine` decrements, so peek+unget does not double count), EOL style, pushback (range LR).
- ID generator counter (+prefix `Query_`/`Subject_`): one value consumed per RECORD (also title-less records and `>?_x` pseudo-deflines), `id_counter` oracle: records q1, "", q3, "" are q1, Query_2, q3, Query_4.
- The mask object is per record (created by `SaveMask()` right before `ReadOneSeq`).
- Nothing else carries across records. `m_SeqData` empty is what makes the first data line of EACH record go through `CheckDataLine`.

## Exact messages (all on stderr, newline-terminated, NO `Warning:` prefix, produced by `LOG_POST_X(1, Warning << Message())` because the listener is null)
- `CFastaReader: Hyphens are invalid and will be ignored around line N` (once per line that has a `-`; printed before that line's invalid-residue warning).
- `FASTA-Reader: Ignoring invalid residues at position(s): On line N: 51-54, 62` (no "nucleotide"/"protein" word; 1-based byte index in the trimmed line; merged ranges; at most 1000 ranges, silently truncated).
- `FASTA-Reader: Title ends with at least 20 valid nucleotide characters.  Was the sequence accidentally put in the title line?` and `... at least 50 valid amino acid characters. ...` (two spaces after the first period; at the END of the record).
- Gap lines: `CFastaReader: Bad gap size at line N`; `CFastaReader: Problem parsing gap mods at line N`; `Unknown gap-type: V`; `Unknown linkage-evidence: V`; `Unknown gap modifier name(s): K`; `There were conflicting gap-types around line N`; `FASTA-Reader: Unknown gap-type can have linkage-evidence of type 'unspecified' only.`; `CFastaReader: This gap-type should have at least one specified linkage-evidence.`
- Silent (ignored problems): modifier `[k=v]` in titles, title > 1000 characters, >40% ambiguous first line, gap-type that forbids linkage evidence, "Gap mods are ignored ...".
- Error (stderr `BLAST query error: CFastaReader: Near line N, there's a line that doesn't look like plausible data, but it's not marked as defline or comment.` + newline, exit 1; nothing of earlier records of the same batch printed; also for subject files; with `-outfmt 0` the header was already printed). The prefix `BLAST query error: ` is added by the app, the rest is the exception text.
- Not from the reader but seen in the same runs (range BI/search): `Warning: [blastn] Query_2 q2: Sequence contains no data ` (record without residues, rc 0 unless all are empty: `BLAST engine error: Warning: Sequence contains no data  Warning: ...` rc 3), `Warning: [blastn] Query is Empty!` (empty/white-space-only file, rc 0), `BLAST engine error: Empty CBlastQueryVector` (rc 3; file with only comment lines: the reader throws eEOF "Expected defline", swallowed by `CBlastInput`), `Warning: [blastp] Query_1 q1: One or more O characters replaced by X for alignment score calculations at positions 40 `.

## Key oracle observations (inputs are in scratch_RD/*.q.fa; B = 200 nt known to hit the subject, PB = 100 aa)
- Defline ">   lead title" -> outfmt 0 `Query= lead title`; ">q1\ttab title" -> title `q1`; ">q1 ctl\x01tail" -> `q1 ctl`; ">\x01q1 title" keeps the first byte; ">q1\x00zz title" -> `q1`; UTF-8/non-UTF-8 bytes kept; ">" and ">   " -> empty title, ID `Query_N`; 1104-char title accepted silently; `[organism=...]` stays in the title silently.
- Title tests use the untrimmed text: ">q1 "+ACGT*5 warns, ">q1 "+ACGT*5+"  " does not, ACGT*5 as the whole title (20) does not, 21 does; lower case counts; U and N do not; protein: 50 letters (title length exactly 50) no, 51 yes, trailing space/digit no.
- Sequence lines: spaces/tabs inside lines silently dropped; digits, `*`, `@`, DEL, NUL, bytes >= 0x80, `>` not in column 0 in nucleotide mode = bad residues (warning, residue dropped); `E F I J L O P Q Z X` also bad in nucleotide mode; `;` ends the line; `!`/`#`/`;` first-non-blank lines skipped; `-` dropped with the hyphen warning; `U` kept (searched as T); protein keeps all letters and `*` (qlen counts it).
- CheckDataLine: error iff `bad >= good/3 && (len > 3 || good == 0 || bad > good)` on the first <= 70 bytes of the trimmed first data line of a record (hyphen, digit, space neutral; `;` stops). Failing in record 1 or record 3 both give rc 1 and empty stdout (outfmt 6); a later batch fails after the earlier batches printed (`BATCH_SIZE=250`).
- No defline: sequence-only file is one record `Query_1`; BOM before the sequence = 3 bad residues; BOM before `>q1` = CheckDataLine error; ` >q1` is data.
- Gap lines: see rows 36-39. `>?_x` is a defline "x" (new record).
- Masks (outfmt 0 prints masked query residues in lower case): runs are not closed by white space, hyphens, bad bytes, digits, `;` text, comment/blank lines, line ends or gap lines; gap bases belong to the run (`m_gap_inside`, `m_gap_after_lower`; not when the gap precedes the run: `m_gap_before_lower`); `*` closes a protein run. Subjects get the same masks (display only in the oracle).
- LOSAT before: every case that NCBI reads with a warning is a hard error (`has X at residue N, which is not an IUPAC nucleotide letter ... not supported by LOSAT's BLASTN`, protein `has 'X' in a sequence line ...`), deflines with empty/white-space/control/non-ASCII bytes or `?` are errors, text before the first defline is `FASTA that bio cannot read`, records without residues are errors. SAME as NCBI: plain deflines, 20-nt title warning (no trailing blank), U as T, lower case with `-lcase_masking` for accepted input, protein letters/`*`/`U`/`O`/`J`/`B`/`Z`/`X`, empty/white-space-only query files.

## Surprises
1. Reader warnings have no `Warning: [prog]` prefix and no SeqId/line prefix: only the message text (null listener -> `LOG_POST`), unlike app-level warnings.
2. The title warnings come at the END of the record, after that record's data-line warnings; BLASTX's port prints them at the defline (order differs).
3. `CheckDataLine` treats hyphens as neutral, so `----` as first line is an error although a hyphen later is only a warning; `AC;rest` (fewer than 3 letters before `;`, line longer than 3) is an error too.
4. `bIsNuc` is false inside `CheckDataLine` (no molecule yet), so the ambiguous-nucleotide statistics are always 0; the ignored 40% warning could never fire anyway.
5. `AssignMolType` never guesses (threshold UINT_MAX): protein text in blastn stays nucleotide and is stripped (a whole protein query gives only a long warning, rc 0, no hits), nucleotide text in blastp is read as protein letters without any message; the `Protein FASTA provided for nucleotide sequence` errors are unreachable for FASTA input. `sRefineNaMol` (DNA/RNA) is unreachable.
6. `BLASTINPUT_GEN_DELTA_SEQ` set non-empty changed nothing observable (6 runs incl. a 250 kb query).
7. `>?_x` is NOT a gap: it is rewritten to a defline `>x`; mid-record it ends the record. A leading-space ` >?7` IS a gap line (data path), a leading-space ` >q1` is data.
8. Gap mods and gap sizes only produce warnings; residues are always N (nucleotide) / X (protein) repeated by the digits (min 1).
9. Same-line order of messages: hyphen warning, invalid-residue warning; per record: all line warnings, then title warning.

## Decisions for the session
- Gap-line modifiers (`[gap-type=...]`, `[linkage-evidence=...]`, row 37): port the ten gap-type names and the Linkage-evidence enum names (M) or accept a rejection (needs a documented exception; no network/NCBI-crash reason exists).
- Where the warnings go: the reader should return per-record warning texts in NCBI order (line warnings, then title warning); the caller prints them to stderr as read (subjects first). BLASTX's `reader_warning` text table is reusable.
- Title type must be bytes (NCBI keeps non-UTF-8 bytes; BLASTX currently fails on them: input.rs:604); report wrapping of such titles is range RP.
- Records without residues are produced by the reader (NCBI keeps them); the downstream `Sequence contains no data` handling is in BI/AD/search ranges.
- `-lcase_masking` for BLASTP and TBLASTX is rejected by LOSAT's CLI (cli.rs:375,637); the reader should produce masks for all programs, consumption is a program decision.
- Batch-by-batch reading (errors in a later batch after earlier output) needs BLASTX-style batch delivery.
- Not covered here (other ranges): EOL detection, `IsIStreamEmpty`/`Query is Empty!`, Seq-id try of `CBlastInputReader`, ranges (`x_FastaToSeqLoc` from/to checks), outfmt title/ID rendering (outfmt 6 shows the first word of the title as the ID, outfmt 0 wraps the title), subject ID prefix `Subject_`.
