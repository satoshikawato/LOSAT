- `-outfmt 1`, `2`, `3` and `4` (the query-anchored views) in `blastx` (`-task blastx-fast` too) and `tblastx`, with `-subject` and `-db`, byte for byte as NCBI BLAST+ 2.17.0 writes them: each query frame's alignments under `For reading frame <f> of query sequence:` when more than one frame has them, the query rows of minus frames running from high to low, the translated rows of both strands of `tblastx`'s subjects, insertions, the query's masks (SEG, `-lcase_masking`) of each frame, a subject's `-lcase_masking` runs on every row of the subject, `-query_gencode`, `-db_gencode`, `-strand` (`blastx`), `-query_loc` (the frames of the record), `-subject_loc`, `-line_length`, `-sorthits`, `-num_alignments`, `-show_gis` and `-parse_deflines`. As in NCBI BLAST+, a `tblastx` subject's alignment of the other strand than its first in the same query frame is not shown there (it is in the description table). A `tblastx` query record that is also a subject under `-parse_deflines` is shown as NCBI BLAST+ shows it: in each query frame its alignment with itself on the same letters disappears into the query row and its other alignments with itself are rows labelled with the record; where NCBI BLAST+ stops with an error on such a section (`Start iterator already exists for seq2`), `tblastx` refuses it before that query batch's first byte. `tblastx` writes formats 1 to 4 query batch by query batch as format 0, so their memory stays that of format 0 however many queries a run has. Refused: with `-db`, a database sequence whose Seq-align id or display id is the id NCBI BLAST+ gives a query of its batch (as in `blastp`, `blastn` and `tblastn`) (line RG, T3c).
