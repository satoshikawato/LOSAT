6. 既知の例外（承認済みの遺伝暗号の例外、認証済みプロファイルの外の設定、native-equivalent の升目）の一覧を、検証バッジの判定表と照らして作る。
7. 独立監査（エンジン側の主張）と画面レビュー（公開する画面）を受ける。

## S16（W7）から引き継ぐこと

[W7 のゲート記録](../evidence/losat_web_w7/README.md)の要点。上の 1.〜8. の条件はこの節で緩めない。**S17 は S16b（[W7 の続き：プレビューでの確認](session_s16b_w7_preview.md)）が終わってから始める**。S16 は計画 §7 の S16 の行の 3 つめ（プレビューで `crossOriginIsolated === true`）を確かめずに終わった。保守者の Cloudflare のデプロイが要るためで、S16b が最初に行う。V-OFF と V-PRIV は最後の木のゲート 3（`35970fa1`、すべての段階が通った）で通っている。S16b は画面レビュー 2 回目の Low 4 件（見た目と文言）でアプリを変えてゲートを再実行するので、最後の木・release ID・件数・計測の値は S16b の記録が正本になり、ここの値（ゲート 3、`35970fa1`）は S16b が書き直す。S16b の結果（プレビューの確認、`_headers` の Pages での挙動、直した残件）は、ゲート記録に追記される。それを読んでから、次を使う。

- **release ID と ReleaseManifest（上の 8.）**：release ID は `LOSAT_WEB_RELEASE_ID` があればそれ、無ければ `<commit 12>-<エンジンの digest 8>[-dirty]`（FakeEngine のビルドは `<commit 12>-fake`）。形は `^[0-9a-z][0-9a-z.-]{0,63}$`。S16 のゲート 3 の木（最後のアプリの木 `35970fa1`）の例は `35970fa18885-e2fb7128`（エンジンの digest `e2fb7128` は `141615ec` の reactor のもの）。`-dirty` と `-fake` の release は公開しない。ビルドの入力は `web/app/build/inputs.ts` に 1 度だけ列挙されている（`web/app`、`docs/web/verification_cells.tsv`、認証の記録の表、`LOSAT/tests/wasi_shared_memory.js`）。**S17 は最終の commit で reactor を作り直すので、release ID のエンジンの digest は変わる**。そのとき `web/app/src/examples/self-test.json` の期待値を `tools/examples.py expected` で作り直す（oracle の lock の下。`self-test-engine.test.ts` が合うまで落ちる）。ReleaseManifest は format 1：`release`・`app`（`version` と、commit の先頭 8 桁の `build`）・`engine`（2 つの module の build 名。FakeEngine は `null`）・`entry`・`assets`（`path`・`size`・`sha256`、sorted）。サイトの索引 `/releases.json` は release の外（サイト単位）：`latest`、`releases[]`、`shell`、任意の `analytics.endpoint`。形式と起動ページの動きは [`docs/web/release_manifest.md`](../web/release_manifest.md)。S17 の「版の名前」は人が読む名前で、release ID（ビルドのバイトの識別）とは別。S17 は ReleaseManifest の実物（デプロイした release のもの）を記録する。同じ commit と同じ reactor からの build は、同じ機械・同じ Node なら checkout のパスによらず同じ bytes（`release-bytes.test.ts`）。別の機械（CI の Node 24 と手元の Node 26 など）での同一は示していないので、公開する build は 1 か所で作り、その ReleaseManifest を記録する。
- **オフラインと更新の動き（上の 8. の「ReleaseManifest の内容」、S17 の対応環境の表）**：起動ページが `localStorage['losat-web:release']` の release を始める（無ければ `latest` を固定する）。サイトの Service Worker `/sw.js` が、その release の全 file（2 つの wasm、Worker、例題、JavaScript、CSS）と shell のサイズと SHA-256 を確かめて保存し、それから見出しが「Offline ready」になる（load の後 2 s と idle の後。約 2.0〜2.3 s）。研究データは cache に入れない。更新は、新しい release を知らせる → 利用者が選ぶ → 取得して確かめる → 切り替えの隣で、その時点の「再読み込みが失うもの」を言う → 固定を切り替えて再読み込み。取得が不完全なら今の release のまま。`skipWaiting` は利用者が切り替えるときだけ。旧版の cache は、その release の lock を持つタブが無くなってから消す。サイトがもう配らない固定は、黙って切り替えず、起動ページが「Use release <latest>」を出す。Service Worker を許さないブラウザ（Cookie とサイトデータを塞ぐ設定など）にはオフライン用の保存が無く、切り替えは検査なしで出す。Playwright の WebKit は `navigator.onLine` が常に true。**実機の Safari と iOS での Service Worker とオフラインは S17 の V-MOB で確かめる**（Playwright の WebKit は Safari ではない）。
- **利用統計（GA4）の状態**：方式 (b) を実装した。同意の後だけ、`{"v":1,"release","client"}` を同一 origin の `/api/visit` へ 1 回の訪問ごとに 1 件送り、Pages Function が本番の secret があるときだけ GA4 の Measurement Protocol に `app_visit`（`release_id` 付き）を転送する。サイトの索引に `analytics.endpoint` が無ければ、同意の文も送信も無い。どの文書にも Google のスクリプトは無い。比較は [`ga4_probe/RESULTS.md`](../evidence/losat_web_w7/ga4_probe/RESULTS.md)、実装は [`docs/web/analytics.md`](../web/analytics.md)。**保守者の確認待ち**：方式 (b)、GA4 の property と custom dimension（`release_id`）と 2 つの secret（Production だけ）、同意の文言（法的な確認）。S17 の公開する文面の案は、何を送るか（`analytics.md` の「What is sent, and when」）と、この判断待ちを引く。
- **V-PRIV・V-OFF・TD-11 と CI**：V-OFF は `tests/e2e/offline.spec.ts`（オフラインの開始、明示更新、不完全な更新、別のタブが切り替えても保つ旧版のタブ、サイトがもう配らない固定、固定の無いオフライン。オフラインはサーバーを止めて作る）。V-PRIV は `tests/e2e/privacy.spec.ts` と `support/privacy-scan.ts`（正常・取消・拒否・失敗・書き出し・再読込・更新・「Try an example」と自己試験・計測の各経路で、すべての要求を捕まえ、試験文字列と他の origin を探す）。TD-11 は同じ spec の最後の試験（サイトが配る全 file にビルドした機械のパスとユーザー名が無い。Chromium で 1 回）。三つとも `.github/workflows/web.yml` の `web` の job（FakeEngine のビルド）と `browser-engine` の job（エンジン入りのビルド）の `npm run e2e` に入っている。`browser-engine` は自己試験の期待値の試験 `self-test-engine.test.ts` も走らせる。ゲートは [`run_gate.sh`](../evidence/losat_web_w7/run_gate.sh)。S17 の「V-ABI・V-BR の再実行」では、最終の commit で reactor を作り直し、ゲートの script を `losat_web_g` に替えたコピーで走らせるのが最短。
- **自己試験と例題（NCBI と同じ出力）**：5 program の例題（DnaA とその遺伝子の 2,000 nt の領域とタンパク質）が release の資産に入っている。`self-test.json` は、各例題の argv、入力の SHA-256、outfmt 0・6・7 の SHA-256 と長さを持ち、ネイティブの LOSAT（`141615ec`）が書くバイトで、NCBI BLAST+ 2.17.0 のバイトと 15 件とも一致する。ブラウザの自己試験は、これをアプリのエンジンの出力と比べる（1 スレッドと Auto のスレッドの 2 回。ゲート 3 で Chromium 0.23 s、Firefox 1.7 s、WebKit 0.24 s）。BLASTX の例題と期待値は入っているが、SX まで「Try an example」と自己試験は無効（BLASTX の期待値は SX の後に、エンジンが NCBI と一致することを再び確かめる）。S17 の BLASTX の認証が済んだら、BLASTX を有効にし、期待値を作り直す。文書は [`docs/web/examples.md`](../web/examples.md)。
- **配信の実測（上の 5.）**：`tests/e2e/delivery-measure.spec.ts` が、初回・2 回目・オフラインの訪問（`app`・`ready`・送られた byte・保存した byte）、準備、自己試験、例題から最初の結果までを 3 ブラウザで測る（1 回の暖機と 3 回の中央値と範囲）。最後の木のゲート 3（`35970fa1`、[`run-20261011T080950Z/measure/`](../evidence/losat_web_w7/run-20261011T080950Z/measure/)）の値はゲート記録の「実測」にある：初回の訪問で「Offline ready」まで Chromium 2.19 s、Firefox 2.26 s、WebKit 2.17 s（2 回目 2.05〜2.10 s、オフライン 2.02〜2.08 s）、検索フォームが出るまで 65〜116 ms、保存する release は 17 file・8,188,494 byte（初回に送られる byte は 8.2 MB、WebKit は 12.4 MB）。結果と書き出し（10 万 query・149,828 HSP）は W6 のゲート 3 と同じか速い（Run を開く Chromium 266・Firefox 473・WebKit 357 ms、JSON 1.6〜1.7 s、セッションの保存 1.8〜2.3 s・開く 1.3〜1.9 s）。100 ms を超えたフレームの間隔は Chromium の JSON の 250 ms（W6 との対の A/B で退行ではない：W6 183 / 133 / 250 ms、W7 200 / 167 / 133 ms。100 ms 超は W6 から）と WebKit の書き出しの開始の 117〜134 ms。結果の計測は W7 から「Offline ready」の後に始める。**測っていないもの**：準備が検索と重なる場面（コードレビュー 2 回目 I2）、取消の後の再準備の時間（S17 の 5.、DW-22）、公開する対応規模の最大の入力でのメモリ、iOS・Android の実機（V-MOB）。ゲート記録の計測の値は 3,000 写しまで（WebKit は 1,500 写しまで）で、4000 写しの自己検索は 3 ブラウザでエンジンのメモリ不足になる（W6 のまま）。
- **残件（S17 に関わるもの）**：ゲート記録の「残件と注意」。S16b で直すものを除き、主なもの：コードレビュー 4 回目の情報 I1〜I3（click の時点の再確認は別の tab の掃除との競合を閉じない、cookie を塞いだ WebKit の probe、保管場所の確認の余裕）、shell の保存が atomic でないこと（コードレビュー 1 回目 I1）、自己試験を取り消せないこと（I4）、V-OFF 3b が決定的でないこと（コードレビュー 2 回目 I1）、V-PRIV が request header の符号化を限られた形でしか探さないこと（コードレビュー 3 回目 I2）、WebKit の scroll anchoring と遅れて読まれる Alignments（W6 の判断 17）、WebKit の書き出しの開始の 128〜155 ms、隠れた tab の timer、`query.fa` / `subject.fa`、W5 コードレビュー L3、グラフの行 8 px、電話のタブの行、BLASTX（SX）、`abi_v2.md` の kind 0、E2j の申し送り、エンジンのメモリ不足、WebKit の保存の上限（512 MB）、`runInputs` の解放、iOS Safari（V-MOB）、WebKit の `navigator.onLine`、Playwright の offline の emulation の限界、Chromium が `/r/` の 404 を immutable として覚えること。V-PERF の lock の規則を WP-U の V-OFF の 1 回の実行で破ったこと（記録済み）。
- **保守者の判断待ち（S16 から）**：プレビューのデプロイ（S16b）、GA4 の方式と設定、Cloudflare に残す旧版の数とドメイン名（計画 §10）、同意の文言、本番へのデプロイ。判断 1〜20 はすべて Owner-delegated で、保守者が予約した判断は無い。
