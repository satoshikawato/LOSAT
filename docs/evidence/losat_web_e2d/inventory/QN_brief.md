# Range QN: the query range for nucleotide queries (blastn, tblastx)

Files: `QN.tsv`, `QN_notes.md`. Read `COMMON.md` first.

Entry points (NCBI): the query range becomes a `CSeq_interval` (from, to, strand both) in `CBlastFastaInputSource::x_FastaToSeqLoc` (`c++/src/algo/blast/blastinput/blast_fasta_input.cpp:380-460`) and an `SSeqLoc`/`CBlastSearchQuery` in the query vector. Follow it through `CObjMgr_QueryFactory` (`c++/src/algo/blast/api/objmgr_query_data.cpp`), `CBlastQuerySourceOM`, `SetupQueryInfo_OMF` and `SetupQueries_OMF` (`c++/src/algo/blast/api/blast_setup_cxx.cpp`: how the sequence data, context lengths and offsets are built from the interval; strands; frames for tblastx with the query genetic code; `GetSequence` on an interval), the masks: lowercase (`-lcase_masking`: the mask read with the record in full-record coordinates, then restricted/shifted to the interval? find the code), DUST for blastn (`Blast_FindDustFilterLoc` in `c++/src/algo/blast/api/dust_filter.cpp`: does it dust the interval's letters or the full record and then intersect?), SEG for tblastx (`BlastSetUp_GetFilteringLocations` in `c++/src/algo/blast/core/blast_filter.c` on the interval's translated frames), `-soft_masking`; `Blast_FindRepeatFilterLoc`/window masker are out of scope. Then: BLASTN query batches and split (`CBatchSizeMixer`/`GetQueryBatchSize`, `CQuerySplitter`, `split_query_aux_priv.cpp`, `s_SetSplitQuerySeqInterval`): are the batch and chunk sizes computed from the interval length; how chunk coordinates map back to the record. TBLASTX's query split (10002 letters; LOSAT does not split TBLASTX and its output is unchanged, E2e R2c-1). Statistics: the query length that enters `BLAST_CalcEffLengths` / length adjustment / effective search space per context (interval length?), `BlastQueryInfo` context offsets. The "query has no letters"/"Query is Empty!" style errors and warnings when the interval is empty or all masked. Record each step's coordinates (0-based, strand, frame, nucleotide units).

LOSAT side: BLASTN query reading and encoding (`algorithm/blastn/blast_engine/run.rs`, `coordination.rs`, `input.rs`), contexts, DUST and lowercase (`algorithm/blastn/filtering/`), query batches (`blastinput/query_batch.rs`) and split (`algorithm/blastn/query_split.rs`), stats; TBLASTX query reading, frames, SEG, stats (`algorithm/tblastx/blast_engine/run_impl.rs`, `translation.rs`). For each NCBI step say where LOSAT must apply the range (cut the letters, shift masks, use the interval length) and whether the existing code would then behave like NCBI.

Oracle runs to make (blastn and tblastx, outfmt 0 and `6 std qlen`): a range in the middle of a record with hits crossing the range edges (on both strands of the query for blastn, on all six frames for tblastx); a range whose end is past the record end; multiple query records with one range; a lowercase run that straddles the range start, with and without `-lcase_masking`; a low-complexity run (DUST/SEG) that straddles the range start (does the masked region depend on the letters outside the range?); a ranged query long enough to be split or batched (blastn: a few hundred kb record with a range of > 1 Mb? choose sizes from the NCBI code; e.g. CHUNK_SIZE environment variable is unset, so use the default sizes); tblastx with a range whose length is not a multiple of 3 (frames at the range end).
