- A database header record that NCBI BLAST+ 2.17.0 cannot read (a damaged or cut record, a taxid of another type or outside `int`, a tag, length or end that NCBI's reader does not take) gives NCBI's error, where LOSAT refused it (exit 1): the search programs write `Error: ` and NCBI's exception (its place, position, message, the path of NCBI's object stack and the `error while reading <member>` lines) with exit status 255, after what NCBI writes before (the outfmt 0 prolog of `blastp` and `tblastn`, which LOSAT did not write, and the reports of the query batches before in `blastp`, `tblastn`, `tblastx` and `psiblast`); `blastdbcmd` writes `Error: [blastdbcmd] ` and NCBI's message (exit 1), `segmasker` NCBI's exception (exit 1), `dustmasker` NCBI's report (exit 3, where LOSAT exited 1) (line RG, T5d).
- A search no longer refuses a database whose first header record NCBI cannot read when no report reads that record: NCBI reads no header when it opens a database, and LOSAT writes its whole output (line RG, T5d).
- A header record is read as NCBI's reader reads it in two more cases: the bytes after the definition lines are not read, where LOSAT refused the record, and a constructed value with a definite length in the long form ends where NCBI's reader ends it, where LOSAT read the record (PD-LOSAT-NCBI-DEFECTS 1.39; makeblastdb writes neither) (line RG, T5d).
