## 2. What the display uses (and what it does not)

* The display never uses the engine's alignment letters. Both rows are re-translated from the FASTA nucleotides (`CAlnVec::GetSeqString` width 3, `x_GetSeqVector` IUPAC strand-aware, `TranslateNAToAA` through `CTrans_table`). So ambiguity codes show as the table's letter (`GCN` -> `A`, `GAY` -> `D`, `RAY` -> `B`, `SAR` -> `Z`, `MTA` -> `J`, `NNN`/`GAN`/`KGA` -> `X`) and identities, positives and the middle line are counted from these rows.
* Identities = columns with equal characters (so `X`/`X` and `*`/`*` are identities, the middle line shows `X` and `*`); positives = columns with BLOSUM62 > 0 (`B`/`D`, `Z`/`E` count; `J` and `*` against a letter never do); gaps are always 0. LOSAT's `Hit.num_positives` is just `matches` (`run_impl.rs:3063`) and `Hit.num_ident` comes from the engine's own letters, which can differ from the displayed rows next to ambiguity codes; the display counts must be recomputed from the rows.
* Scores come from the Std-seg scores `score`, `bit_score`, `e_value`|`sum_e`, `sum_n` (present only when the HSP is in a sum group of at least 2). `Expect(n)` is printed iff `sum_n > 0` (that is, n >= 2).
* Subject masks are empty for a local `-subject` without `-lcase_masking`; only the query is lowercased (SEG, default on), and only in the Query row (never in the middle line).
* `-db_gencode N` with a local `-subject`: the NCBI SEARCH uses the default subject code, but the DISPLAY translates the subject row with N (oracle below). LOSAT applies N to the search too (approved exception); the display rule is the same.

8. Blank lines: one after every chunk, one more after every HSP block, one more (the footer's) before `Lambda` (`showalign.cpp:1551,3980`; `blast_format.cpp:456`).
9.
