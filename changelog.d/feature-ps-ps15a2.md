- `losat rpsblast` and `losat rpstblastn` now write every output format that NCBI's programs write, with the bytes of NCBI BLAST+ 2.17.0 `-num_threads 1` at every thread count: `rpsblast` adds the query-anchored reports (`-outfmt 1` to `4`), and both add the Seq-annots (`8`, `9`, `12`), BLAST JSON and XML2 (`13` to `16`), the organism report (`18`) and comma-separated values with a header line (`20`). Before, both refused these formats, so a pipeline or a script written for NCBI's `rpsblast` with one of them stopped. The formats come from the writers of `blastp` and `blastx`; what differs for the RPS programs is data the run hands them (the Seq-annot's "Blast Type" `rpsblast`/`rpstblastn`, and the Seq-aligns' identity counts on the searched letters, as in the archive). Refused, where NCBI takes the query for a profile whose id is `lcl|Query_N`, the generated id of a query of its batch: `rpsblast -outfmt 1` to `4`, and both programs' `-outfmt 13` to `16`, `18` when the profile has a taxid, and `20` with a field that shows more of the profile than its id, such as `stitle`, `slen` or `pident` (in `rpstblastn` also a field of the alignment, where NCBI stops with an exception); the Seq-annots (`8`, `9`, `12`) and the other tables (such as `20 qseqid sseqid sacc evalue`) write NCBI's bytes for it.
