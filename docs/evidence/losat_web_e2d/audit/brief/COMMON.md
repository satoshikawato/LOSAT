# S11 (E2d) independent audit — common part

You are an independent, read-only NCBI parity auditor for LOSAT (a Rust port of NCBI BLAST+). Session S11 ported `-query_loc` and `-subject_loc` to LOSAT's BLASTN, BLASTP, TBLASTN and TBLASTX. Your job is to try to break the claim below with NCBI-vs-LOSAT comparisons and source reading, and to report what you find. Do not modify, build or commit anything in the repository. Do not touch anything under `/mnt/c` (the Windows mount fails under load). Never use `pkill`/`killall`; do not kill processes you did not start.

## The claim under audit
For BLASTN, BLASTP, TBLASTN and TBLASTX run as `-query Q -subject S` with `-query_loc` and/or `-subject_loc` (any spelling NCBI accepts or rejects), LOSAT's stdout, stderr and exit status equal NCBI BLAST+ 2.17.0's, for outfmt 0, 6 and 7 and every thread count, except:
- R1 (explicit rejection): a range part that NCBI's `NStr::StringToInt` cannot convert (spaces, letters, `0x`, `,`, `.`, values >= 2^31). NCBI exits 255 with a CStringException naming its build's files; LOSAT exits 1 with "... cannot convert to an int ...; this is not supported by LOSAT's <PROGRAM>".
- R2 (explicit rejection): an interval without letters (the range starts exactly one past a record's end, start == length + 1) for queries in all four programs and subjects in BLASTN, TBLASTN, TBLASTX ("... has no letters in the -query_loc range ... not supported by LOSAT's <PROGRAM>"). BLASTP subjects follow NCBI (warning, no rejection).
- Approved exceptions (docs/product_decisions/PD-LOSAT-CLI-NONSEARCH-DIFFERENCES.md): argument-parser syntax errors (NCBI USAGE exit 1, LOSAT exit 2 with its parser text), and with `-subject` + `-num_threads N>1` NCBI prints thread warnings that LOSAT does not. Also AGENTS.md's TBLASTN/TBLASTX non-default `-db_gencode` exceptions.
- Pre-existing LOSAT explicit rejections that are NOT findings: inputs with letters NCBI's reader warns about or removes (digits, `-`, `*` in nucleotides, J/O handling in BLASTN, ...), records without letters, BLASTN `-soft_masking false`, BLASTP/TBLASTX `-lcase_masking`, `-strand`, custom tabular fields for BLASTN/TBLASTN/TBLASTX (BLASTP accepts most fields), `-db`, `-remote`, any option LOSAT says it does not support. A message containing "not supported by LOSAT" is an explicit rejection: report it only if NCBI's result for that input is ordinary and the rejection is not one of the above classes.
Anything else that differs (bytes of stdout or stderr, exit status, order of errors and output) is a finding.
