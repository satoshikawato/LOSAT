# Range AD: the Web adapter and ABI (scan, register, run) and ABI v1

Files: `AD.tsv`, `AD_notes.md`. Read `COMMON.md` first. This range has no NCBI entry points of its own: it maps the reader's results (ranges LR, RD, BI, RP) onto the Web adapter. Use `ncbi_file`/`ncbi_lines` for the NCBI behaviour that the adapter must reproduce or index (e.g. `fasta.cpp` `ParseDataLine` for the bytes that become residues), and `losat_location` for the adapter code. No oracle runs are needed except to confirm a claim; instead run the base-commit adapter through its tests' helpers only if they need no build (they do need one: then read only).

What to inventory (`web/adapter/src`, contract `docs/web/abi_v2.md` §4, §8, §9; the application side is read-only reference: `web/app/src/ports/engine.ts` (`InputMismatchError`), `web/app/src/domain/programs.ts` (`fastaParser`), `web/app/src/application/draft.ts` (`indexParser`), `web/app/src/application/coordinator.ts` (`snapshotInput`), `web/app/src/infra/fake/fake-fasta.ts`):
- `scan.rs`: the kind-0 scanner (a reproduction of `bio::io::fasta` 1.6.0): its state machine, chunk handling, `header_offset`/`sequence_offset`/`end_offset`, `length`, `line_layout` (`uniform` and `checkpoints` every 65536 residues) and `residue_counts`, the errors (`Expected > at record start.` ...). For each NCBI reader rule (ranges LR and RD: line endings LF/CRLF/CR/mixed, comment lines `!#;`, white space inside lines, `;` to the end of a line, `-` removed with a warning, invalid residues removed, digits, bytes ≥ 0x80, text before the first defline, a record without a defline (`fDLOptional`), empty records, `>?` gap lines (the maintainer's decision: ABI v2 `register` and `scan` reject them), the defline title bytes, the local ID), say what a new scan kind (proposed: 1 = NCBI reader with nucleotide flags, 2 = with protein flags) must do so that its records, IDs and lengths equal the engine reader's for any chunking, and what "read forward from a checkpoint under the parser's rules" must skip so that residue `i` is found (the rules for `line_layout` and which bytes `residue_counts` counts). Note where the NCBI reader's state crosses lines (EOL style detection, pushback, `CheckDataLine` on a record's first data line, the title warning) and whether a chunked scanner can reproduce it.
- `lib.rs` `losat_web2_scan_begin` (rejects kinds other than 0), the scanner handle lifecycle.
- `store.rs` `register` (line 39) and `check_scan` (151): how each program/role parses today (which LOSAT functions, which checks, in what order), the JSON (`id`: today `bio`'s ID; the session will make it the NCBI title's first word up to `' '`, empty when there is no title, never `Query_N`), what `q_idx`/`s_idx` count (the session: empty records count too), UTF-8 handling (the session: non-UTF-8 bytes become U+FFFD only in JSON), the rejection list documented in `abi_v2.md` §4 `register`.
- `run.rs`: how handles become `run_local_*` calls (records type `bio::io::fasta::Record` today), warnings to stream 3, how record indices map to `q_idx`/`s_idx` in HSP records (§8) when a record is empty or skipped.
- ABI v1: `LOSAT/src/web_api.rs` and the programs' `run_web_pair*` (TD-1 freezes v1's accepted inputs, rejection texts and their order; the maintainer's decision: v1 runs its current checks first and then passes the accepted inputs to the new reader). List v1's checks in order per program, and say for which accepted inputs `bio` and NCBI could still differ (should be none: confirm or list).
- Tests: `web/adapter/tests/scan_properties.rs` (what properties, generators, edge cases; what a kind-1/kind-2 property test needs: generated inputs and edge cases from `COMMON.md`, arbitrary chunk splits), the V-ABI tools (`web/adapter/tools/v_abi_cases.py`, `run_v_abi_parallel.py`, `web/adapter/tests/v_abi.js`), v1 tools (`docs/evidence/losat_web_e1a/v1_requests.js`, `LOSAT/tests/check_wasm_threading.py`).

`status_before` for adapter rows: describe today's adapter against what the new kind must do (`divergent`/`unported`/`rejected-now`/`faithful`). `blastx_*`: BLASTX's input path in the adapter (none until SX: `n/a`) or BLASTX's `input.rs` when a rule is shared.
