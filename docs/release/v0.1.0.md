## Supported scope

| Area | v0.1.0 claim |
| --- | --- |
| BLASTN | The 14-case local query/subject `blastn` and `megablast` profile: 13 exact source-defined cases and one narrow source-underdetermined equal-HSP case. |
| BLASTP / LOSATP | The nine-case gbdraw P1-P3 local query/subject profile using standard outfmt 6. |
| TBLASTX / TLOSATX | The 20-case gbdraw P1-P2 local query/subject profile using standard outfmt 6 and one thread per job: 14 exact source-defined cases and exactly six approved local-subject non-default `db-gencode` deviations. |
| Native CLI | The declared profiles on Linux x64, Windows x64, macOS arm64, and macOS x64. |
| Serial command Wasm | The 41 directly applicable declared rows on `wasm32-wasip1`; each is byte-identical to native LOSAT. |

This is not a claim of generic NCBI BLAST compatibility. Database or remote
search, unlisted tasks/options/formats, `dc-megablast`, threaded Wasm, public
Rust API stability, and browser/embeddable Wasm ABI stability remain outside
the release claim.

## Compatibility boundaries

### BLASTN source-underdetermined case

`Sakai.MG1655.megablast` is not an intentional LOSAT product deviation. NCBI
BLAST+ 2.17.0 source leaves the comparator-equal edit-script survivor
underdetermined. The accepted contract requires the same row count, HSP
membership/coordinate keys, E-values, and bit scores; differences are limited
to the demonstrated edit-script-derived identity, length, mismatch, and
gap-open fields. No broader tolerance is permitted.

### TBLASTX approved deviation

For local `-s/--subject` searches, LOSAT intentionally honors an explicit
non-default `--db-gencode` during subject translation, search, and reporting.
Exactly six declared cases exercise this behavior. It is the only approved
v0.1.0 product deviation and permits no unrelated timing, ordering, scoring,
filtering, statistics, pruning, coordinates, or formatting difference.

Native and Wasm archives also contain `README.md`, `LICENSE`, and
`RELEASE-METADATA.json`. Each primary artifact has a JSON metadata sidecar and
SHA-256 sidecar. The final handoff adds `RC-HANDOFF.json`, `RC-HANDOFF.md`, and
the aggregate `SHA256SUMS` file. Archive member order, timestamps, ownership,
and permissions are fixed by the release helper so repeated assembly of the
same built input is deterministic.

The historical binary SHA-256 values from PR 5/PR 6 identify those completed
certification builds. They remain in candidate metadata as provenance, but are
not asserted as cross-runner reproducibility contracts: hosted runner images,
linkers, and binary metadata are not fully pinned by `CERT_TOOLCHAIN`. The RC
gate instead binds each newly built artifact to its exact candidate SHA,
recorded runner/toolchain environment, candidate-specific checksums, target
architecture, and exact representative output.

The representative execution is the committed exact BLASTP case
`pairwise_default_serial`. Every executable artifact must reproduce raw
output SHA-256
`fd4b010800e32ce6c823cb38b42a10b7845f3342edae892acccc8f554f9edf34`.

## Running the gate

Run the manual `.github/workflows/release-readiness.yml` workflow with the
exact committed candidate SHA. Leave `run_integrated_certification` false for
this tooling/documentation-only candidate.

The bounded local equivalents are:

```bash
python -m unittest LOSAT/tests/test_prepare_release_candidate_v010.py
python LOSAT/tests/check_pure_rust_runtime_boundary.py --root .

cd LOSAT
cargo fmt --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --all-features --locked
cargo build --release --locked
cargo build --release --target wasm32-wasip1 --no-default-features --locked
cargo package --list
cargo package --locked \
  --config 'build.target-dir="/tmp/losat-cargo-package-target"'
cargo publish --dry-run --locked \
  --config 'build.target-dir="/tmp/losat-cargo-publish-target"'
```

The workflow may emit `RC_HANDOFF_READY` only after all six artifacts and all
metadata/checksum/smoke gates pass. Any target, hash, version, ancestry,
certification-input, package-content, or smoke mismatch fails closed.

## Publication boundary

Passing the handoff gate does not create a release. This PR and its workflow do
not create or push `v0.1.0`, create a GitHub Release, upload to crates.io,
submit/update Bioconda, sign, notarize, deploy, or merge the PR. Those remain
separate maintainer-authorized actions.
