- Library API: `losat::api::Error`'s messages are now the bytes that the command line writes (`Error::Argv`, `Input` and `Search` hold a `Vec<u8>`; `message()` gives `&[u8]`), also bytes that are not UTF-8: a tool's error that quotes one (`blastdbcmd -outfmt '%é'` writes the first byte of `é` alone) turned each such byte into U+FFFD before the first release. `to_string_lossy()` and `Display` give the text with one U+FFFD per maximal ill-formed subpart; `Debug` writes the kind and the message as text, a byte that is not UTF-8 as `\xNN` (`Search("...'%\xC3'")`); an error is made from text with `into()` (`Error::Argv("-query is required".into())`). pylosat: every exception has `message_bytes`, and `Outcome`, `Batch` and `ToolOutput` have `diagnostics_bytes` beside `diagnostics`, whose text (also `str(error)`) has U+FFFD for such bytes, as before (now documented); `Search.run_to_file` returns a `FileOutcome` with the same two (it returned the text). The reports, the command line and LOSAT Web do not change.
