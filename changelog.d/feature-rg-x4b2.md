- `blastx -use_sw_tback` now runs, with every `-comp_based_stats` (0 to 3), `-db` and `-subject`, with sum statistics (the default) and with `-sum_stats false`, where LOSAT refused the option before: each match is aligned again in the windows of the query's frames with NCBI BLAST+ 2.17.0's Smith-Waterman traceback, at every `-num_threads` as NCBI's `-num_threads 1` does it. A query batch whose last Smith-Waterman alignment fails ends as NCBI's does when the batch's first query has kept no alignment: the results of the query batches before, then `BLAST engine error: Traceback failed`. With a `-negative_seqidlist`, a subject that the list leaves without a definition line is skipped when the alignments are made again, and it resets the query batch's failure, as in NCBI. Refused, after the results of the query batches before (the manual's page "What LOSAT refuses"): a query and subject whose alignment NCBI never finishes; a query batch on which NCBI crashes, one whose last alignment fails after the batch's first query has kept one; in e-value mode (`-sum_stats false`, or a `-max_intron_length` of 1 to 4), a query batch in which NCBI reads past its lists of kept results, one per query of the batch, which it picks by the match's reading frame (6 × the query's place in the batch, counted from 0, plus 0 to 5 for frames +1, +2, +3, -1, -2, -3): a number that is the batch's number of queries or more (NCBI then crashes, fails or goes on with what lies there; a smaller number makes NCBI check another query's list, and LOSAT does the same); with one query in the batch, any hit outside frame +1 is refused, so in this mode most query batches with hits are refused; and `-use_sw_tback` with `-ungapped`, on which NCBI crashes at every query batch (line RG, X4b-2).
