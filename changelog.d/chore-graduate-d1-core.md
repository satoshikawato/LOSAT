- The variables `LOSAT_X_CODONFAST`, `LOSAT_X_DUSTFAST`, `LOSAT_X_DUSTRING`, `LOSAT_X_ENVCACHE`, `LOSAT_X_ERFMEMO`, `LOSAT_X_IDEALMEMO`, `LOSAT_X_KARLINFAST`, `LOSAT_X_SEGFAST` and `LOSAT_X_SEGMEMO` are gone, with `LOSAT_X_DUSTSHADOW` and `LOSAT_X_SEGSHADOW`: their paths were already the default and now run unconditionally, so neither `=0` nor `LOSAT_X_DEFAULT=0` reaches the previous code. The literal `std::list` port of DUST's `find_perfect`, the SEG shadow comparison, the DUST shadow comparison and the unit test that compared the Karlin K lanes with the scalar-only run were deleted; the fallbacks the default still takes stay (ambiguous codons, a DUST window above 64, a SEG window above 15 letters or a segment above 127, Karlin K with `first != 0`). Outputs do not change.
- The variables `LOSAT_X_COMPFAST`, `LOSAT_X_NEWTONEXACT`, `LOSAT_X_NEWTONLANES` and `LOSAT_X_NEWTONLANES8` are gone, with `LOSAT_X_COMPSHADOW`, `LOSAT_X_NEWTONEXACTSHADOW` and `LOSAT_X_NEWTONLANESSHADOW`: the reordered Newton loops, the exact Newton module and the Newton lanes (eight lanes on aarch64) were already the default and now run unconditionally. `NEWTONLANES` and `NEWTONLANES8` keep their rules (which redo loops and which TBLASTN windows prefetch, aarch64 only) and move from the strict set to `GRADUATED`. The original-order `MultiplyByA` / `MultiplyByAtranspose` loops, the three bitwise shadow comparisons and the `[X_SHADOW]` lines were deleted; the line-by-line ports the default still takes stay (`optimize_target_frequencies_reference` for the unconstrained rule, and the size fallbacks of the reordered functions). `tests/newton_lanes8_default.rs` keeps only the test that the default takes eight-lane batches on aarch64 only. Outputs do not change.
- The variables `LOSAT_X_DPFAST`, `LOSAT_X_DPAVX2`, `LOSAT_X_DPW128` and `LOSAT_X_DPNEON` are gone, with
  `LOSAT_X_DPSHADOW`: the vector X-drop DP (128-bit SSE/AVX/simd128/NEON kernels, the 256-bit AVX2 kernels
  on a CPU with AVX2, the `DPW128` kernels where the 128-bit kernel would run) always runs where the target
  and the CPU have it, and the scalar X-drop stays for calls that do not fit the 8/16-bit lanes and for
  targets without a vector kernel. The call-site comparison with the scalar port (blastn, blastp) and its
  recursion guard went, the NEON-off test file `xdrop_neon_default.rs` was deleted, and the arm64 platform
  check mode `noneon` is gone (`dpneon2` stays). `LOSAT_X_DPEMASK`, `LOSAT_X_DPNEON2`, `LOSAT_X_DPNO8`,
  `LOSAT_X_DPNOAVX` and `LOSAT_X_DPCAPTURE` are separate variables and stay. Outputs do not change.
