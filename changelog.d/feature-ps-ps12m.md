- `losat rpstblastn` and `losat rpsblast` hold less memory per thread on large profile databases: on 100 query records of 5 kb against the CDD database, the peak memory at 32 threads is 362 MB instead of 640 MB (44 % lower; 259 instead of 396 MB at 16 threads, 244 instead of 312 MB at 8), and each added thread costs about 6.4 MB instead of 15.3 MB. The scan of a query keeps its words and makes the hits of 64 buckets of the profile rows at a time, so the memory no longer grows with the number of hits of a whole scan; the time and the output are unchanged: the same bytes as NCBI BLAST+ 2.17.0 at every thread count (line PS, series PR, item PS12m; DECISIONS 64 and 65). A profile database whose table lists the hits of a word out of order (makeprofiledb never writes one) is read as before.
