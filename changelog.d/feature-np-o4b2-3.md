- A search on a damaged taxonomy database whose last entry begins past the end of `taxdb.btd` (NCBI BLAST+ writes `Offset error at end of taxdb file.`), where a volume of the database also holds another tax id of that entry's slot of NCBI BLAST+'s 256-slot taxonomy cache, now writes NCBI BLAST+'s output where a query batch's prefetch reads the sequences (the default, in every format but `-outfmt 13` to `16`): the prefetch follows NCBI BLAST+'s order of its loads, and the offset error comes as many times as NCBI BLAST+ writes it. Before, such a run was refused at its first fetch. It is still refused where that order depends on NCBI BLAST+'s memory layout, and for the reports' reads with `PRE_FETCH_SEQS_LIMIT` turning the prefetch off and for `-outfmt 13` to `16`.
