- Added unified P-values to `blastp`: `-comp_based_stats 1u`, `2u` and `3u` (a `u` or `U` after the mode) combine each e-value with a P-value of the two sequences' compositions, as NCBI BLAST+ 2.17.0 does. LOSAT refused them before. A query that has a next query in its batch of queries gets the output of NCBI BLAST+ with `-num_threads 1` byte for byte (apart from the version line, which names LOSAT): NCBI BLAST+ adjusts its e-values with the next query's length and search space. For the last query of a batch (a search with one query included), where NCBI BLAST+ reads past the end of its data and its report changes from run to run, LOSAT uses the query's own length and search space, which is NCBI BLAST+'s output for that query when a copy of it follows in the same batch and does not change the pieces in which NCBI BLAST+ searches the batch (PD-LOSAT-NCBI-DEFECTS). A batch where a query with a residue that can be scored is followed by one with none is refused unless a `-searchsp` above 0 is given: NCBI BLAST+ reports every e-value of the first of the two as 0. `psiblast`, `blastx` and `tblastn` read `1u` to `3u` as the mode alone, as NCBI BLAST+ does (the manual said `psiblast` refused them, which it never did).
