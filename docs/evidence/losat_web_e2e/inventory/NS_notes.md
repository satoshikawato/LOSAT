## Main findings

1. **Defect in the certified default family (row 25, medium)**: the mode-0 (ordinary traceback) path in `stage_d_pipeline.rs:1119-1122` uses only `(final_bits*LN2/lambda) as i32` as gap X-drop. NCBI uses `MAX(final_conv, prelim_conv)` (`BlastExtensionParametersNew`, `blast_parameters.c:455-466`, then `gap_align->gap_x_dropoff = gap_x_dropoff_final`). Whenever the preliminary X-drop exceeds the final one (`-xdrop_gap` > 25 bits with the default final of 25, or `-xdrop_gap_final` below 15) `-comp_based_stats 0` gives different HSPs (batch4: `y_cbs0_xg30/40/60/100`, `y_cbs0_xf5`; mode 2 is correct because `local_extension_final_xdrop` does the MAX).
2. **Gumbel/Spouge block only for 2 (matrix, gap) pairs (row 45, high once the gate is lifted)**. NCBI fills it for every table row; without it LOSAT falls back to the simple Karlin formula (wrong cutoffs, wrong E-values) and the linking code errors out.
3. **PAM30/PAM70 tables are incomplete and one value is wrong (row 44)**; `scoring.rs` allows all NCBI pairs, so validation and engine disagree. `lookup_protein_params` silently falls back to another row for unknown pairs.
4. **Search gate (row 71)**: `args.rs:409-433` accepts exactly BLOSUM62/11-1/ws3/thr13/win40 and BLOSUM45/14-2/ws2/thr16/win60 (mode 0 only). All other matrices, gap pairs, word sizes, thresholds, windows, `-ungapped`, `-max_intron_length`, `-comp_based_stats 1/3/D/T`, `-task tblastn-fast`, `-use_sw_tback` end in ad-hoc errors. The engine code below the gate is largely parameterised by matrix and gap costs; what is missing is data (rows 6, 44, 45, 53, 54) and verification (rows 47, 82).
5. **`-comp_based_stats` spellings**: `D/d/T/t` (= mode 2), unknown first character or empty string (= mode 0, no error in NCBI), `1`, `3` are rejected by LOSAT (rows 17, 18, 57, 58). `2u` is correct (suffix ignored for tblastn).
6. **Float-to-int casts of X-drops (row 26)**: NCBI takes any strtod double (negative, hex, 1e30), casts `(Int4)` (x86-64: INT_MIN for out-of-range values, which `MAX(final, prelim)` then ignores). LOSAT rejects negatives/hex in clap and, for 1e10, panics with `capacity overflow` (exit 134) because Rust `as i32` saturates.
7. **Minimum subject length (row 78)**: NCBI floors the shortest subject length at `BLAST_SEQSRC_MINLENGTH` = 10 before dividing by 3. LOSAT divides the true shortest length; a subject shorter than 3 nt (or an empty record) makes the Spouge input degenerate and silently removes hits of all other subjects (`sh_1.fna`: -evalue 100000 gives 54 lines instead of 3685).
8. **Option-error wrapper (rows 62, 63, 3, 4, 8, 20)**: NCBI prints `BLAST query/options error: <msg>` + `Please refer to the BLAST+ user manual.`, exit 1, for every error raised after argument parsing; LOSAT TBLASTN prints `Error: <msg>` (BLASTN/BLASTX/TBLASTX already use the NCBI form), and checks `-word_size 8`, `-threshold 0` and `-seg` format in clap (exit 2). PD-LOSAT-CLI-NONSEARCH-DIFFERENCES item 1 covers only errors the NCBI argument parser itself raises.
9. **`-matrix IDENTITY`** (rows 6-9): accepted by NCBI tblastn (gap pair 15/2 only, threshold 29, CBS reset with one warning per query). `-word_size 5` and `-task tblastn-fast` with IDENTITY crash NCBI (SIGSEGV in `s_BlastCompressedAaScanSubject`, deterministic, input independent): decision needed (NCBI defect policy: reject).
10. **Footer text of `-matrix`**: NCBI prints the matrix as typed (`Matrix: blosum62`), LOSAT prints the upper-case name (row 5, outfmt 0 only).
11. **`on`/`off`** are valid NCBI booleans (`NStr::StringToBool`); LOSAT's `ncbi_bool` lacks them (row 21).
12. **Mode 0, `-evalue 1e6`** (row 51, UNSURE): two of 109,685 outfmt 6 lines differ in subject coordinates for equal-score HSPs in different frames; all other E-values and mode 2 are equal.
13. **acos clamp in the conditional rule** (row 56, UNSURE): LOSAT clamps the cosine to [-1,1]; C yields NaN for arguments outside it (so `angle > 70` is false). Only matters for strongly biased composition pairs in the default mode 2.
