- The Node threaded runner (`LOSAT/tests/run_losat_wasi_threads.js`) starts a command's threads sooner. Its thread workers load a file of their own (`wasi_thread_worker.js`, without the host's guard cache, hashing and argument code) and share the runner's environment instead of copying it; the guard cache keeps an index by the module file's identity (device, inode, size, modification and change times), so the cached guarded module is compiled at once and its checks (both SHA-256, the guard version, the record) run while V8 compiles; a spawn that takes a standby worker which already waits returns without waiting for the thread's start confirmation, and the standby workers boot once the compile has started. On the workstation the 16-thread blastx search of a 50 kb genomic query against the D. melanogaster proteins started its threads at 120 instead of 179 ms and ended in 1.37 instead of 1.46 s; one thread is not slower. Reports do not change.
