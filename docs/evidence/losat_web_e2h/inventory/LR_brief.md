# Range LR: line reading and the input stream

Files: `LR.tsv`, `LR_notes.md`. Read `COMMON.md` first.

Entry points (NCBI): how the `-query` and `-subject` arguments become a stream and a line reader, for all four programs and both roles.
- The argument's stream: `CArgValue::AsInputFile` (`c++/src/corelib/ncbiargs.cpp` ~700-760: `-` is `cin`, a file that does not open, binary/text mode), and where each program asks for it (`c++/src/app/blast/blastn_app.cpp:199-214`, `tblastx_app.cpp:128-136`, `tblastn_app.cpp:209-213`, `blastp_app.cpp:207-215`; the subject in `c++/src/algo/blast/blastinput/blast_args.cpp:2525-2557`).
- `IsIStreamEmpty` (`c++/src/app/blast/blast_app_util.cpp:845-875`): which bytes count as space (C `isspace` with `skipws`), what happens for a pipe (`tellg() < 0` returns false), what it does to the stream state, and what the program does when it is true (the query: `Query is Empty!` warning? find the exact text and where it is printed; the subject: is it checked at all?). An empty pipe as the query (E2g row A-042).
- `CStreamLineReader` (`c++/src/util/line_reader.cpp:77-300`): constructor, `AtEOF`, `PeekChar`, `operator++`, `operator*`, `UngetLine`, `GetLineNumber`, `x_AdvanceEOLUnknown`, `x_AdvanceEOLSimple`, `x_AdvanceEOLCRLF`, the `eEOL_mixed` branch; `NcbiGetline` (`c++/src/corelib/ncbistre.cpp`, both the single-delimiter and the multi-delimiter forms) and `CStreamUtils::Pushback` / `CPushback_Streambuf` (`c++/src/corelib/stream_utils.cpp`) where the line reader uses them. For each end-of-line style (LF, CRLF, CR only, LF CR, mixed in one file, a lone CR inside a line after LF lines, no final line break, an empty last line, a NUL byte, a very long line) record which lines the reader returns, their bytes (is a trailing CR kept?), and the line numbers (they appear in warnings: `around line N`, `Near line N`). `CStreamLineReaderConverter` (gaps to Ns) and `CMemoryLineReader`: say whether the four programs can reach them.
- `CBlastFastaInputSource::End` (`blast_fasta_input.cpp:370-374`) and how the batch loop of each app uses it (`for (; !input.End(); ...)`): when is a trailing blank/comment-only tail a batch with no queries; how `AtEOF` interacts with `UngetLine`.
- A byte order mark (EF BB BF) at the start of a file, NUL bytes, bytes 0x80-0xFF: the line reader passes them through? (The record-level meaning is range RD; here only the lines.)

LOSAT side: `algorithm/blastn/input.rs` (`open_input`, `standard_input`, `read_fasta_bytes` (a directory reads as no bytes), `is_blank`), the programs' `run` functions (where the query and subject files are opened and read, and the `Query is Empty!` handling: grep `Query is Empty`), `bio`'s line handling (it splits on `\n` only and trims a trailing `\r`; a CR-only file is one line for `bio`). BLASTX: `algorithm/blastx/input.rs` `FastaStream`, `stream_is_empty`, `FastaMemoryLines`, and its unit test fixture `LOSAT/tests/unit/blastx_stage_e_io_stream_expected.tsv` (an independent C++ oracle of the stream behaviour; describe what it covers).

Oracle runs to make (blastn and blastp at least; outfmt 6 and 0): the same two-record input with LF, CRLF, CR only, mixed endings and no final newline; a CR-only file whose second record has a title warning (to see the line number); `-query -` from a file, from an empty pipe (`: | blastn -query - ...`), from a pipe with only blank lines; `-subject -`; an empty query file, a white-space-only query file, a white-space-only subject file (exact messages and exit codes); a file whose last line is a lone `>`.
