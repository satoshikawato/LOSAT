## 3. Data loader and the Seq-id decision (`CBlastInputReader::ReadOneSeq`, `blast_fasta_input.cpp:130-152`)
Only when `UseDataLoaders()` (section 4). At the start of EVERY `ReadOneSeq` call the reader executes `line = TruncateSpaces_Unsafe(*++GetLineReader())`, i.e. the NEXT line of the stream (blank lines are not skipped; `++` at EOF gives an empty line), trimmed of `isspace` bytes at both ends. If `line` is non-empty and its first byte is `isalnum` ([A-Za-z0-9] in the C locale; a BOM, `>`, `;`, `#`, `!`, any non-ASCII byte do not qualify) it is parsed:
`CSeq_id id(line, fParse_AnyRaw | fParse_ValidLocal)`; `if (id.IsLocal() && !StartsWith(line, "lcl|")) id = CSeq_id(line)` (default flags `fParse_AnyRaw`, which throws `Malformatted ID` for anything that is not a tag/accession); then `x_CreateBioseq(id)` (data loader). Exceptions: a `CSeqIdException` whose message contains `Malformatted ID` -> fall back to FASTA (`UngetLine()` then `CFastaReader::ReadOneSeq`); any other `CSeqIdException` or `std::exception` is rethrown (the query is then skipped by `GetNextSeqBatch`, a subject is fatal); `catch (...)` -> FASTA. If the line is empty / not alnum-first the reader does `UngetLine()` and reads FASTA. Because `CFastaReader::ReadOneSeq` stops only at a `>` line or EOF, the line tested is: the first line of the stream, or the line directly after a Seq-id line (each Seq-id line, fetched or skipped, consumes exactly ONE line; net2: `AB123456` then `>q1` -> two records). A blank line, comment, or anything before an accession line defeats the test: `\nAB123456\n` is read as FASTA data (pd6 for the blank-line reading; net5 shows the chain of five Seq-id lines).

`CSeq_id::Set(the_id, flags)` (`objects/seqloc/Seq_id.cpp:2457-2551`) for these flags:
1. **Tag form** (`s_CheckForFastaTag` `:632-642`): `size>3 && s[2]=='|'` -> tag = first 2 bytes, else `size>4 && s[3]=='|'` -> first 3 bytes (an if/else-if on the position, not on the lookup result); `WhichInverseSeqId` is case-insensitive (`sc_ChoiceArray` `:526-562`). Recognized: 2 bytes `gb gi sp tr`; 3 bytes `bbm bbs dbj emb gim gnl gpp lcl nat pat pdb pgp pir prf ref tpd tpe tpg` (`gibbsq`, `not_set`, `???` cannot match). A recognized tag NEVER gives `Malformatted ID` (`:2517-2551`; the only throw of that text is `:2502`): `x_Init` either builds an id (looked up -> section above) or throws another `CSeqIdException` (`FASTA-style ID ... has too many parts.`, `Not enough fields for ID of type ...`, `Malformatted PDB ID ...` (no `ID` right after `Malformatted`, `:2814`), `Bad sequence number`, numeric conversion errors) that is rethrown. Unknown 2/3-byte tags (`xx|abc`) are not tags: they go on to step 2.
2. **Raw accession** (`fParse_AnyRaw` = RawText|RawGI): `IdentifyAccession(line, flags | fParse_FallbackOK)` `:1634-1664` -> `x_IdentifyAccession` `:1666-1830`. Let `main` = the part before the first `.`; a `.` as last byte or a non-digit after it -> unknown; `main` is upper-cased. `digit_pos` = index of the first digit (none -> unknown), `non_dig_pos` = first non-digit at or after it:
   * `non_dig_pos` exists (digits followed by non-digits): PDB if no version, `digit_pos==0`, `size>=4`, `non_dig_pos<5`, bytes 1-3 alnum, and either (`4<size<=17`, byte 4 in `|-_`, and `size<=6` or byte 5 alnum) or `size==4` (`:1679-1710`); Swiss-Prot if `digit_pos==1` and `size==6` with (byte 0 in O/P/Q or byte 2 alpha), byte 1 digit, bytes 2-4 alnum, byte 5 digit, or `size==10` with byte 0 not O/P/Q (`:1712-1727`); PRF if no version, `digit_pos==0`, `non_dig_pos` 6 or 7, followed by end, `:`, or one letter then end/`:` (`:1728-1738`); the WGS/TSA protein flag shape (`:1739-1745`; `digit_pos>=4`, `non_dig_pos==digit_pos+2`, `size-non_dig_pos>=6`, byte 3 not `_`, flag byte S or P, digits after) continues to the table lookup; anything else -> unknown. These need no tables.
   * only digits after the first digit (including `digit_pos==0`, all digits): digits only, no version, first byte not `0` -> GI (`:1752-1756`); other digit-first -> unknown; a letter-first line `L letters + D digits` (letters may include `_`) goes to the **accession guide** `SAccGuide::Find(s_Key(digit_pos, digit_count), main_acc)` (call `:1768`, definition `:1370-1450`, built-in text `accguide2.inc` lines 36-25779, same as `accguide2.txt`): the guide knows only the 26 formats (letters+digits) 1+5 2+6 2+8 2+10 3+5 3+6 3+7 3+8 3+9 3+11 4+5 4+6 4+8 4+9 4+10 5+6 5+7 6+9 6+10 6+11 7+8 7+9 7+10 9+9 9+10 9+11 (first lines in accguide2.inc: 1+5 at 319, 2+6 at 348, 3+5 at 41, 3+6 at 277, 4+5 at 290, ...); other formats -> unknown. A listed format is then matched against 1458 prefix/wildcard rules and the `special2` ranges (from line 1527); rules whose type is `unreserved_*`, `unknown`, `ambiguous*`, `maybe_*` have `E_Choice` e_not_set, i.e. are NOT accessions (e.g. `ZZ123456`, `XP_123456`, `N12345`).
   * The result of `GetAccType`: GI -> `Set(e_Gi)`; PRF/PDB/accession types -> id built; `e_not_set` -> step 3.
3. **General dbtag whitelist** (`:2483-2495`, `kSupportedRawDbtags` `:98-124`): the text before the first `:` is upper-cased and looked up case-sensitively in `ATGC BCMHGSC BERKELEY CELERA GSDB HOOD LANLCHGS LRG MIPS NCBI_EXT_ACC NCBI_GENOMES NCBI_MITO PGEC PID SGD SHGC SRA TIGR UOKNOR UWGC WASHU WIBR WUGSC dbGSS dbSTS` (the last two can never match after upper-casing) -> `general|<db>|<rest>` Seq-id (`SRA:SRR000001`).
4. **Local ID** (`:2496-2503`): `IsValidLocalID` (`:2576-2600`, `CheckLocalID` `:2583`: non-blank, <= 50 bytes, none of ``space > [ ] | "``) with `fParse_ValidLocal` -> local id (then the retry in `ReadOneSeq` throws `Malformatted ID`); otherwise `Malformatted ID <line>`. Either way the reader falls back to FASTA, so **every line that is not a tag, an identified accession/GI/PDB/PRF/Swiss-Prot, or a whitelisted `DB:` prefix is FASTA data**: `ACGTACGT`, `ACGT ACGT`, a 40-nt line, `MKVLAAGIVGLLLAQ`, `0123`, `12.5`, `XP_123`, `contig1`, `ACGT1234` (4+4 not a guide format), `gb|`, `xx|abc`. A sequence-only file is therefore one record `Query_1` with an empty title (net5, n01, n02, fl_text).
**Rule for LOSAT (row 55 has it in one line; `scratch_BI/seqid_probe.py` implements it and reproduces the 6 network observations and the `.ncbirc` runs)**: with the loaders on, at stream start and after each rejected-or-not Seq-id line, trim the next line; if it starts with [A-Za-z0-9] and (a) has a 2/3-byte tag from the list followed by `|` at that position, or (b) is a GI/PDB/PRF/Swiss-Prot shape by the tests above, or (c) is `letters/_ + digits` (optionally `.digits`, or two digits + S/P + digits) whose (letters, digits) pair is one of the 26 guide formats, or (d) has a whitelisted `DB:` prefix, then reject explicitly (`... may be a sequence identifier that NCBI BLAST+ fetches through a data loader, which is not supported by LOSAT's <PROGRAM>`). Otherwise read the line as FASTA. Parts that cannot be ported faithfully without the table: only (c) (over-rejects prefixes the guide maps to an unrecognized type, e.g. `ZZ123456`; and any nucleotide sequence line that is letters + digits in a guide format, e.g. a first line `AB123456` is a real accession for NCBI; broad rejection costs nothing since such a first line is not FASTA data in practice). Network observations behind it (section 0): `AB123456` fetched, `AB000000` well-formed but unknown -> silently skipped (queries) or `Sequence ID not found: 'dbj|AB000000|'` exit 1 (subject), nucleotide accession for blastp -> skipped (mismatch and the `pir|` retry), protein accession `P01308` for blastn -> skipped, `MKVLAAGIVGLLLAQ` -> FASTA, `lcl|foo` -> skipped (a tag route Seq-id looked up and not found).

## 8. Standard input and pipes (row 46, 34, 53, 54)

## 9. Surprises
1. The Seq-id test sees only the NEXT line of the stream at the start of a record: the first line of the file, or the line after a Seq-id line. A blank line before `AB123456` makes it FASTA data.
2. A Seq-id query line that is not found/mismatched/duplicated is silently dropped (no message, not counted in `# BLAST processed`), but the same line in the SUBJECT file is fatal (`Sequence ID not found: 'dbj|AB000000|'` exit 1).
