# LOSAT v0.1.0 Scope

Last updated: 2026-08-29.

This document freezes the intended v0.1.0 release scope. A final release tag may
only promote an area to supported when the corresponding release gate records
current NCBI parity evidence for the exact behavior being claimed.

NCBI BLAST C/C++ source code remains the sole behavior authority. NCBI BLAST+
executables are validation oracles only and must not be used by LOSAT runtime,
build, feature, fallback, or unsupported-feature paths.

## Scope Decisions

| Area | Decision | Required action before final tag |
| --- | --- | --- |
| BLASTN `--task megablast` | Supported for the declared local query/subject profile | Enforce [`blastn_v0.1.0_certification.md`](release/blastn_v0.1.0_certification.md): exact source-defined parity plus the one frozen Version 1.1 source-underdetermined case. |
| BLASTN `--task blastn` | Supported for the declared local query/subject profile | Enforce the same committed 14-case certification manifest and gate; do not generalize this status to options absent from that profile. |
| TBLASTX local `-subject` | Supported candidate | Re-run native TBLASTX NCBI parity fixtures and record the approved `--db-gencode` exception. |
| BLASTP | Experimental | Keep README/release notes explicit that the subcommand exists but is not primary supported scope for v0.1.0. |
| Native CLI | Supported candidate | Build release binary, record target triple, build metadata, checksum, and smoke-test output. |
| `wasm32-wasip1` serial | Experimental | Build with `--no-default-features`; the targeted BLASTN native/Wasm check passed, but full-manifest Wasm runtime certification remains pending. |
| `wasm32-wasip1-threads` | Experimental | Build only with `--features wasm-threads`; document runtime requirements and prove output order. |
| Rust library API | Internal only | No semver-stable API guarantee in v0.1.0. |
| Web API / embeddable Wasm API | Internal only | Public ABI and memory ownership remain undocumented and unstable. |

## Approved Deviation

TBLASTX local `-subject` searches intentionally honor `--db-gencode` for subject
translation/search/reporting for every non-default genetic code. This is the
only approved v0.1.0 deviation from NCBI BLAST+ local `-subject` behavior.

This exception is narrow. It does not permit differences in timing, ordering,
scoring, filtering, statistics, pruning, coordinate handling, output fields, or
formatting.

The BLASTN source-underdetermined equal-HSP classification in
[`PD-BLASTN-HSP-CANONICALIZATION`](product_decisions/PD-BLASTN-HSP-CANONICALIZATION.md)
Version 1.1 is not an additional deviation. It preserves the multiple survivor
representations permitted by NCBI BLAST+ 2.17.0 source while retaining exact
parity for source-defined behavior.

## User-Facing Contract

- LOSAT is a Rust implementation, not a wrapper around NCBI BLAST+.
- NCBI BLAST+ may appear in tests, diagnostics, comparison scripts, and release
  validation artifacts only.
- Unsupported options must fail explicitly or remain outside the documented
  release scope.
- Generated comparison outputs are not release source unless explicitly
  documented as canonical fixtures.

## Promotion Rules

An experimental area can be promoted to supported in v0.1.0 only when all of the
following are recorded in `docs/release/v0.1.0.md`:

- LOSAT commit.
- NCBI BLAST+ version.
- Rust version and target triple.
- Input FASTA paths.
- LOSAT and NCBI command lines.
- Output paths and checksums.
- Diff summary covering hit count, order, coordinates, raw score, bit score,
  E-value, and selected output format.
- Explicit pass/fail result.
