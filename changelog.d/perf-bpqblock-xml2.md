- `blastp` searches its queries in blocks of whole query batches also when the report is `-outfmt 15` or `16` (`LOSAT_X_BPQBLOCKXML2`), as it does for `-outfmt 5`: a large query set needs the memory of `-outfmt 6` instead of that of the search of all queries, with the same report bytes. A run whose block search could refuse after some blocks' bytes (a name that NCBI cannot write as for `-outfmt 5`, a `-db` sequence whose taxid does not read, a taxonomy database that does not open or whose name of a taxid NCBI cannot write) takes the search of all queries. `=0` or `LOSAT_X_DEFAULT=0` turns it off. With `-db` the run checks beforehand, in one pass over the header file, that every sequence's title and taxid read: about 0.7 us per sequence (+1.4 s at 1 thread, +0.4 s at 4 threads for 2 M sequences of 40 letters with two tiny blocks, WSL under load; the search of all queries does not pay it). Memory on the local WSL case (3000 queries x 6,600-protein database): max RSS 25.7 MiB (outfmt 15) and 25.8 MiB (16) at 1 thread against 219.7 / 219.4 MiB with `=0`, 37.6 / 38.5 against 259.9 / 259.5 at 4 threads; numbers on the workstation against NCBI follow from v4-MEM.
