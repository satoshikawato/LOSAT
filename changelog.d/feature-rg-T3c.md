- `-outfmt 1`, `2`, `3` and `4` (the query-anchored views) in `blastx` (`-task blastx-fast` too) and `tblastx`, with `-subject` and `-db`, byte for byte as NCBI BLAST+ 2.17.0 writes them (apart from the first line, which names LOSAT and its version, `BLASTP (LOSAT 0.2.0)` where NCBI writes `BLASTP 2.17.0+`): each query frame's alignments under `For reading frame <f> of query sequence:` when more than one frame has them, the query rows of minus frames running from high to low, the translated rows of both strands of `tblastx`'s subjects, insertions, the query's masks (SEG, `-lcase_masking`) of each frame, a subject's `-lcase_masking` runs on every row of the subject, `-query_gencode`, `-db_gencode`, `-strand` (`blastx`), `-query_loc` (the frames of the record), `-subject_loc`, `-line_length`, `-sorthits`, `-num_alignments`, `-show_gis` and `-parse_deflines`. As in NCBI BLAST+, a `tblastx` subject's alignment of the other strand than its first in the same query frame is not shown there (it is in the description table). A `tblastx` query record that is also a subject under `-parse_deflines` is shown as NCBI BLAST+ shows it: in each query frame its alignment with itself on the same letters disappears into the query row and its other alignments with itself are rows labelled with the record; where NCBI BLAST+'s merge of such a section throws (`Start iterator already exists for seq2` or `Infinite loop detected`), `tblastx` writes NCBI BLAST+'s report up to that query's description table and then its error, exit status 255, as NCBI BLAST+ does. `tblastx` writes formats 1 to 4 query batch by query batch as format 0, so their memory stays that of format 0 however many queries a run has. Refused: with `-db`, a database sequence whose Seq-align id or display id is the id NCBI BLAST+ gives a query of its batch (as in `blastp`, `blastn` and `tblastn`) (line RG, T3c). With `-ungapped -window_size 0` and a low `-threshold`, `blastx`'s one-hit alignments of length 0 (in `-outfmt 0` since line RG X2g) are shown in formats 1 to 4 as NCBI BLAST+ shows them: in the query's frame +1 group, where they show no letters (the flat formats 3 and 4 show that group's heading alone where one lies at another nucleotide), NCBI BLAST+'s exceptions where the description table, a sort or `-subject`'s mapped alignment reads them, and no line for a section of such alignments only; refused where NCBI BLAST+'s merge frees memory that it still reads (it crashed in every such run): where one starts at a codon of an alignment of frame +1, and where one is followed on its query row by unaligned letters, whose segment the merge's `FillUnalignedRegions` frees unless it is the last segment the merge made.
