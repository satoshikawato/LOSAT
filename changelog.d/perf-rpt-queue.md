- `tblastx` with two or more threads computes the report's per-HSP values (the displayed identities and the outfmt 0 rows, for which each HSP's codons are translated again) and formats the tabular rows on the search's threads after the last query batch, instead of on one thread while the others wait (`LOSAT_X_TBXRPTPAR`, one of the switches of the strict set, so reports do not change; `LOSAT_X_TBXRPTPAR=0` turns it off; `LOSAT_X_TBXRPTPARSHADOW=1` also runs the one-thread stage and compares). On the workstation three ~650 kb genomes against three (genetic code 4) took 7.38 s at 16 threads with outfmt 6 (8.39 s before; the report stage 0.25 s instead of 1.31 s) and 7.88 s with outfmt 0 (10.48 s; 0.78 s instead of 3.39 s), 12.59 s at 8 threads (13.65 s) and 23.42 s at 4 (24.05 s); MelaMJNV against nine MJNV genomes at 16 threads 1.16 / 1.29 s with outfmt 6 / 0 (1.44 / 1.84 s); peak memory unchanged within the runs' spread; one thread unchanged ([`docs/agents/diagnostics.md`](docs/agents/diagnostics.md)).
