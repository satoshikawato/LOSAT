- A subject whose title NCBI BLAST+ cannot decode (a byte such as 0x81 that no text encoding NCBI recognises; for a database sequence without a title, such a name in the taxonomy database) is reported as NCBI BLAST+ 2.17.0 reports it, where LOSAT refused it before: the tabular rows of NCBI's catch (`sseqid` `Unknown`, the Seq-align ids `Subject_1` or `gnl|BL_ORD_ID|0` in `sallseqid`, `sallgi`, `sallacc`, added row by row within a query's report, the zeros of an empty alignment, the titles and taxonomy of the row before), the BLAST XML values (`Hit_id` `lcl|Subject_1`, `Unknown`, `Hit_len` 0; a query's `lcl|Query_1`, with `-parse_deflines` its own id such as `gb|AB000099.1|`, and `No definition line`) and the XML2 and JSON ids alone, in all six search programs; also for a `-subject` record or database sequence with the parsed id `lcl|Subject_N`, whose `sseqid` is the first word of the title generated from the rest of its definition line (`s7` for `>lcl|Subject_9 TPA: s7 third ~` with `-parse_deflines`), where LOSAT wrote the title's first word or refused it, and whose outfmt 0 line in place of an alignment names that id (`Subject_9`). Only the rows at which NCBI stops are refused: the tabular `sacc` or `saccver` (the default fields of outfmt 6, 7 and 10; NCBI exits with a null pointer exception) and a first row's `staxid` (NCBI prints an uninitialised number) (line RG, T7). In LOSAT Web each stream is the command line's run of its format, in one search: a stream that the argv does not ask for and that the command line refuses fails alone (empty, its refusal in the warnings) while the others are written, such as streams 6 and 7 for such a subject where the argv asks for outfmt 0, or BLASTP's stream 0 for a subject titled `, ,` where the argv asks for `-outfmt 6` (a run that failed in LOSAT Web before); the argv's own format refused fails the run, as on the command line (`-outfmt 6` or `7` with such a subject, which LOSAT Web wrote as a successful run)). Two limits remain in LOSAT Web: a run still fails as a whole, where the command line completes the argv's format, when a format fails in the middle of its report (`-sorthits` with a description total above 99999 bits in outfmt 0, an NCBI error of outfmt 0 alone such as BLASTX `Row is empty`; both as in dev) or when a BLASTX stream fails alone after it sent a chunk (a later query batch with such a subject).
- `blastx` reads a `-subject` or `-query` title that is not UTF-8 as its bytes, as NCBI BLAST+ and the other programs do, where it refused it at the reader; its `-subject` records' tabular `sseqid`, outfmt 0 description lines and alignment headings are the titles NCBI's definition line generator makes (`Subject_5 a & b` for `Subject_5 a &amp; b,`, `s7 third` for `TPA: s7 third ~`), where it wrote the raw title (line RG, T7).
- The tabular `sallseqid` and `sallacc` of a `-subject` record are the first word of its title as NCBI writes them (`Subject_4.`), where LOSAT wrote the word of the generated title (`Subject_4`), in all six search programs (line RG, T7).
