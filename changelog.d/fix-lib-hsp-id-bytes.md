- Library API: `HspRecord::query_id` and `subject_id` are now `losat::api::Id`, the id's bytes exactly as the tabular reports write them in `qaccver` and `saccver`, also bytes that are not UTF-8 (a title read from a Latin-1 file, for example). Before the first release they turned each such byte into U+FFFD while the reports kept it. `Id` gives the bytes (`as_bytes`), the text where it is UTF-8 (`to_str`) or with one U+FFFD per maximal ill-formed subpart (`to_string_lossy`); it has no `Display`, so lossy text is always asked for by name. It equals a `str`, `String`, `[u8]`, byte array or `Vec<u8>` of the same bytes (`hsp.query_id == "seq1"`, also the other way round), is equal, ordered and hashed as its bytes, is `Borrow<[u8]>` (a map keyed by ids is looked up by `&[u8]`), and clones without copying the bytes. pylosat's `qaccver` and `saccver` columns and `Hsp.query_id` and `subject_id` stay text with U+FFFD, as before (now documented); the reports, the command line and LOSAT Web do not change.
