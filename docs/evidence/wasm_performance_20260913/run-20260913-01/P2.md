# P2 — BLASTN speculative traceback investigation

Status: COMPLETE. The isolated batch-32 candidate is REJECTED; no production Rust change is adopted.

## Authority and baseline

NCBI `c++/src/algo/blast/core/blast_traceback.c:403–405,436–472,509–512,583–609` owns ordered containment, start adjustment, traceback, identity tests and tree insertion. `blast_itree.c:273–290,558–583` permits common-endpoint replacement; earlier containment cannot replace the authoritative ordered replay. The candidate only changes the threaded-Wasm speculative window from 16 to 32. Native remains 16 and serial Wasm remains 8 (speculation is compiled out for serial). All jobs retain their original prelim index and use the existing scratch slots/pool.

Baseline is the original `snapshot-v2.json` and `artifacts/`, normal Node 24.21.0, no TurboFan flags. P1 did not adopt an optimization. The isolated candidate source/builds and normalized patch are preserved separately.

## Measurement limits and memory

The dedicated artifact collects slot-local wall intervals and dumps them after the subject stage. Slot labels are scratch-slot identities, not worker identities; summed slot wall is not CPU time or utilization. Batch intervals include filtering, dispatch, result collection and diagnostic sampling. Retained scratch capacity scans occur outside those intervals. Reserve/reallocation counts, physical copy bytes and allocation peaks remain unmeasured; no copy/allocation benefit is claimed.

Formatting the full diagnostic vector directly to WASI stderr causes substantial process-time overhead on this filesystem. For example AP n4/n8 diagnostic processes take 179.7/158.6 s, although their batch interval sums are 4.054/3.528 s. These are correctness and instrumentation runs, never adoption timings. Exact attribution of the overhead to formatting versus host I/O was not separately measured. The release A/B runs disable diagnostics entirely.

At n8, retained speculative scratch totals are 6,635,225 bytes on LC738874, 32,222,059 on AP027202, and 572,262,953 on NZ self. These are capacity sums for the speculative pool only, not process RSS or linear-memory peaks. The NZ observation makes the high-density memory control especially necessary if the candidate passes exploration. Capacity does not authorize a new cross-search cache.

## Final exploration decision

All 34 processes in `p2-exploration/` passed (two fresh oracles, eight diagnostic gates, 24 measured release runs); all LOSAT outputs match their oracle bytes. Full release samples, ranges and RSS maxima are retained in `summary.json`.

The candidate fails the 10% main-input improvement threshold and has a material small-main-input regression. It is rejected after the declared three-repeat exploration; no adoption claim is made and no warmup-plus-five expansion is warranted. Other batch widths, allocator/copy changes and work reassignment were not pursued: the present evidence does not establish an eligible optimization, and rejected hypotheses are not stacked. No candidate control, retry or memory result that was not run is marked passed. The high-density and fallback controls above describe the unchanged baseline only.

The independent baseline audit is in `audit-p2-baseline.md`. P3 continues from the unchanged original artifacts and normal Node mode. Megablast receives no claimed DP benefit.
