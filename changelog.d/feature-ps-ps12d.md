- `losat rpstblastn -use_sw_tback` no longer refuses a profile whose Smith-Waterman alignment starts with a gap in the profile's row: the reports are NCBI BLAST+ 2.17.0's, byte for byte and with its exit status, at every thread count. NCBI cannot take the range of such an alignment, so it warns that the sequence data could not be pre-fetched, outfmt 0 to 4, 13 and 14 stop at the description table (exit status 255), and BLAST XML, JSON and XML2 stop their document; the tables, the Seq-aligns and outfmt 0 without the description table (`-num_descriptions 0`, the leading gap shown as spaces) are written in full. LOSAT does the same. An alignment that starts with a gap in the query's row stays refused: no search has been found that gives one (line PS, series PR, item PS12d; DECISIONS 83 and 95; PD-LOSAT-NCBI-DEFECTS 1.89).
